# 제품 관계도 — IR · B2C · F&B · 사내

작성 근거: 2026-08-11 기준 코드 전수 조사. 모든 항목에 파일 경로가 붙어 있고, **코드에 없는 것은
"없다" 고 적었다.** 있는 척하는 문서는 그것을 믿고 만드는 사람을 헤매게 한다.

---

## 1. 한 장으로 보는 구조

```
                      apps/internal-admin  (사내 · 3302)
                      "우리 회사 ↔ 고객사"
                               │
        ┌──────────────────────┼──────────────────────┐
        │  코드로 이어진 것 둘  │  개념만 같은 것 다수  │
        │  ① 권한 카탈로그      │  요금제 · 기능 토글   │
        │  ② 지원 문의          │  PG · OAuth · DNS     │
        └──────────────────────┴──────────────────────┘
                               │
   ┌───────────────┬───────────┴───────────┬───────────────┐
   │               │                       │               │
 B2C 한 쌍       IR 한 쌍               F&B 한 쌍       (B2B — 앱 없음)
 3310 / 3301     3304 / 3303            3305 / 3306
   │               │                       │
   └───────────────┴───────────────────────┘
                   │
          packages/store  — 서버가 없다. 이 패키지가 DB 자리다.
```

**저장소에 서버도 API 도 없다.** 어드민이 저장한 값이 사이트에 나타나는 것은 두 앱이 같은
모듈(`@winpilot/store`)을 읽기 때문이지 통신하기 때문이 아니다. 그래서 이 문서의 "→" 는 전부
**같은 값을 함께 읽는다**는 뜻이다.

## 3. `packages/store` 파일별 소유

| 파일 | 소유 | 비고 |
|---|---|---|
| `permissions.ts` | **사내 + 전 테넌트 공용** | `CONSOLE_RESOURCES` / `CONSOLE_ROLES` 가 갈래별 카탈로그를 담는다 |
| `support.ts` | **사내 + B2C 공용** | 고객사가 올리고 우리가 답하는 문의 |
| `fnb.ts` | F&B 전용 | 두 F&B 앱이 나눠 읽는다 |
| `ir.ts` | **IR 사이트 전용** | 공시 · 재무 · 주주 · 자료실. 어드민이 더는 안 읽는다 |
| `site.ts` | IR 전용 | 회사 홈페이지 쪽(솔루션 · 공지 · 배너 · 설정) |
| `orders.ts` · `products*.ts` · `coupons.ts` · `reviews.ts` · `categories.ts` · `banners.ts` · `contents.ts` · `company.ts` · `policies.ts` · `inquiries.ts` · `inquiry-form.ts` · `nickname.ts` | B2C 전용 | 16개 |

`internal-admin` 이 이 패키지에서 실제로 읽는 것은 **`permissions.ts` 와 `support.ts` 둘뿐**이다.
나머지 자원(고객사 · 구독 · 청구 · 연동)은 전부 앱 안 시드(`apps/internal-admin/lib/data/*`)다.

## 4. 사내 ↔ 테넌트 어드민 — **실제로 이어진 곳은 둘**

### 4-1. ① 권한 카탈로그 — `packages/store/src/permissions.ts`

계약은 그 파일 머리말에 적혀 있다.

| 어디 | 무엇을 하는가 |
|---|---|
| `internal-admin` `/subscriptions/roles` | **우리가 무엇을 주는지** 정한다 |
| 테넌트 어드민의 운영자 화면 | **내 역할이 무엇을 여는지** 본다 |

두 벌로 두면 그 어긋남은 **고객사가 "안 된다" 고 전화할 때 처음 드러난다.**

갈래별 카탈로그:

| 갈래 | 자원 | 역할 | 쓰는 앱 |
|---|---|---|---|
| B2C | `TENANT_RESOURCES` 16 | `TENANT_ROLES` 4 | `b2c-admin` 이 안내 표로 읽음 |
| IR | `IR_RESOURCES` | `IR_ROLES` 3 | **아무도 안 씀** — `ir-admin` 에 운영자 화면 자체가 없다 |
| B2B | `B2B_RESOURCES` | `B2B_ROLES` | **앱이 없음** |
| **F&B** | **`FNB_RESOURCES` 11** | **`FNB_ROLES` 3** | 이번에 추가 (§7) |

### 4-2. ② 지원 문의 — `packages/store/src/support.ts`

`b2c-admin` `/support` 가 올리고 `internal-admin` `/inquiries` 가 답한다. 사내 쪽은
`SupportRequest → InquiryRecord` 로 **이름만 갈아 끼운다.**

다만 **고객사가 우리 답을 받아 보는 화면이 없다.** 메일로 답한다고 문서가 적어 두었다.

### 4-3. 이어져 있다고 문서가 말하지만 코드에는 없는 것

| 무엇 | 문서의 주장 | 코드의 사실 |
|---|---|---|
| 플랜 → 메뉴 게이팅 | "플랜이 켜는 권한만큼만 메뉴가 열린다" | `admin-menu.ts` 에 게이팅 조건 **0건**. `PLAN_FEATURES` 를 읽는 앱은 사내뿐 |
| 회원 상한(`memberLimit`) | 플랜마다 상한, 90% 알림까지 있음 | 회원 수를 제한하는 코드 **없음** |
| 배포 수(`deployments`) | 플랜마다 허용 개수 | 검사하는 코드 **없음** |
| PG · OAuth 키 | 사내에서 넣으면 배포에 적용 | 전부 `useState` 에만 남음 |
| 역할 편집 | 사내에서 켜면 고객사 콘솔에 반영 | `TENANT_ROLES` 는 상수. 로컬 state 만 바뀜 |
| 권한 검사 | 역할이 화면을 연다 | `hasPermission` 은 **안내 표에만** 쓰임. 라우트 가드 없음 |

사내 어드민 문서(`deployment-mapping.md`)가 이 상태를 스스로 인정한다 — "도면의 화살표는 뜻이지
구현이 아니다."

## 5. 어드민 ↔ 사이트 — 제품별 실태

### 5-1. B2C — 값은 흐르는데 **거래 계산이 값을 안 본다**

흐르는 길:
```
b2c-admin ─저장─▶ packages/store ─투영─▶ @winpilot/client-content ─▶ 템플릿
                                          (숨김 · 기간만료를 여기서 거른다)
```

투영 단계가 걸러 주는 것: 숨김 상품 · 기간 지난 배너 · 숨김 공지/뉴스/FAQ · 숨긴 리뷰 · 꺼 둔
문의 폼 항목. **고객 화면이 다시 판단하지 않는다.**

끊긴 자리:

| 값 | 문제 |
|---|---|
| ~~배송비~~ | **메웠다** — `orderShippingFee()` 가 상품별 정책에서 계산한다 |
| ~~등급 할인율~~ | **메웠다** — `GRADES` 를 store 로 올리고 결제가 읽는다 |
| ~~팝업~~ | **메웠다** — `PopupLayer` 를 `SiteShell` 이 띄운다. 결제·결과 화면만 끈다 |
| 쿠폰 소진 | 결제해도 `used` 가 `true` 로 안 바뀐다 |
| 주문 생성 | 결제해도 `ORDERS` 에 안 들어가 어드민 판매 목록에 안 뜬다 |
| 공급자 · SEO 설정 | 어드민이 **자체 상수**를 쓰고 store 를 안 읽는다 |
| 적립금 · `salesCount` | 어드민에 칸이 없거나, 주문이 생겨도 증가하지 않는다 |

### 5-2. IR — **두 결함이 정확히 반대 방향**

`ir.ts`(공시 · 재무 · 주주)는 정책이 촘촘한데 **어드민 편집 경로가 거의 없다.**
`site.ts`(홍보 · 설정)는 편집 경로가 촘촘한데 **사이트가 그 값을 안 읽는다.**

어드민에서 고치면 사이트가 실제로 바뀌는 자원은 **여섯뿐**이다 — 공지 · 뉴스 · FAQ ·
특허인증 · 연혁 · 제품(`SOLUTIONS`).

못 고치는 값(사이트에는 나감): `IR_COMPANY` 전부 · **공시** · 재무 · 주가 · 배당 · 총회 ·
지배구조 · 자료실 · IR 일정 · 알림 구독자 · 오시는 길 · 히어로 슬라이드 · 홈 소개 문단.

안 쓰이는 값(어드민에만 있음): `SITE_SEO` · `SITE_SUPPLIER` · `LEGAL_DOCS` · `SITE_INTRO` ·
`LOCALE_PAIRS` · DART 설정 · 주가 연동 설정.

`SITE_BANNERS` 는 이 목록에서 빠졌다 — **팝업 쪽을 메웠다.** `liveSitePopups()` 가 기간으로
고르고 `IrSiteShell` 이 띄운다. 첫 화면 배너(`메인 비주얼`)는 아직 `HERO_SLIDES` 가 따로
그리고 있어 이어지지 않았다.

구조적 결함 둘:
- **어드민에서 공시 · 재무 · 주주 · 자료 화면 열을 지웠다.** 사이트의 열한 화면은 그대로
  `ir.ts` 를 읽으므로 계속 그리는데, **저장소 어디에도 고치는 자리가 없다.** 사이드바에서
  뺐다 → `IR` 갈래로 되돌렸다 → 다시 뺐다 → 화면째 지웠다. 사연은
  `apps/ir-admin/docs/path.md` §5 에 있다. 사이트에서 그 화면들까지 내리기로 하면 그때
  `ir.ts` 를 함께 지운다.
- **대표이사 이름이 store 안에서 이미 갈려 있다** — `SITE_SUPPLIER.ceo` 와 `COMPANY_PROFILE.ceo`
  가 서로 다른 사람이다.

### 5-3. F&B — **가장 촘촘하게 이어져 있다**

이 한 쌍은 어드민의 화면이 사이트에 나가는 것에서 거꾸로 짜였다. 사이트가 읽는 값 중 어드민에서
못 고치는 것이 **없다.**

| 어드민 | 사이트 |
|---|---|
| 등록 > 메뉴 | 메뉴판 · 메뉴 상세 · 홈 대표 메뉴 굴림판 |
| 등록 > 마케팅 | 마케팅 화면의 창구별 카드 |
| 등록 > 가맹점 | 매장 찾기 · 홈 GRAND OPEN · 홈 숫자 띠 |
| 창업 > 문의 내역 | (사이트가 넣고 어드민이 받는다 — 반대 방향) |
| 창업 > FAQ | 가맹점 개설문의 |
| 창업 > 비용 · 절차 | 창업 안내 비용표 · 인테리어 평형별 안 |
| 고객센터 > FAQ | 고객센터 자주 묻는 질문 |
| 고객센터 > 공지사항 | 홈 공지 띠 · 고객센터 공지사항 |
| 배너 > 메인 비주얼 | 첫 화면 큰 글씨 · 부제 · 단추 |
| 배너 > 팝업 | 모든 화면 위에 뜨는 팝업 |
| 설정 > 브랜드 정보 | 첫 화면 · 푸터 · 창구 번호 |

## 6. 정책이 사는 곳

| 제품 | 정책이 있는 곳 | 특징 |
|---|---|---|
| B2C | 코드와 주석 | 교환만 코드로 강제(같은 상품 · 같은 색 · 다른 사이즈). **취소 · 반품 기간 규칙이 없다** |
| IR | 소스 JSDoc | 문서 레이어가 없어 정책이 전부 주석에 있다 |
| F&B | 코드와 주석 | 배너 기간 자동 판정 · 마지막 대표 보호 등 |
| 사내 | `lib/data/*` | 요금제 · 연체 구간 · 알림 규칙에 숫자가 있다 |

**세부 정책 문서는 `docs/architecture/policy.md` 로 따로 뺐다.**

## 7. 이번에 메운 것 — F&B ↔ 사내

F&B 는 두 앱이 다 만들어져 있는데 **사내 어드민에 통째로 없었다.**

| 없던 것 | 결과 | 지금 |
|---|---|---|
| `PlanDomain` 에 `F&B` | 무엇을 파는지 사내에서 답할 수 없었다 | 추가 |
| F&B 요금제 | 계약해도 청구가 안 걸린다 | 3등급 추가 (35 / 55 / 85만원) |
| F&B 기능 목록 | 계약 자리에서 읽을 표가 없다 | 어드민 10 · 웹 12 |
| `DeploymentKind` 에 F&B | **고객사를 등록할 자리가 없었다** | `F&B Client` · `F&B Admin` 추가 (IR 것도 함께) |
| `ConsoleDomain` 에 F&B | 권한을 사내에서 볼 수 없었다 | `FNB_RESOURCES` 11 · `FNB_ROLES` 3 |
| `TenantRecord.domain` | 등급 이름만으로 플랜을 찾아 **IR·F&B 에 B2C 금액이 붙었다** | 제품 칸 추가, `planOfTenant(domain, name)` 로 고침 |

F&B 권한 카탈로그가 콘솔의 `대표 · 운영 · 조회` 셋과 뜻이 같게 맞춰져 있다 — 이름이 갈리면
사내에서 본 권한과 고객사가 콘솔에서 보는 권한이 다른 것처럼 읽힌다.

## 8. 남은 구멍 (우선순위 순)

1. **플랜 게이팅이 없다** — 사내에서 정한 플랜이 테넌트 콘솔의 메뉴를 열고 닫지 않는다. 문서는
   된다고 적혀 있어, 이 어긋남이 계약 자리에서 드러난다.
2. **IR 사이트의 공시 · 재무 · 주주 · 자료 열한 화면에 어드민이 없다** — 값은 사이트에
   나가는데 고치는 화면이 저장소에 없다.
3. **취소 · 반품 기간 정책이 없다** — 전자상거래법 표시 항목인데 코드에도 문서에도 없었다.
   `policy.md` 에서 정한다.
4. **IR 첫 화면 배너가 어드민과 안 이어져 있다** — `SITE_BANNERS` 의 `메인 비주얼` 을 사이트가
   안 읽고 `HERO_SLIDES` 를 그린다. 팝업은 이어졌다.

메운 것:

| 무엇 | 어떻게 |
|---|---|
| 팝업 렌더 (F&B · B2C · IR 셋 다) | `PopupLayer` · `SitePopup`. 기간 판정은 store 한 벌이 하고 화면은 감추기만 한다 |
| IR 두 앱의 문서 레이어 | `/docs` 를 이식했다 — 이제 일곱 앱 모두가 갖는다 |

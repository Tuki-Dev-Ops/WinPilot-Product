# 정책 명세

이 저장소의 화면이 지켜야 하는 규칙을 한자리에 모은다.

## 이 문서를 읽는 법

항목마다 **상태**가 붙는다. 지금 코드가 무엇을 하고 있는지와 무엇을 해야 하는지를 갈라
적는다 — 둘을 섞으면 "된다고 적혀 있는데 안 되는" 자리가 문서 안에서 사라진다.

| 상태 | 뜻 |
|---|---|
| 🟢 구현 | 코드가 이대로 동작한다. 파일 경로가 붙는다 |
| 🟡 표시만 | 화면에 글자로는 있는데 코드가 강제하지 않는다 |
| 🔴 미구현 | 정한 것뿐이다. 만들 때 이 문서를 근거로 삼는다 |

**프론트엔드 전용 저장소다.** 서버가 없으므로 결제 · 발송 · 보관 같은 것은 실제로 일어나지
않는다. 그래도 정책을 먼저 적어 두는 이유는, 서버가 붙는 날 화면이 이미 만들어 놓은 규칙과
서버가 만드는 규칙이 갈리는 것을 막기 위해서다.

## 1. B2C — 거래

### 1-1. 주문 상태

두 축이 따로 논다. **결제 상태**와 **배송 상태**는 서로를 막지 않는다.

| 축 | 값 |
|---|---|
| 결제 | `결제완료` · `결제취소` · `환불완료` |
| 배송 | `배송준비` · `배송중` · `배송완료` · `교환요청` · `교환완료` |

전이 규칙:

| 전이 | 조건 | 상태 |
|---|---|---|
| 결제완료 → 결제취소 | `결제완료` 일 때만. 되돌릴 수 없다 | 🟢 구현 |
| \* → 배송중 | 운송장 등록 시. **현재 배송 상태를 검사하지 않는다** | 🟢 구현(가드 없음) |
| \* → 교환요청 | 교환 접수. 한 번에 한 건만 | 🟢 구현 |
| → 환불완료 | — | 🔴 타입만 있고 가는 길이 없다 |
| → 교환완료 | — | 🔴 같음 |

**정할 것**: `배송완료` 인 주문의 운송장은 잠근다. 지금은 다시 `배송중` 으로 되돌릴 수 있다.
문서에는 잠긴다고 적혀 있는데 코드가 그렇지 않다. 🔴

### 1-2. 취소 · 반품 · 환불 — **기간을 여기서 정한다**

코드에도 문서에도 기간 규칙이 없었다. 전자상거래법이 요구하는 표시 항목이므로 아래를 기준으로
삼는다.

| 항목 | 기준 | 근거 |
|---|---|---|
| **주문 취소** | 배송 준비 중이면 언제든. 배송이 시작되면 취소가 아니라 반품이다 | 발송 후에는 물건이 이미 움직인다 |
| **단순 변심 반품** | **수령일로부터 7일 이내** | 전자상거래법 제17조 1항 |
| **표시·광고와 다르거나 하자** | **안 날로부터 30일 이내, 받은 날로부터 3개월 이내** | 같은 법 17조 3항 |
| **환불 처리** | 반품 도착 확인 후 **3영업일 이내** | 같은 법 18조 2항이 3영업일을 정한다 |
| **환불 불가** | **최종 결제 완료일로부터 15일이 지나면 단순 변심 환불을 받지 않는다** | 회사 정책. 법정 7일보다 길게 잡아 둔 것이라 고객에게 불리하지 않다 |
| **반품 배송비** | 단순 변심은 고객 부담, 하자·오배송은 회사 부담 | |
| **교환** | 같은 상품 · 같은 색상 · **다른 사이즈만.** 한 번에 한 건 | 🟢 구현 |

교환을 그 셋으로 좁힌 이유가 코드에 적혀 있다 — 다른 상품이나 다른 색으로 바꾸는 것은 교환이
아니라 **취소 후 재주문**이고, 금액과 재고가 달라지므로 그 화면에서 처리할 일이 아니다.

사이즈 옵션이 없는 단일 상품은 교환 불가. 재고 0 인 사이즈는 목록에 **남기되 못 누르게** 한다 —
왜 못 고르는지 보여야 하기 때문이다. 🟢

**미구현**: 위 기간 규칙 전부 🔴. 고객 화면에 취소 · 반품 신청 자리 자체가 없다(어드민만 취소
가능). 표시 의무가 있는 항목이므로 상품 상세와 주문 상세에 이 표가 서야 한다.

### 1-3. 쿠폰

| 규칙 | 값 | 상태 |
|---|---|---|
| 상태 판정 순서 | 사용 완료 → 기간 만료 → 사용 가능 | 🟢 |
| 한 주문에 쓰는 장수 | **한 장만** | 🟢 |
| 정률 쿠폰 값 | 1 이상 100 이하 | 🟢 |
| 정액 쿠폰 값 | 1원 이상 | 🟢 |
| 최대 할인 한도 | **정률에만** 입력칸이 뜬다 | 🟢 |
| 최소 주문 금액 | 미달이면 결제 단추에서 막는다(고르는 시점엔 안 막음) | 🟢 |
| 이미 발급한 쿠폰 | **조건을 나중에 바꾸지 않는다** — 수정 기능 자체가 없다 | 🟢 |
| 만료된 공개 쿠폰 | '쿠폰 받기' 목록에서 아예 뺀다 | 🟢 |
| 내 쿠폰함의 만료 쿠폰 | 숨기지 않고 흐리게 남긴다 | 🟢 |
| 결제 시 소진 | 결제해도 `used` 가 안 바뀐다 | 🔴 |

여러 장을 겹쳐 쓰는 규칙(중복 가능 여부 · 적용 순서)은 **운영이 정할 일**이라, 정해지기 전에
화면이 먼저 규칙을 만들면 되돌리기 어렵다. 그래서 한 장으로 둔다.

### 1-4. 적립금

| 규칙 | 값 | 상태 |
|---|---|---|
| 적립 계산 | 정률은 판매가 기준 **내림** | 🟢 |
| 적립률 상한 | 100% | 🟢 |
| 사용 | **전액 사용 체크박스 하나.** 부분 사용 불가 | 🟢 |
| 사용 상한 | 보유액과 (상품금액 − 쿠폰할인) 중 작은 값 | 🟢 |
| 배송비에 사용 | 불가 — 배송비는 할인 대상이 아니다 | 🟢 |
| 적립 · 차감 실행 | 주문이 적립금을 늘리거나 줄이는 코드가 없다 | 🔴 |
| 어드민 조정 | 회원 폼에 적립금 칸이 없다 | 🔴 |

**정할 것**: 적립 시점은 **구매 확정 시**(배송완료 + 7일)로 한다. 결제 즉시 적립하면 취소·반품
때 회수해야 하고, 이미 쓴 뒤면 회수할 것이 없다. 🔴

유효기간은 **적립일로부터 1년**. 소멸 30일 전 알린다. 🔴

### 1-5. 할인 계산 순서

```
상품금액 → 등급 할인 → 쿠폰 할인 → 적립금 차감 → (배송비 더하기)
```

**등급이 쿠폰보다 먼저다.** 등급은 그 사람에게 늘 걸리는 것이고 쿠폰은 이번 주문에만 쓰는
것이라, 늘 걸리는 것을 먼저 적용해야 쿠폰의 최대 할인 한도가 같은 기준으로 잡힌다. 반대로
두면 같은 쿠폰이 등급에 따라 다르게 깎인다. 🟢

배송비는 할인 대상이 아니라 **맨 마지막에 더한다.** 🟢

배송비는 **어드민이 상품마다 정한 정책**에서 나온다(`orderShippingFee`). 🟢

| 정책 | 계산 |
|---|---|
| 무료 | 0원 |
| 조건부 무료 | **주문 전체 금액**이 문턱 이상이면 0원, 아니면 배송비 |
| 유료 | 배송비 |

한 주문에 **한 번만** 붙는다 — 여러 상품을 담으면 가장 비싼 조건 하나를 따른다. 상품마다 더하면
세 벌을 산 사람이 배송비를 세 번 낸다.

조건부 무료의 문턱은 **그 상품 하나의 값이 아니라 주문 전체**로 본다. `3만원 이상 무료` 인
상품을 만 원짜리로 세 개 담으면 무료여야 한다 — 장바구니에서 합계를 보고 담는 사람의 셈이 그렇다.

한때 이 자리에 `5만원 이상 무료, 미만 3,000원` 이 글자로 박혀 있었다. 어드민은 상품마다 정책을
받고 있었고 상품 상세는 그 값으로 문구를 그렸으므로, **상세에서 `3만원 이상 무료배송` 을 보고
담은 사람이 결제에서 5만원 기준에 걸렸다.**

**지역별 추가비는 아직 안 붙는다** 🔴 — 배송지를 다 적기 전에는 어느 지역인지 모르고, 주소를
적는 도중에 금액이 바뀌면 그 변화가 무엇 때문인지 읽히지 않는다.

### 1-6. 회원 등급

| 규칙 | 값 | 상태 |
|---|---|---|
| 산정 | 누적 결제금액 자동. 사용자가 고를 수 없다 | 🟢 |

| 할인율 적용 | 결제에서 **상품금액에 걸린다**. 쿠폰보다 먼저 | 🟢 |

**정할 것**: 등급 산정 기간은 **최근 12개월 누적**. 매월 1일 재산정. 강등은 한 단계씩만. 🔴

## 3. IR

**아래 규칙 대부분이 지금 `투자자 사이트에만` 산다.** 어드민의 공시 · 재무 · 주주 · 자료 화면
열을 지웠기 때문이다 — 게시 · DART · 지분 합 같은 규칙은 **강제하던 화면이 없어졌고**, 남은
것은 사이트가 값을 어떻게 읽고 그리는지다. 서버가 붙는 날 이 표가 그 규칙의 근거가 된다.

| 항목 | 규칙 | 상태 |
|---|---|---|
| 공시 상태 | `작성 중` · `검토 요청` · `공시됨` · `정정` | 🟢 |
| 사이트 노출 | `공시됨` 과 `정정` 만. **주소로도 안 열린다** | 🟢 |
| 게시 | 되돌릴 수 없다. 나간 뒤에는 정정 공시로만 고친다 | 🔴 **게시하는 화면을 지웠다** |
| 재게시 | 이미 나간 것은 다시 게시할 수 없다 | 🔴 같음 |
| 권한 | 원고 작성과 게시를 나눈다 | 🟢 카탈로그만 |
| DART 고유번호 | 8자리 숫자 | 🔴 검증하던 폼을 지웠다 |
| DART 확인 주기 | **5분 이상 1,440분 이하** — 짧으면 호출 한도에 걸린다 | 🔴 같음 |
| 주가 | 지연 시세임을 **항상** 표시 | 🟢 |
| 주가 숫자 | 손으로 고치는 칸을 두지 않는다 | 🟢 이제 화면 자체가 없다 |
| 전자투표 | 여기서 투표하지 않는다. **행사 기간은 총회일 전날까지** | 🟢 |
| 지분 합 | 100% ± 0.05 를 벗어나면 경고 | 🔴 경고하던 화면을 지웠다 |
| 자료실 파일 | **크기를 반드시 표기** — 모바일에서 8MB 를 모르고 누르는 것과 알고 누르는 것은 다르다 | 🟢 |
| 구독 메일 | **확인 안 된 주소로는 보내지 않는다** | 🟢 규칙만 |
| 문의 답변 | `답변완료` 로 갈 때만 답변 본문 필수 | 🟢 |
| 문의 원문 | 보낸 사람의 글은 **수정 불가** | 🟢 |
| 문의 응답 | 영업일 기준 **1~2일** | 🟡 문구만 |
| 첨부 | **20MB** | 🟢 문의 답변 폼이 지킨다 |
| 공정공시 | 공시 전 실적·전망을 개별 안내하지 않는다 — 폼에 상시 고지 | 🟢 |
| 배너 · 팝업 노출 | 사람이 켜지 않고 **날짜가 정한다**(`scheduleState`). B2C 배너와 같은 판정을 쓴다 | 🟢 |
| 팝업 동시 노출 | 걸린 것이 여럿이어도 **한 번에 하나만**. 닫으면 다음 것이 뜬다 | 🟢 |
| 팝업 자리 | 가운데 하나뿐이다. 여기 뜨는 것이 휴무·처리방침 개정처럼 **읽혀야 뜻이 있는 고지**라, 모서리에 조용히 서는 자리를 두지 않는다 | 🟢 |
| 팝업 본문 | **필수**. 제목만 뜬 팝업은 무슨 일인지 안 알려 주는 상자가 된다 | 🟢 |
| 팝업 `하루 감추기` | 그 사람의 브라우저에만 남는다. 날짜가 바뀌면 저절로 되살아난다 | 🟢 |
| 되돌릴 수 없는 동작의 자리 | **사이드바에 있어야 한다** — 급할 때 주소를 외워 닿는 자리에 두면 못 찾는다 | 🟢 어길 자리가 없어졌다. 공시 게시 화면을 지웠다 |

## 7. 이 문서가 만들어진 이유

정책이 코드 주석에 흩어져 있었다. 주석은 그 파일을 여는 사람만 읽고, **정하지 않은 것은 주석에도
없다.** 취소 · 반품 기간이 그랬다 — 전자상거래법이 표시하라는 항목인데 저장소 전체에 그 문자열이
하나도 없었다.

🔴 로 표시한 것은 **아직 안 만든 것**이다. 만들 때 여기서 값을 가져가고, 만든 뒤에 🟢 로 바꾼다.

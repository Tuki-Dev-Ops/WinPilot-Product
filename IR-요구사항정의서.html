1. 사 업 배 경 과 목 표

1.1 배경

회사 홈페이지의 내용이 코드에 고정되어 있으면 공지 한 건, 제품 소개 한 줄을 고치는 데에도 개발과 배포가 필요하다. 그 결과 사이트는 구축 시점에 멈추고, 최신 소식과 특허 · 인증이 실제보다 뒤처진 상태로 남는다. 도입을 검토하는 방문자의 문의도 전화와 이메일로만 들어와, 누가 언제 무엇을 물었고 답했는지가 남지 않는다.

1.2 목표

순번구분목표판단 기준
1도입 문의 확보방문자가 제품이 자기 문제를 푸는지 스스로 판단할 수 있어야 한다.제품별로 해결 대상 문제 · 기능 · 구성 · 성과 · 적용 업종 · 진행 절차가 공개되어 있고, 각 화면에서 문의 경로가 연결된다.
2회사 신뢰 확보거래 상대가 회사의 실적과 자격을 확인할 수 있어야 한다.연혁이 최신으로 유지되고, 특허 · 인증을 등록번호로 조회할 수 있다.
3문의 관리접수된 문의가 유형별로 분류되어 누락 없이 처리되어야 한다.문의가 목록으로 쌓이고 처리 상태와 답변이 관리되며, 대시보드에서 유입량과 유입 경로를 확인할 수 있다.
4운영 자립운영자가 개발 의존 없이 사이트 내용을 유지할 수 있어야 한다.사이트에 노출되는 값 전부에 대응하는 관리 화면이 존재한다.

오시는 길 화면이 본사 한 곳을 표식으로 세운다. 매장 여럿을 다루지 않으므로 검색이나 필터와 맞물리지 않는다. 키와 도메인 등록은 발주처 계정으로 발급받아야 하는 값이라, 개발이 끝나도 이 값이 없으면 지도가 표시되지 않는다. 착수 시점에 준비를 시작해야 한다.

순번요구 ID준비 항목주체내용미준비 시 영향
1REQ-EX-01카카오 계정발주처카카오 개발자 사이트(developers.kakao.com)에 로그인할 계정이다. 개발자 계정은 카카오 계정 기준이며, 무료 쿼터가 이 계정 단위로 부여되므로 담당자 개인 계정이 아니라 회사가 계속 보유할 수 있는 계정으로 만들어야 한다.앱 등록 자체가 불가능하다.
2REQ-EX-02앱 등록발주처개발자 사이트에서 애플리케이션을 생성하고, 앱 관리 콘솔에서 카카오맵 API 를 활성화한다.키가 발급되지 않는다.
3REQ-EX-03웹 플랫폼 등록발주처[내 애플리케이션] → [플랫폼] → [Web] 에서 사이트 도메인을 등록한다. 등록된 도메인에서만 지도 API 가 동작하므로 운영 도메인 · 스테이징 도메인 · 개발용 http://localhost:3304 를 모두 등록한다.등록되지 않은 도메인에서는 지도가 뜨지 않는다. 화면은 대체 안내 영역을 표시한다.
4REQ-EX-04JavaScript 키발주처 → 수행사앱의 JavaScript 키를 전달받아 환경 변수 NEXT_PUBLIC_KAKAO_MAP_KEY 로 설정한다. 이 키는 브라우저에 노출되는 값이므로, 도메인 등록이 사실상의 접근 통제 수단이 된다. REST API 키 · Admin 키와는 다른 값이다.지도 SDK 를 내려받지 못한다.
5REQ-EX-05무료 쿼터 확인발주처개발자 계정이 소유한 앱 1개에만 무료 이용 쿼터가 부여된다. 두 번째 앱부터는 유료 설정 후 사용량에 따라 과금될 수 있으므로, 이 서비스용 앱을 무료 쿼터가 걸린 앱으로 지정할지 확인이 필요하다. 사용량은 개발자 콘솔의 [통계] → [쿼터] 에서 확인한다.의도치 않은 과금이 발생하거나 쿼터 초과로 지도가 멈춘다.
6REQ-EX-06유료 전환 여부발주처무료 쿼터를 초과해 운영할 계획이면 비즈니스 지갑 연결과 유료 API 사용 설정이 필요하다. 참고 수치
- 무료 제공은 전체 API 월 300만 건, 지도 일 30만 건, 좌표→주소 변환 일 10만 건이며, 초과분 단가는 지도 0.1원/건, 좌표→주소 변환 0.5원/건으로 안내되어 있다. 정책과 단가는 변경될 수 있으므로 계약 시점에 재확인한다.		쿼터 초과 시 429 응답과 함께 지도 호출이 차단된다.
7REQ-EX-07표기 및 이용 조건발주처카카오맵 로고 및 디자인 가이드가 별도로 제공된다. 상업적 이용 조건과 표기 의무는 카카오 정책 문서를 계약 시점에 확인한다.표기 누락 시 이용 조건 위반 소지가 있다.

연동 방식 — 브라우저에서 https://dapi.kakao.com/v2/maps/sdk.js 를 appkey 와 함께 내려받아 지도를 그린다. 서버를 거치지 않으므로 2단계 Back-End 구축 이후에도 이 구조는 그대로 유지된다.

7. 제 약 사 항 과 전 제

  • 1단계 시점에는 서버와 데이터베이스가 없다. 화면이 참조하는 데이터는 공통 데이터 구조로 관리하며, 관리자에서의 변경은 브라우저 세션 범위에서 유지된다. 2단계에서 실제 서버로 대체한다.
  • 제품과 서비스는 등록과 삭제를 제공하지 않는다. 화면 구조가 코드에 있어 문구만 고칠 수 있으며, 제품을 늘리는 것은 별도 협의 대상이다.
  • 회원 체계는 사이트에 두지 않는다. 방문자는 로그인 없이 전 화면을 이용하며, 로그인은 관리자에만 존재한다.
  • 관리자 계정 관리 화면이 현재 범위에 없다. 계정 발급과 권한 회수 절차는 정의가 필요하다.
  • 개인정보를 수집하는 경로는 문의하기 한 곳이다. 다만 현재 화면에 개인정보 수집 · 이용 동의 항목이 없어 추가가 필요하다. 보존과 파기 기준은 「비기능 명세서」에 정의한다.
  • 방문 통계는 조회 화면만 존재하며, 수집 방식 · 집계 주기 · 보존 기간은 2단계에서 확정한다.
  • 요구사항의 추가와 변경은 「과업범위 정의서」의 변경 관리 기준을 따른다.

3. 공통 기능

전 화면에 공통으로 적용되는 구현 기준입니다. 성능 · 반응형 · 접근성 · 보안 등 비기능 요건 전체는 「비기능 명세서」에 정의되어 있으며, 본 장에는 화면 구현에 직접 적용되는 항목만 기재합니다.

  • 데스크톱 1440 · 태블릿 768 · 모바일 375 세 너비에서 가로 스크롤이 생기지 않습니다.
  • placeholder·option·input value 는 추출되지 않으므로 화면 문구로 쓰지 않는다 (겹친 글자·직접 그린 목록으로 대체).
  • 차트·아이콘·삽화는 전부 인라인 SVG 입니다. 비트맵은 Figma 에서 벡터로 복원되지 않습니다.
  • 모션 감소를 켠 사용자에게는 자동 넘김·전환이 돌지 않습니다.
  • 색만으로 상태를 알리지 않습니다
    - 모양이나 글자를 함께 둡니다.
  • 토스트는 화면 하단 정중앙 한 곳에서만 뜹니다.

8.3 데이터 관계 정의

후속 개발자가 데이터 모델을 설계할 수 있는 요구사항 수준으로 정의합니다. 물리 ERD 는 포함하지 않습니다.

순번관계정의
1메뉴 카테고리 : 메뉴하나의 메뉴 카테고리는 여러 메뉴를 가집니다. 메뉴는 반드시 하나의 카테고리에 속합니다.
2메뉴 : 알레르기 정보하나의 메뉴는 여러 알레르기 유발 재료를 가질 수 있으며, 값은 정의된 목록에서 선택합니다.
3메뉴 : 표시 태그하나의 메뉴는 여러 표시 태그를 가질 수 있습니다. 태그가 부여된 메뉴는 홈의 대표 메뉴 영역에 우선 배치됩니다.
4마케팅 채널 : 마케팅 콘텐츠하나의 채널은 여러 게시물을 가집니다. 게시물은 반드시 하나의 채널에 속합니다.
5지역 : 가맹점하나의 지역은 여러 가맹점을 가집니다. 가맹점은 하나의 지역에 속하며, 지역 목록은 가맹점 데이터에서 도출합니다.
6가맹점 : 제공 서비스하나의 가맹점은 여러 제공 서비스 항목을 가질 수 있습니다.
7창업 상담 신청 : 상담 상태하나의 창업 문의는 하나의 상담 상태를 가집니다. 상태 이력의 보관 여부는 별도 협의 대상입니다.
8창업 상담 신청 : 상담 메모하나의 창업 문의는 여러 건의 상담 메모를 가질 수 있습니다.
9지역 : 창업 상담 신청창업 문의의 검토 지역은 가맹점의 지역 목록과 동일한 값을 사용합니다. 별도 목록으로 관리하면 어느 필터에도 걸리지 않는 문의가 발생합니다.
10문의 분류 : FAQ하나의 문의 분류는 여러 FAQ 를 가집니다. FAQ 는 하나의 분류에 속합니다.
11대상 구분 : FAQFAQ 는 창업 또는 고객 중 하나의 대상 구분을 가지며, 대상 구분에 따라 노출되는 고객 서비스 화면이 갈립니다.
12공지사항 : 노출 상태하나의 공지는 공개 여부와 상단 고정 여부를 각각 가집니다. 두 값은 독립적으로 관리합니다.
13배너 · 팝업 : 노출 기간하나의 배너 또는 팝업은 노출 시작일과 종료일을 가집니다. 종료일이 없으면 상시 노출로 판정합니다.
14관리자 계정 : 권한 등급하나의 관리자 계정은 하나의 권한 등급을 가집니다.

비기능 요건 · 4/4 2026년 8월 20일

1. 적 용 범 위

본 문서는 고객 서비스와 관리자 서비스 전 화면 47개에 적용된다. 화면 하나에만 걸리는 요건은 3장 「화면별 비기능 요건」에 따로 두었다.

1단계(Front-End)에서 판정 가능한 요건과 2단계(Back-End)에서 판정하는 요건을 구분해 표기한다. 구분하지 않으면 서버가 없는 상태에서 보안 요건이 미충족으로 잡히고, 실제로는 아직 만들 차례가 아닌 것을 결함으로 다루게 된다.

2. 공 통 비 기 능 요 건

주제별로 정리한다. 요건마다 기준값과 검증 방법을 함께 적었으며, 저장소에 검사 도구가 있는 항목은 그 도구를 적었다.

구분요건기준검증 방법
성능화면 하나가 내려받는 자원 크기를 예산 안으로 관리한다.JavaScript 700KB · CSS 120KB · 이미지 400KB (전송 기준). 문서 화면은 JavaScript 1600KB 를 적용한다.저장소의 weight:check 가 전 화면을 실제로 열어 전송 바이트를 잰다.
목록 화면은 조회 조건이 바뀔 때 화면 전체를 다시 그리지 않는다.조건 변경 시 목록 영역만 갱신되며, 헤더 · 필터 상태는 유지된다.화면별 검수 기준으로 확인한다.
반응형정의된 기준 해상도에서 의도하지 않은 가로 스크롤이 발생하지 않는다.1280 · 1024 · 768 · 390 네 너비. 화면 47개 × 4 지점을 모두 검사한다.저장소의 overflow:check 가 자동으로 검사한다.
표와 넓은 콘텐츠는 화면 밖으로 넘치지 않고 자체 영역에서 스크롤한다.좁은 너비에서 표는 가로 스크롤 영역을 가지며, 페이지 본문은 가로로 움직이지 않는다.overflow:check · 육안 확인.
접근성색만으로 상태를 알리지 않는다.노출 · 미노출 등 상태 표시는 색과 함께 모양 또는 글자를 둔다.상태 표시 요소를 흑백으로 두고 구분 가능한지 확인한다.
모션 감소를 켠 사용자에게는 자동 전환이 동작하지 않는다.캐러셀 자동 넘김과 흐르는 띠가 멈춘다. 사용자가 직접 조작하는 이동은 유지한다.운영체제의 모션 줄이기 설정을 켜고 확인한다.
자동 전환은 사용자 조작 중에 멈춘다.마우스가 올라가거나 포커스가 들어오거나 직접 밀면 자동 넘김이 멈춘다.화면별 검수 기준으로 확인한다.
화면 밖으로 벗어난 영역의 자동 전환은 동작하지 않는다.보이지 않는 영역에서 타이머가 돌지 않는다.스크롤 후 동작 확인.
사용성알림은 한 자리에서만 표시한다.토스트는 화면 하단 정중앙 한 곳에서만 뜬다.전 화면 공통 확인.
데이터가 없는 상태를 빈 화면으로 두지 않는다.목록 결과가 0건이면 빈 상태 문구를 세우고, 조건이 걸려 있으면 조건을 지우는 경로를 함께 둔다.「기능 명세서」의 예외 처리 기준으로 확인한다.
입력 오류는 미입력과 형식 오류를 구분해 안내한다.「형식이 아닙니다」는 빈 칸에 대한 답이 아니다. 항목별로 사유를 구분한다.양식이 있는 화면의 검수 기준으로 확인한다.
호환성최신 브라우저에서 동작한다.Chrome · Edge · Safari · Firefox 의 최신 두 개 버전과 iOS · Android 기본 브라우저.대상 브라우저에서 주요 화면 육안 확인. 지원 범위는 발주처 확인이 필요하다.
이미지가 없는 상태에서도 화면 구조가 무너지지 않는다.이미지 미제공 영역은 대체 표기로 자리를 유지한다.이미지 차단 상태로 확인한다.
보안사이트와 관리자 모두 HTTPS 로만 제공한다.개인정보가 오가는 경로가 있다.배포 환경 설정 확인. 2단계 · 배포 시점 적용.
관리자는 인증된 운영자만 접근한다.권한 등급과 등급별 연산 범위는 4장에 정리한다.2단계 구현 대상. 1단계에서는 화면 흐름까지 구현되어 있다.
개인정보가 포함된 데이터는 접근 권한을 분리한다.콘텐츠 관리와 다른 권한으로 다룬다. 분리 수준은 발주처 확인이 필요하다.2단계 구현 대상.
화면 검증에 의존하지 않는다.「기능 명세서」에서 서버 검증으로 표기된 규칙은 API 직접 호출에도 적용되어야 한다.2단계 완료 기준. API 를 직접 호출해 확인한다.
데이터동일한 값을 두 곳에서 관리하지 않는다.사이트와 관리자는 같은 데이터를 참조한다. 합계 · 건수 · 목록은 저장하지 않고 계산한다.「기능 명세서」의 데이터 변경 영향도로 확인한다.
노출 중단과 데이터 삭제를 구분한다.노출 상태를 해제해도 데이터는 유지된다. 삭제는 더 이상 사용하지 않는 데이터에 한정한다.상태 변경 후 관리자 목록에 값이 남아 있는지 확인한다.
삭제는 사본까지 함께 처리한다.본문뿐 아니라 첨부 · 검색 색인 · 캐시에 남은 사본을 함께 제거한다.2단계 구현 대상.
운영변경 이력을 남긴다.등록 · 수정 · 삭제마다 누가 · 언제 · 무엇을 바꿨는지 기록한다.2단계 구현 대상. 보존 기간은 5장 참조.
개인정보 열람 기록을 남긴다.개인정보가 담긴 건을 열어 본 기록을 남긴다. 변경 기록만으로는 누가 들여다봤는지 알 수 없다.2단계 구현 대상.
성능지도는 매장 수와 무관하게 좌표 변환 요청을 발생시키지 않는다.좌표는 가맹점 데이터가 보유한다. 화면에서 주소를 좌표로 변환하지 않는다.네트워크 요청 확인
- 지도 SDK 외 외부 호출이 없어야 한다.
외부 연동지도를 이용할 수 없어도 매장 정보는 조회된다.키 미설정 · 도메인 미등록 · 쿼터 초과 시 지도 영역은 대체 안내를 표시하며, 매장 목록과 검색은 정상 동작한다.키를 비운 상태로 매장 찾기 화면을 확인한다.
외부 서비스 사용량을 관리한다.카카오 지도는 개발자 계정당 앱 1개에 무료 쿼터가 부여된다. 사용량은 개발자 콘솔에서 확인한다.「요구사항 정의서」 참조. 운영 주체는 발주처다.
문서문서와 코드가 어긋난 상태로 남지 않는다.화면이 등록되었는데 명세가 비어 있거나, 명세가 가리키는 화면이 사라진 상태를 허용하지 않는다.spec:check · sync:check · docs:check · bind:check

2.1 전 화면 공통 제작 기준

화면을 가리지 않고 전 화면 제작에 적용되는 기준이다.

  • 데스크톱 1440 · 태블릿 768 · 모바일 375 세 너비에서 가로 스크롤이 생기지 않습니다.
  • placeholder·option·input value 는 추출되지 않으므로 화면 문구로 쓰지 않는다 (겹친 글자·직접 그린 목록으로 대체).
  • 차트·아이콘·삽화는 전부 인라인 SVG 입니다. 비트맵은 Figma 에서 벡터로 복원되지 않습니다.
  • 모션 감소를 켠 사용자에게는 자동 넘김·전환이 돌지 않습니다.
  • 색만으로 상태를 알리지 않습니다
    - 모양이나 글자를 함께 둡니다.
  • 토스트는 화면 하단 정중앙 한 곳에서만 뜹니다.

3. 화 면 별 비 기 능 요 건

해당 화면에만 걸리는 요건이다. 전 화면에 걸리는 것은 2장에 한 번만 적었으므로 여기서 되풀이하지 않는다. 총 67항목.

기능 ID화면구분요건
BRAND-001브랜드 이야기고객 사이트
  • 브랜드명 · 창업 연도 · 매장 수를 글자로 적지 않습니다
    - 전부 값에서 읽습니다.
MENU-001메뉴판고객 사이트
  • 묶음별 개수는 모듈이 처음 불릴 때 한 번만 셉니다
    - 렌더 안에서 세면 묶음을 바꿀 때마다 메뉴 전체를 다시 훑습니다.
  • 기둥은 좁은 화면에서 가로로 접힙니다. 세로로 두면 첫 화면이 고르는 줄로 채워집니다.
  • 매운 정도는 표가 아니라 불꽃 개수로 알립니다
    - 맵다는 말만으로는 얼마나 매운지가 빠집니다.
MENU-002메뉴 상세고객 사이트
  • 알레르기는 문장이 아니라 목록으로 받습니다
    - 우유 조금 같은 말은 검색도 대조도 되지 않습니다.
  • 메뉴 카드는 메뉴판 · 상세 · 홈이 한 조각을 함께 씁니다.
INTERIOR-001인테리어고객 사이트
  • 굴림 규칙은 홈의 대표 메뉴와 같은 조각을 씁니다
    - 두 벌이면 한쪽만 고쳐지는 날이 옵니다.
  • 숫자는 고정폭입니다. 세 안을 넘겨 볼 때 자릿수가 같은 자리에 서야 견줘집니다.
  • 모자이크는 넓이의 합이 열여섯 칸이라 두 열에서도 네 열에서도 줄이 떨어집니다.
MARKETING-001마케팅고객 사이트
  • 카드에 hover 를 넣지 않습니다
    - 움직이지 않는 것이 누를 수 없다는 말이 됩니다.
  • 기둥은 좁은 화면에서 가로로 접힙니다.
STORE-001매장 찾기고객 사이트
  • 표식을 다시 만들지 않고 보일지 말지만 바꿉니다
    - 걸러질 때마다 새로 만들면 지도가 깜빡입니다.
  • 걸러 낸 목록을 기억해 둡니다. 렌더마다 새로 만들면 검색창에 다섯 글자를 칠 때 지도 맞춤이 다섯 번 일어납니다.
  • 지도가 없어도 목록과 검색은 그대로 씁니다.
  • 줄 전체가 단추이며 aria-pressed 로 눌린 상태를 알립니다
    - 지도가 움직인 것은 낭독기에 전해지지 않습니다.
FRANCHISE-001가맹점 개설절차고객 사이트
  • 탭은 밑줄입니다
    - 채워진 알약은 지금 보고 있는 자리가 아니라 지금 눌러야 할 자리로 읽힙니다.
  • 금액은 고정폭 숫자로 세로가 맞습니다.
FRANCHISE-002가맹점 상담 신청고객 사이트
  • 고르개는 생 <select> 가 아니라 공유 조각을 씁니다
    - 다른 화면의 고르개와 생김새가 갈리지 않게.
  • 동의 문구가 무엇을 얼마나 보관하는지를 함께 적습니다. 한 줄만 두면 그 동의는 실제로 동의가 아닙니다.
  • 지역과 예산이 같은 첫 값(고르지 않음)을 씁니다.
FRANCHISE-003가맹점 개설문의고객 사이트
  • 접힌 본문은 높이가 0 이면서 invisible 이라 낭독기와 탭 이동에서 빠집니다.
  • 펴고 접히는 것은 grid-rows 로 움직입니다
    - 본문 높이를 미리 알 수 없어 max-height 로는 잘리거나 느려집니다.
SUPPORT-001공지사항고객 사이트
  • 왼쪽 기둥은 목록을 읽는 내내 같은 자리에 남습니다
    - 가로 탭이면 조금만 내려도 화면 밖으로 나갑니다.
  • 고정 공지는 색이 아니라 딱지 글자로 알립니다.
  • 기둥은 좁은 화면에서 가로로 접힙니다.
SUPPORT-002자주 묻는 질문고객 사이트
  • 같은 FNB_FAQS 를 갈래로 걸러 씁니다
    - 두 벌로 적어 두지 않습니다.
  • 접힌 본문은 낭독기와 탭 이동에서 빠집니다.
LEGAL-001서비스 이용약관고객 사이트
  • 비워 두는 이유를 화면에 적습니다
    - 준비 중이라는 말만 두면 만들다 만 화면으로 보입니다.
LEGAL-002개인정보 처리방침고객 사이트

ADMIN-001대시보드관리자

6. 오 류 응 답 요 건

화면을 가리지 않고 같은 방식으로 처리한다. 화면마다 되풀이해 적으면 47벌이 되고, 한 곳만 고쳐진다.

상황발생 조건시스템 처리 · 화면 표시
존재하지 않는 데이터 조회요청한 식별자에 해당하는 데이터가 없습니다.서버는 404 로 응답한다. 화면은 목록으로 돌아가는 경로와 함께 없는 대상임을 안내한다.
비공개 데이터의 고객 서비스 접근공개 상태가 아닌 데이터를 고객 서비스 주소로 직접 요청했습니다.서버는 404 로 응답한다. 데이터의 존재 여부를 드러내지 않는다. 다만 메뉴는 판매 중지 안내와 함께 응답한다.
삭제된 데이터 접근삭제 처리된 데이터를 요청했습니다.서버는 404 로 응답한다. 삭제 이후 보관 기간 동안의 복구 요청은 관리자 경로로만 처리한다.
필수값 누락필수 항목이 비어 있는 상태로 저장을 요청했습니다.서버는 400 과 함께 누락 항목 목록을 응답한다. 화면은 입력값을 유지한 채 항목별로 안내한다.
형식 오류연락처 · 날짜 등 형식이 정해진 항목의 값이 규칙에 맞지 않습니다.서버는 400 과 함께 항목별 사유를 응답한다. 미입력과 형식 오류를 구분하여 응답한다.
허용되지 않은 상태값정의되지 않은 상태값으로의 변경을 요청했습니다.서버는 400 으로 응답하며 상태를 변경하지 않는다.
중복 데이터 등록이미 존재하는 값으로 등록을 요청했습니다. 관리자 계정의 이메일이 이에 해당합니다.서버는 409 로 응답한다. 화면은 중복 항목을 지목하여 안내한다.
권한 없는 접근인증되지 않았거나 등급이 부족한 요청입니다.미인증은 401, 등급 부족은 403 으로 구분하여 응답한다. 인증 구현은 2단계 대상이다.
검색 결과 없음조건에 해당하는 데이터가 없습니다.서버는 200 과 함께 빈 목록 및 총 건수 0 을 응답한다. 오류로 처리하지 않는다. 화면은 조건 초기화 경로를 함께 제공한다.
외부 서비스 오류지도 SDK 가 응답하지 않거나 인증 키가 유효하지 않습니다.화면은 빈 영역 대신 대체 안내를 표시한다. 매장 목록은 지도와 무관하게 조회 가능해야 한다.

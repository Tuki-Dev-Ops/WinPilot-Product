## 5. 사용자 시나리오

### 정상

- 이메일 및 비밀번호 로그인 → 결과가 화면에 바로 반영된다.
- 소셜 로그인 → 결과가 화면에 바로 반영된다.
- 회원가입 탭으로 이동 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 이메일 및 비밀번호 로그인 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 소셜 로그인 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 회원가입 탭으로 이동 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 어느 항목이 일치하지 않는지 구분하여 안내하지 않습니다. 계정 존재 여부가 노출되기 때문입니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 이메일 형식이 아니면 해당 위치에 안내를 표시합니다.
- 비밀번호는 8자 이상입니다.
- 두 항목 중 하나라도 미입력이면 버튼을 비활성화합니다.

### 화면 정책

- 회원가입은 동일 화면의 탭에서 진입합니다.
- 소셜 로그인 목록은 사내 어드민에서 사용 설정한 항목만 표시합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 비밀번호 찾기 화면. 현재는 링크 영역만 정의되어 있습니다.

## 5. 사용자 시나리오

### 정상

- 수정 모드 전환 → 결과가 화면에 바로 반영된다.
- 닉네임 자동 생성 → 결과가 화면에 바로 반영된다.
- 우편번호 서비스로 주소 검색 → 결과가 화면에 바로 반영된다.
- 마케팅 수신 동의 → 결과가 화면에 바로 반영된다.
- 저장 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 수정 모드 전환 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 닉네임 자동 생성 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 우편번호 서비스로 주소 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 마케팅 수신 동의 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 저장 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

- 닉네임은 2~12자이며 금칙어를 사용할 수 없습니다.
- 이메일은 수정할 수 없습니다. 계정 식별 기준이므로 조회만 제공합니다.
- 새 비밀번호를 입력한 경우 현재 비밀번호가 필수입니다.

### 화면 정책

- 저장하지 않고 화면을 벗어나면 수정 내용이 반영되지 않는다는 확인 안내를 표시합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 회원 탈퇴. 현재 해당 화면이 없습니다.

## 7. 사용자 시나리오

**정상**

- 배송지 수정 → 결과가 화면에 바로 반영된다.
- 배송 요청사항 선택(직접 입력 포함) → 결과가 화면에 바로 반영된다.
- 쿠폰 한 장 적용 → 결과가 화면에 바로 반영된다.
- 적립금 사용 → 결과가 화면에 바로 반영된다.
- 결제 수단 선택 → 결과가 화면에 바로 반영된다.
- 결제 → 결과가 화면에 바로 반영된다.

**예외**

- 배송지가 비면 결제할 수 없다.
- 쿠폰의 최소 주문 금액을 넘지 못하면 막고 그 이유를 말한다.
- 직접 입력을 골라 놓고 비워 두면 막는다.
- 주문 내용 확인 동의 없이는 결제할 수 없다.

## 9. 검증 규칙

- 필수 항목(받는 사람·연락처·주소·필수 약관)이 비면 결제 단추가 잠긴다.
- 연락처는 숫자와 하이픈만 받는다.
- 결제할 상품이 없으면 결제 단추가 잠긴다.
- 기간이 지났거나 조건에 못 미치는 쿠폰은 고를 수 없다.

## 10. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

## 11. UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

## 12. 화면 정책

- 상품 상세에서 장바구니를 거치지 않고 바로 들어올 수 있다(`?productId=…`).
- 결제 수단은 화면만 있고 실제로 결제하지 않는다 — 서버가 없다.

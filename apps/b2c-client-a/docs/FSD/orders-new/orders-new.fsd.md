## 5. 사용자 시나리오

### 정상

- 배송지 입력 → 결과가 화면에 바로 반영된다.
- 배송 요청사항 선택 → 결과가 화면에 바로 반영된다.
- 쿠폰 적용 → 결과가 화면에 바로 반영된다.
- 적립금 사용 → 결과가 화면에 바로 반영된다.
- 결제 수단 선택 → 결과가 화면에 바로 반영된다.
- 결제 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 배송지 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 배송 요청사항 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 쿠폰 적용 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 적립금 사용 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 결제 수단 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 결제 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 배송지가 미입력이면 결제할 수 없습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 쿠폰의 최소 주문 금액에 미달하면 적용하지 않고 사유를 표시합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 배송 요청사항에서 직접 입력을 선택하고 내용을 비우면 결제할 수 없습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 주문 내용 확인 동의 없이는 결제할 수 없습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 필수 항목(수령인 · 연락처 · 주소 · 필수 약관)이 미입력이면 결제 버튼을 비활성화합니다.
- 연락처는 숫자와 하이픈만 입력할 수 있습니다.
- 주문 대상 상품이 없으면 결제 버튼을 비활성화합니다.
- 사용 기간이 종료되었거나 조건에 미달하는 쿠폰은 선택할 수 없습니다.

### 화면 정책

- 상품 상세에서 장바구니를 거치지 않고 직접 진입할 수 있습니다(`?productId=…`).
- 결제 수단은 화면만 제공하며 실제 결제는 처리하지 않습니다. 서버 연동은 2단계 대상입니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 배송지 주소록. 현재는 매 주문 시 입력합니다.
- 부분 결제 및 분할 배송.

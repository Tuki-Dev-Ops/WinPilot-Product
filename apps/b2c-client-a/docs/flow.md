# Flow Chart — B2C Client 템플릿 A

> 지금 화면에 실제로 구현된 흐름만 적는다. 서버가 없으므로 저장은 브라우저(`localStorage`)에서
> 일어나고, 서버가 생기면 바뀌는 곳은 각 절의 **경계** 표시로 적어 둔다.

## 1. 구매

```mermaid
flowchart TD
  P["상품 상세 /products/[productId]"] --> C{"색상 고름?"}
  C -- 아니오 --> CE["토스트: 색상을 먼저 골라 주세요"]
  C -- 예 --> S{"사이즈 고름?"}
  S -- 아니오 --> SE["토스트: 사이즈를 골라 주세요"]
  S -- 예 --> Q{"수량 ≤ 재고?"}
  Q -- 아니오 --> QE["토스트: 재고보다 많이 담을 수 없습니다"]
  Q -- 예 --> B["장바구니 담기 / 바로 구매"]

  B --> CART["장바구니 /cart"]
  B --> CONFIRM["확인 창: 바로 주문할까요?"]
  CONFIRM --> CHECKOUT["결제 /orders/new"]
  CART --> CHECKOUT

  CHECKOUT --> V{"배송지·쿠폰·동의 확인"}
  V -- 어긋남 --> VE["토스트: 결제하지 못했습니다 + 무엇이 문제인지"]
  V -- 통과 --> PAY["확인 창: 결제할까요?"]
  PAY --> DONE["완료 /result?state=done&kind=order&id=…"]
  DONE --> ORDERS["주문 내역 /orders"]
```

- 품절 옵션은 **누를 수 없다**(`disabled` + 취소선). 눌러 놓고 마지막에 막으면 그때까지의 선택이 헛수고가 된다.
- 담기·바로 구매 앞에서 **같은 검사**를 돌린다. 한쪽만 막으면 다른 길로 같은 문제가 들어온다.
- **경계**: 장바구니와 주문은 `app/_components/cart-store.ts` 가 브라우저에 보관한다. 서버가 생기면 이 파일만 바뀐다.

## 2. 회원가입 (이메일 인증)

```mermaid
flowchart TD
  F["회원가입 /signup"] --> E{"이메일 형식"}
  E -- 어긋남 --> EE["토스트: 이메일 형식을 확인해 주세요"]
  E -- 맞음 --> SEND["인증번호 발송 · 3분 타이머"]
  SEND --> CODE{"번호 일치 · 시간 남음"}
  CODE -- 아니오 --> CE["토스트: 인증번호가 일치하지 않습니다 / 시간이 지났습니다"]
  CODE -- 예 --> OK["인증 완료 — 이메일 칸 잠김"]
  OK --> EDIT{"주소를 다시 고침?"}
  EDIT -- 예 --> RESET["인증 해제 — 처음부터"]
  EDIT -- 아니오 --> SUBMIT["가입하기"]
  SUBMIT --> CHECK{"필수 항목 · 비밀번호 확인 · 필수 동의"}
  CHECK -- 어긋남 --> CHE["토스트: 가입하지 못했습니다 + 첫 번째 문제"]
  CHECK -- 통과 --> CONF["확인 창: 이 내용으로 가입할까요?"]
  CONF --> DONE["완료 /result?state=done&kind=signup"]
```

인증 뒤 주소를 고치면 인증이 풀린다 — 그러지 않으면 인증만 받아 놓고 다른 주소로 가입할 수 있다.

## 3. 로그인 · 로그아웃

```mermaid
flowchart LR
  L["로그인 /login"] --> M{"이메일·비밀번호"}
  M -- 비었거나 형식 어긋남 --> ME["토스트: 로그인하지 못했습니다"]
  M -- 통과 --> ON["세션 켜짐 → 헤더가 바뀜"]
  L --> SOCIAL["카카오·네이버·Google·Facebook·Apple"] --> ON
  ON --> OUT["아바타 > 로그아웃"] --> OFF["세션 꺼짐 → 로그인 단추"]
```

실패 안내는 **어느 항목이 틀렸는지 말하지 않는다** — 계정이 있는지를 알려 주는 것과 같기 때문이다.

## 4. 문의

```mermaid
flowchart TD
  C["문의하기 /contact"] --> A["첨부: 형식·용량·개수 검사"]
  A --> V{"필수 항목 · 이메일 형식 · 개인정보 동의"}
  V -- 어긋남 --> VE["토스트: 문의를 보내지 못했습니다"]
  V -- 통과 --> CONF["확인 창: 문의를 보낼까요?"]
  CONF --> SENT["접수 — 어드민 문의 목록에 Path /contact 로 쌓임"]
  SENT --> MY["문의 내역 /mypage/inquiries 에서 답변 확인"]
```

첨부는 **고른 순간** 걸러 낸다. 보내고 나서 막으면 적은 내용이 통째로 날아간다.

## 5. 쿠폰

```mermaid
flowchart LR
  BANNER["홈 쿠폰 띠"] --> BOX["쿠폰함 /mypage/coupons"]
  BOX --> TAB{"탭"}
  TAB -- 내 쿠폰 --> MINE["사용 가능 · 사용 완료 · 기간 만료"]
  TAB -- 쿠폰 받기 --> OPEN["받기 → 확인 창 → 내 쿠폰으로 이동"]
  MINE --> CHECKOUT["결제 화면에서 한 장 적용"]
```

## 6. 오류

```mermaid
flowchart LR
  ANY["아무 화면"] --> NF["없는 주소 → 404 (hero)"]
  ANY --> ERR["처리 중 예외 → 오류 (hero, 오류 번호 표시)"]
  ACTION["되돌릴 수 없는 동작"] --> FAIL["실패 /result?state=failed (center)"]
```

## 7. 안내가 뜨는 자리

| 종류 | 자리 | 쓰는 곳 |
|---|---|---|
| 토스트 | 화면 **하단 정중앙** | 성공·실패·정보. 무엇을 했는지 한 줄 덧붙인다 |
| 확인 창 | 화면 가운데, 뒤는 어둡게 | 삭제·주문·저장처럼 되돌리기 어려운 동작 앞 |
| 결과 화면 | 본문 가운데 | 흐름이 **끝난** 뒤 (주문·가입) |

토스트만으로 끝내지 않는 동작이 있다: 가입·결제는 결과 화면으로 옮긴다. 폼에 남으면 방금 한 일이
끝난 것인지 알 수 없다.

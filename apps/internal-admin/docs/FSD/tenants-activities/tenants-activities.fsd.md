- 상대 담당자 · 활동 내용 · 담당자 검색 → 결과가 화면에 바로 반영된다.
- 활동 유형 필터 → 결과가 화면에 바로 반영된다.
- 고객사 필터 → 결과가 화면에 바로 반영된다.
- 활동 항목 선택 시 상세 모달 표시 → 결과가 화면에 바로 반영된다.
- 활동 등록 → 결과가 화면에 바로 반영된다.

- **Given** 이 화면을 열었을 때 **When** 상대 담당자 · 활동 내용 · 담당자 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 활동 유형 필터 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 고객사 필터 **Then** 그 결과가 화면에 반영된다.

|---|---|---|

## 7. 검증 규칙

- 활동 내용과 상대 담당자는 공백만으로 저장할 수 없습니다.

### 화면 정책

- 타임라인이 아닌 목록 형태로 구성합니다. 후속 조치 유무에 따라 항목 높이가 달라지면 일자별 처리 건수를 확인하기 어렵습니다.
- 목록에는 활동 내용을 1행으로 표시하고 전문은 모달에서 제공합니다.
- 후속 조치가 등록된 항목은 목록에도 표시합니다. 모달에서만 확인 가능하면 미처리 건을 집계할 수 없습니다.
- 목록 항목을 선택하면 해당 값이 입력된 모달을 표시합니다. 주된 조회 대상이 후속 조치이며 확인 후 수정 또는 삭제가 필요한 항목입니다.
- 수정 모달에서 일시와 고객사는 변경할 수 없습니다. 발생 일시를 변경하면 기록 순서가 달라지며 파이프라인 건의 활동에는 고객사 코드가 없습니다.
- 고객사로 전환되지 않은 파이프라인 건의 활동은 링크 대신 표식을 표시합니다.
- 일시는 서버에서 결정한 기준일을 사용합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

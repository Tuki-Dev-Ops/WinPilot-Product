## 5. 사용자 시나리오

### 정상

- 고객사 선택 → 결과가 화면에 바로 반영된다.
- 플러그인 사용 설정 → 결과가 화면에 바로 반영된다.
- 연동 키 입력 → 결과가 화면에 바로 반영된다.
- 저장 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 고객사 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 플러그인 사용 설정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 연동 키 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 저장 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 사용 설정한 플러그인 중 연동 키가 필요한 항목의 키가 미입력이면 저장하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 연동 키가 필요한 플러그인은 사용 설정 시 연동 키가 필요합니다.

### 화면 정책

- 고객사 목록을 상단에 배치합니다. 선택 항목만으로는 고객사별 설정 상태를 확인할 수 없어 개별 조회가 필요했습니다.
- 한 번에 한 고객사만 설정합니다. 목록의 선택 표시는 현재 조회 대상이므로 전체 선택 기능을 제공하지 않습니다.
- 화면에 표시되지 않는 플러그인도 목록에서 제외하지 않습니다. 사용 설정 사실이 확인되지 않으면 전송 데이터를 파악할 수 없습니다.
- 플랜에서 제공하지 않는 플러그인은 최소 플랜을 함께 표시합니다.
- 연동 키가 필요 없는 플러그인에는 입력 항목을 표시하지 않습니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

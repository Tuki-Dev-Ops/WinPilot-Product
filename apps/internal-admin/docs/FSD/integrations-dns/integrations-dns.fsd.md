- 고객사 고르기 → 결과가 화면에 바로 반영된다.
- 인증서 만료일과 자동 갱신 상태 읽기 → 결과가 화면에 바로 반영된다.
- 갱신을 막고 있는 레코드로 바로 들어가기 → 결과가 화면에 바로 반영된다.
- 갈래별로 넣어야 할 레코드 읽기 → 결과가 화면에 바로 반영된다.
- 줄을 눌러 왜 넣는지와 빠지면 무슨 일이 생기는지 읽기 → 결과가 화면에 바로 반영된다.
- 넣을 레코드 켜고 끄기 → 결과가 화면에 바로 반영된다.

- 다시 확인 → 결과가 화면에 바로 반영된다.

## 7. 검증 규칙

- A 는 IPv4, AAAA 는 IPv6 모양이어야 한다.
- CNAME · MX 의 서버 이름은 도메인 모양이어야 한다.
- MX 는 우선순위와 서버 이름을 함께 적는다.
- CAA 는 플래그 · 태그 · 따옴표 안의 값 모양이어야 한다.
- SPF 는 v=spf1, DMARC 는 v=DMARC1 로 시작해야 한다.
- TTL 은 60초 이상 86400초 이하의 정수다.

### 화면 정책

- 고객사 목록이 먼저 선다 — 선택기 하나로는 어느 고객사가 막혀 있는지 알 수 없어, 고객사를 하나씩 골라 봐야 했다.
- 한 번에 한 고객사만 본다. 목록의 체크는 고르기가 아니라 지금 보고 있는 곳이라 전체 선택 단추를 두지 않는다.
- 저장은 고객사에 넘길 값을 정하는 것이고, 들어갔는지는 다시 확인이 읽는다. 그래서 저장한 줄은 확인됨이 아니라 확인 중이 된다.
- 없으면 사이트가 열리지 않는 줄은 끌 수 없게 잠근다 — 끌 수 있게 두면 꺼 놓고 왜 안 열리는지 찾는다.
- 종류는 창에서 바꾸지 못한다. A 를 CNAME 으로 바꾸는 것은 값을 고치는 일이 아니라 다른 레코드를 만드는 일이다.
- 값의 모양은 검사하되 그 값이 우리 배포를 가리키는지는 묻지 않는다 — 그것은 모양이 아니라 사실이고 다시 확인이 답한다.
- DNS 와 SSL 을 한 화면에 둔다 — 인증서는 DNS 로 발급받는다(`_acme-challenge` 위임과 CAA). 화면을 나누면 원인이 적힌 표를 보지 못한 채 돌아간다.
- 저장이 없고 다시 확인만 있다 — 등록은 고객사가 자기 도메인 관리 화면에서 한다.
- 레코드를 갈래로 묶는다. 갈래는 막혔을 때 벌어지는 일로 나눈다 — 사이트가 안 열리는 것과 메일이 스팸으로 가는 것은 급한 정도가 다르다.
- 루트 도메인에는 CNAME 을 두지 않고 A 를 적는다. CNAME 은 같은 이름의 다른 레코드와 함께 있을 수 없는데 루트에는 SOA·NS 가 반드시 있다(RFC 1034).
- 인증서 확인용 값은 직접 넣게 하지 않고 위임한다 — 갱신 때마다 고객사가 손댈 일이 없고, 고객사 DNS 키를 우리가 보관하지 않아도 된다.
- 반드시 넣어야 하는 것과 권장을 갈라 적는다. 안 넣어도 되는 줄을 붉게 보면 매번 놀란다.
- 이미 쓰는 메일이 있는 고객사에는 MX 를 넣지 말라고 적는다 — 넣는 순간 받던 메일이 끊긴다.
- DMARC 는 `p=none` 으로 시작한다. 처음부터 `reject` 로 두면 아직 등록 안 된 발신 서버의 메일이 그날로 전부 반송된다.
- 값을 줄이지 않고 자기 상자 안에서 가로로 흐르게 둔다. 잘리면 옮겨 적을 수 없다.
- 전파에 최대 48시간이 걸린다는 것과 바꾸기 전 TTL 을 낮추라는 것을 화면에 적는다 — 모르면 틀린 줄 알고 다시 넣는다.

## 8. 화면 상태

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

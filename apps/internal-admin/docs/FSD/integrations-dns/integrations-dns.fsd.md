## 5. 사용자 시나리오

### 정상

- 고객사 고르기 → 결과가 화면에 바로 반영된다.
- 넣어야 할 레코드 읽기 → 결과가 화면에 바로 반영된다.
- 값 복사해 넘기기 → 결과가 화면에 바로 반영된다.
- 다시 확인 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 고객사 고르기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 넣어야 할 레코드 읽기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 값 복사해 넘기기 **Then** 그 결과가 화면에 반영된다.

### 화면 정책

- 저장이 없고 다시 확인만 있다 — 등록은 고객사가 자기 도메인 관리 화면에서 한다.
- 값을 줄이지 않고 자기 상자 안에서 가로로 흐르게 둔다. 잘리면 옮겨 적을 수 없다.
- 전파에 최대 48시간이 걸린다는 것을 화면에 적는다 — 모르면 틀린 줄 알고 다시 넣는다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

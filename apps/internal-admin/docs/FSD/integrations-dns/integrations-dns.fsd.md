| 발생 조건 | 사용자 안내 | 화면 처리 |

| 필수 레코드가 미등록이거나 값이 일치하지 않으면 영향 범위를 하단에 표시합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- A 는 IPv4, AAAA 는 IPv6 형식이어야 합니다.
- CNAME 과 MX 의 서버명은 도메인 형식이어야 합니다.
- MX 는 우선순위와 서버명을 함께 입력합니다.
- CAA 는 플래그 · 태그 · 인용부호 내 값 형식이어야 합니다.
- SPF 는 v=spf1, DMARC 는 v=DMARC1 로 시작해야 합니다.
- TTL 은 60초 이상 86400초 이하의 정수입니다.

### 화면 정책

- 고객사 목록을 상단에 배치합니다. 선택 항목만으로는 설정이 누락된 고객사를 확인할 수 없어 개별 조회가 필요했습니다.
- 한 번에 한 고객사만 설정합니다. 목록의 선택 표시는 현재 조회 대상이므로 전체 선택 기능을 제공하지 않습니다.
- 저장은 고객사에 전달할 값을 확정하는 것이며 실제 적용 여부는 재확인 기능으로 조회합니다. 저장한 항목은 확인됨이 아니라 확인 중 상태가 됩니다.
- 미등록 시 사이트가 표시되지 않는 레코드는 사용 해제할 수 없도록 처리합니다.
- 레코드 유형은 모달에서 변경할 수 없습니다. A 를 CNAME 으로 변경하는 것은 값 수정이 아니라 다른 레코드를 등록하는 것입니다.
- 값의 형식은 검증하되 해당 값이 실제 배포를 가리키는지는 검증하지 않습니다. 재확인 기능에서 조회합니다.
- DNS 와 SSL 을 한 화면에서 제공합니다. 인증서는 DNS 로 발급되므로(`_acme-challenge` 위임과 CAA) 화면을 분리하면 원인을 확인할 수 없습니다.
- 레코드 등록은 고객사가 도메인 관리 화면에서 수행하므로 본 화면에서는 재확인만 제공합니다.
- 레코드를 분류로 구분합니다. 미등록 시 발생하는 영향을 기준으로 구분하며, 사이트 미표시와 메일 스팸 분류는 긴급도가 다릅니다.
- 루트 도메인에는 CNAME 이 아닌 A 를 등록합니다. CNAME 은 동일 이름의 다른 레코드와 공존할 수 없으나 루트에는 SOA 와 NS 가 필수입니다(RFC 1034).
- 인증서 확인용 값은 직접 입력하지 않고 위임 방식을 사용합니다. 갱신 시마다 고객사가 조작할 필요가 없으며 고객사 DNS 키를 보관하지 않습니다.
- 필수 항목과 권장 항목을 구분하여 표시합니다.
- 기존 메일 서비스를 사용하는 고객사에는 MX 를 등록하지 않도록 안내합니다. 등록 시 기존 메일 수신이 중단됩니다.
- DMARC 는 `p=none` 으로 시작합니다. `reject` 로 설정하면 미등록 발신 서버의 메일이 전량 반송됩니다.
- 값은 축약하지 않고 해당 영역 내에서 가로 스크롤로 표시합니다. 절삭되면 값을 복사할 수 없습니다.
- 전파에 최대 48시간이 소요된다는 점과 변경 전 TTL 을 낮춰야 한다는 점을 화면에 표시합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |

| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

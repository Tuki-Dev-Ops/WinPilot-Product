## 5. 사용자 시나리오

### 정상

- 기준 값 목록명 · 값 · 사용 화면 검색 → 결과가 화면에 바로 반영된다.
- 값 추가 → 결과가 화면에 바로 반영된다.
- 값 삭제 → 결과가 화면에 바로 반영된다.
- 기준 값 목록 등록 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 기준 값 목록명 · 값 · 사용 화면 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 값 추가 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 값 삭제 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 기준 값 목록 등록 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 값이 미입력이면 추가하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 이미 등록된 값이면 추가하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 고정 목록은 값을 추가하거나 삭제할 수 없습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 목록명이나 최초 값이 미입력이면 등록하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 값은 동일 목록 내에서 중복될 수 없습니다.
- 목록명은 전체에서 중복될 수 없습니다.

### 화면 정책

- 목록별로 사용 화면을 표시합니다. 값 변경 시 영향 범위를 확인할 수 있어야 합니다.
- 고정 목록은 고정 사유를 함께 표시합니다. 사유를 표시하지 않으면 오류로 인식됩니다.
- 신규 목록은 수정 가능 상태로 생성합니다. 고정은 화면이 값별로 다르게 동작하는 경우에만 적용합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 값 순서 변경
- 값 사용처 역추적

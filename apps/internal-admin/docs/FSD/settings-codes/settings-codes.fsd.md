## 4. 버튼 및 이벤트

| 버튼 | 눌렀을 때 | 성공 | 실패 |
|---|---|---|---|
| 기준 값 목록 등록 | 등록 모달을 연다 | 잠기지 않은 목록이 생긴다 | 무엇이 비었는지 토스트로 알리고 모달을 닫지 않는다 |
| 더하기 | 입력한 값을 그 목록에 더한다 | 값이 늘고 토스트로 몇 개 화면에 반영되는지 알린다 | 비었거나 이미 있는 값이라고 알린다 |
| 지우기 | 더하려던 입력만 비운다 | — | — |

## 5. 사용자 시나리오

### 정상

- 목록 이름·값·쓰는 화면으로 검색 → 결과가 화면에 바로 반영된다.
- 값 더하기 → 결과가 화면에 바로 반영된다.
- 값 빼기 → 결과가 화면에 바로 반영된다.
- 기준 값 목록 등록 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 목록 이름·값·쓰는 화면으로 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 값 더하기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 값 빼기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 기준 값 목록 등록 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 값이 비면 더하지 않는다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 이미 있는 값이면 더하지 않는다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 잠긴 목록은 값을 늘리거나 빼지 못한다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 목록 이름이나 첫 값이 비면 등록하지 않는다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 값은 같은 목록 안에서 겹치지 않는다.
- 목록 이름은 전체에서 겹치지 않는다.

### 화면 정책

- 목록마다 어느 화면이 읽는지 적는다 — 값 하나를 고칠 때 무엇이 달라지는지 모르면 아무도 고치지 못한다.
- 잠긴 목록은 왜 잠겼는지도 적는다. 이유를 적지 않으면 버그로 읽힌다.
- 새 목록은 잠기지 않은 채로 만든다. 잠금은 화면이 값마다 다르게 그릴 때만 붙는다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 값 순서 바꾸기
- 값을 쓰는 곳 역추적

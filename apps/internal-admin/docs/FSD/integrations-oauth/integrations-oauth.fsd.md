## 5. 사용자 시나리오

### 정상

- 고객사 고르기 → 결과가 화면에 바로 반영된다.
- 제공자 켜고 끄기 → 결과가 화면에 바로 반영된다.
- Client ID·Secret 넣기 → 결과가 화면에 바로 반영된다.
- 리다이렉트 주소 확인 → 결과가 화면에 바로 반영된다.
- 저장 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 고객사 고르기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 제공자 켜고 끄기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** Client ID·Secret 넣기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 리다이렉트 주소 확인 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 저장 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 켜 둔 제공자에 키가 비어 있으면 저장하지 않는다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 켜 둔 제공자는 Client ID 와 Secret 이 모두 있어야 한다.

### 화면 정책

- 리다이렉트 주소를 손으로 적게 하지 않는다 — 오타의 원인이 화면 어디에도 드러나지 않는다.
- 고객사를 바꾸면 그 고객사의 값으로 다시 시작한다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

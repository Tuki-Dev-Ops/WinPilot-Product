## 5. 사용자 시나리오

### 정상

- 고객사 선택 → 결과가 화면에 바로 반영된다.
- 제공자 사용 설정 → 결과가 화면에 바로 반영된다.
- 제공자별 인증 정보 입력 → 결과가 화면에 바로 반영된다.
- 리다이렉트 URL 조회 → 결과가 화면에 바로 반영된다.
- 제공자별 저장 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 고객사 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 제공자 사용 설정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 제공자별 인증 정보 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 리다이렉트 URL 조회 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 제공자별 저장 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 사용 설정한 제공자의 필수 항목이 미입력이면 저장하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 입력이 완료되지 않은 제공자를 사용 설정하면 입력 모달을 표시합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 사용 설정한 제공자는 필수 항목이 모두 입력되어야 합니다.
- 단일 행 항목에는 공백과 줄바꿈을 포함할 수 없습니다.
- 애플 개인 키는 -----BEGIN PRIVATE KEY----- 로 시작해야 합니다.

### 화면 정책

- 리다이렉트 URL 을 직접 입력받지 않습니다. 입력 오류의 원인이 화면에서 확인되지 않습니다.
- 고객사 목록을 상단에 배치합니다. 선택 항목만으로는 설정이 누락된 고객사를 확인할 수 없어 개별 조회가 필요했습니다.
- 한 번에 한 고객사만 설정합니다. 목록의 선택 표시는 현재 조회 대상이므로 전체 선택 기능을 제공하지 않습니다.
- 고객사를 변경하면 해당 고객사의 값으로 초기화합니다.
- 제공자 4개의 입력 항목을 한 화면에 배치하지 않습니다. 애플은 항목이 4개이므로 전체 12개 이상이 되어 특정 제공자만 확인하려는 경우에도 전체를 확인해야 합니다.
- 저장을 제공자별로 처리합니다. 통합 저장 시 일부 제공자의 인증 정보가 미확보 상태이면 다른 제공자도 저장할 수 없습니다.
- 사용 설정했으나 입력이 완료되지 않은 상태를 목록에 별도로 표시합니다. 사용 중으로만 표시되면 설정 누락을 확인할 수 없습니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

## 5. 사용자 시나리오

### 정상

- 제목 · 내용 · 발신자 · 번호 검색 → 결과가 화면에 바로 반영된다.
- 처리 상태 필터 → 결과가 화면에 바로 반영된다.
- 고객사 필터 → 결과가 화면에 바로 반영된다.
- 문의 항목 선택 시 답변 모달 표시 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 제목 · 내용 · 발신자 · 번호 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 처리 상태 필터 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 고객사 필터 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 문의 항목 선택 시 답변 모달 표시 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 검색 조건에 해당하는 항목이 없으면 목록 영역에 데이터 없음 사유를 표시합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 답변완료 또는 처리중으로 변경하려면 답변 내용이 필요합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 답변완료로 변경하려면 답변 내용이 필요합니다.
- 답변 내용은 1000자를 초과할 수 없습니다.

### 화면 정책

- 등록 기능을 제공하지 않습니다. 문의는 고객사에서 접수하는 데이터입니다.
- 긴급도를 1차 기준으로, 동일한 경우 접수일을 2차 기준으로 정렬합니다.
- 기본 탭은 전체가 아닌 미답변입니다. 본 목록의 주된 조회 목적이기 때문입니다.
- 처리 상태 명칭은 B2C Admin 의 문의와 동일하게 표기합니다. 장애 상황에서 동일한 용어를 사용해야 합니다.
- 목록 항목을 선택하면 모달을 표시합니다. 목록 하단 펼침 방식은 조회만 가능하여 답변 작성 시 화면을 이동해야 했습니다.
- 문의 1건의 관리 항목이 5개(제목 · 내용 · 답변 · 상태 · 담당자)이므로 별도 화면이 아닌 모달로 구성합니다.
- 답변 내용 없이 답변완료로 변경할 수 없습니다. 목록에서는 처리 완료로 표시되지만 고객사는 답변을 수신하지 못합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

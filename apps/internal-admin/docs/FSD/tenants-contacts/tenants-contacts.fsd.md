## 5. 사용자 시나리오

### 정상

- 성명 · 직함 · 이메일 · 고객사 검색 → 결과가 화면에 바로 반영된다.
- 역할 필터 → 결과가 화면에 바로 반영된다.
- 담당자 등록 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 성명 · 직함 · 이메일 · 고객사 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 역할 필터 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 담당자 등록 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

- 성명과 직함은 공백만으로 저장할 수 없습니다.
- 이메일 형식이 아니면 저장하지 않습니다.

### 화면 정책

- 고객사 데이터의 담당자 항목과 별도로 관리합니다. 결제 담당자와 기술 담당자가 다르기 때문입니다.
- 대표 담당자는 고객사별 1명입니다. 신규 담당자를 대표로 지정하지 않는 것은 복수 지정 시 연락 대상을 다시 판단해야 하기 때문입니다.
- 목록에서는 연락처 중간 자리를 마스킹합니다. 상세는 사내 전용이므로 전체를 표시합니다.
- 총괄 — 계약과 플랜을 결정하는 담당자. 연장 및 해지를 협의합니다.
- 결제 — 청구서 수신과 세금계산서를 처리하는 담당자. 연체 안내 대상입니다.
- 기술 — 도메인 · 연동 · 장애를 담당합니다. DNS 값 전달 대상입니다.
- 운영 — 관리자 콘솔을 사용하는 담당자. 기능 문의가 접수됩니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 대표 담당자 변경

## 5. 사용자 시나리오

### 정상

- 고객사 선택 → 결과가 화면에 바로 반영된다.
- 결제 대행사 선택 → 결과가 화면에 바로 반영된다.
- 대행사별 인증 정보 입력 → 결과가 화면에 바로 반영된다.
- 결제 수단 선택 → 결과가 화면에 바로 반영된다.
- 운영 모드 선택 → 결과가 화면에 바로 반영된다.
- 저장 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 고객사 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 결제 대행사 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 대행사별 인증 정보 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 결제 수단 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 운영 모드 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 저장 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 상점 ID 또는 비밀 키가 미입력이면 저장하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 결제 수단을 하나도 선택하지 않으면 저장하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 실결제 모드를 선택하면 해당 위치에 경고를 표시합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 상점 ID 와 비밀 키는 공백만으로 저장할 수 없습니다.
- 결제 수단은 1개 이상 선택해야 합니다.

### 화면 정책

- 고객사 목록을 상단에 배치합니다. 선택 항목만으로는 설정이 누락된 고객사를 확인할 수 없어 개별 조회가 필요했습니다.
- 한 번에 한 고객사만 설정합니다. 목록의 선택 표시는 현재 조회 대상이므로 전체 선택 기능을 제공하지 않습니다.
- 고객사를 변경하면 해당 고객사의 값으로 초기화합니다. 이전 고객사의 인증 정보가 유지되면 오설정이 발생합니다.
- 실결제 전환은 복구가 어렵습니다. 선택 시 해당 위치에 경고를 표시합니다.
- 정기결제 설정 항목은 추가 인증 정보를 요구하는 대행사에서만 표시합니다. 다른 대행사에서는 활성화해도 화면 변화가 없어 설정 결과를 확인할 수 없습니다.
- 대행사를 변경하면 이전 대행사의 인증 정보와 정기결제 설정을 함께 초기화합니다. 화면에 표시되지 않는 값이 검증에만 적용되면 실패 사유를 확인할 수 없습니다.
- URL 은 `/integrations/pg` 이며 코드 식별자는 `payment` 입니다. `pg` 는 용어 정의에서 사용을 제한합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 대행사별 수수료 안내
- 테스트 결제 실행

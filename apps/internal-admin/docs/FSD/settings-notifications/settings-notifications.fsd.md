## 5. 사용자 시나리오

### 정상

- 알림 규칙 사용 설정 → 결과가 화면에 바로 반영된다.
- 발송 시점 수정 → 결과가 화면에 바로 반영된다.
- 발송 채널 선택 → 결과가 화면에 바로 반영된다.
- 수신 대상 선택 → 결과가 화면에 바로 반영된다.
- 저장 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 알림 규칙 사용 설정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 발송 시점 수정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 발송 채널 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 수신 대상 선택 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 저장 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 사용 설정한 규칙의 발송 시점이 숫자가 아니면 저장하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 발송 시점은 숫자만 입력할 수 있습니다.

### 화면 정책

- 규칙별로 알림이 발생하는 화면을 함께 표시합니다. 알림 오류 발생 시 확인 대상을 파악할 수 있어야 합니다.
- 규칙을 삭제하지 않고 사용 해제합니다. 삭제 시 해당 알림의 존재 자체가 확인되지 않습니다.
- 「발송 안 함」을 발송 채널의 항목으로 제공합니다. 일시 중지와 삭제는 다른 처리입니다.
- 푸시 알림은 현재 제공하지 않습니다. 서버 연동이 필요한 기능입니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 규칙별 발송 이력
- 수신자별 규칙 선택

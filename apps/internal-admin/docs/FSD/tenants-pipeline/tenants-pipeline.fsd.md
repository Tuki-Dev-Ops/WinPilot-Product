## 5. 사용자 시나리오

### 정상

- 건명 · 건 번호 · 플랜 검색 → 결과가 화면에 바로 반영된다.
- 담당자 필터 → 결과가 화면에 바로 반영된다.
- 진행 단계 변경 → 결과가 화면에 바로 반영된다.
- 파이프라인 건 등록 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 건명 · 건 번호 · 플랜 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 담당자 필터 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 진행 단계 변경 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 파이프라인 건 등록 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 문의 이전 단계와 운영 이후 단계로는 이동할 수 없습니다. 해당 버튼을 비활성화합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 건명이나 예상 금액이 미입력이면 등록하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 건명은 공백만으로 저장할 수 없습니다.
- 예상 금액은 숫자만 입력할 수 있습니다.

### 화면 정책

- 드래그 방식의 단계 변경을 제공하지 않습니다. 실행 취소가 없으면 오조작을 복구할 수 없습니다. 단계 변경은 항목의 버튼으로 처리하며 이전 · 다음 두 방향을 함께 제공합니다.
- 단계 변경에 이전 · 다음 두 방향을 함께 제공합니다. 단방향만 제공하면 오조작을 수정할 수 없습니다.
- 운영 단계의 항목이 고객사 목록이 됩니다. 동일한 데이터를 목록과 단계별 열로 각각 제공합니다.
- 신규 항목은 문의 단계에서 시작합니다. 중간 단계에서 등록하면 유입 경로가 기록되지 않습니다.
- 항목이 없는 단계 열도 표시합니다. 열이 제거되면 해당 단계가 없는 것으로 인식됩니다.
- 항목을 선택하면 조회 모달을 표시합니다. 항목 카드에 포함하지 않은 메모가 진행 지연 사유를 설명하며, 카드에 포함하면 항목별 높이가 달라져 단계별 건수를 확인하기 어렵습니다.
- 상태 탭을 제공하지 않습니다. 진행 단계가 이미 열로 구성되어 있어 중복되며, 탭 선택 시 단일 열만 표시되어 단계 간 흐름이 확인되지 않습니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 단계별 체류 기간
- 분기 예상 매출

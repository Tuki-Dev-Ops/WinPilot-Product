## 5. 사용자 시나리오

### 정상

- 성명 · 계정 · 소속 검색 → 결과가 화면에 바로 반영된다.
- 직급 필터 → 결과가 화면에 바로 반영된다.
- 관리자 등록 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 성명 · 계정 · 소속 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 직급 필터 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 관리자 등록 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 성명이나 소속이 미입력이면 등록하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 이메일 형식이 아니면 등록하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 이미 등록된 계정이면 등록하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 성명과 소속은 공백만으로 저장할 수 없습니다.
- 이메일 형식이 아니면 저장하지 않습니다.
- 동일한 계정을 중복 등록할 수 없습니다.

### 화면 정책

- 관리자 — 전체 고객사를 관리합니다. 실결제 전환 · 플랜 변경 등 복구가 어려운 작업을 수행할 수 있습니다.
- 담당 — 담당 고객사만 관리합니다. 연동 값을 수정할 수 있으나 실결제 전환은 수행할 수 없습니다.
- 조회 — 조회만 가능합니다. 저장 기능을 제공하지 않습니다.
- 신규 계정은 조회 직급으로 시작합니다. 등록 시점부터 복구가 어려운 권한을 부여하지 않습니다.
- 중지한 계정을 삭제하지 않습니다. 기존 이력에 해당 계정명이 기록되어 있습니다.
- 목록 항목을 선택하면 해당 값이 입력된 모달을 표시합니다. 담당 고객사와 중지 여부는 모달에서 변경하지 않습니다. 다른 화면의 기록과 연결된 항목입니다.
- 수정 시 본인 계정은 중복 검사 대상에서 제외합니다. 이메일을 유지한 채 성명만 수정할 수 있어야 합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

- 2단계 인증

## 5. 사용자 시나리오

### 정상

- 처리 결과 조회 → 결과가 화면에 바로 반영된다.
- 처리 번호 조회 → 결과가 화면에 바로 반영된다.
- 이동 경로 선택 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 처리 결과 조회 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 처리 번호 조회 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 이동 경로 선택 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

_N/A — 이 화면에는 해당되지 않습니다._

### 화면 정책

- 성공과 실패를 단일 화면으로 처리합니다. 문구만 다르고 구조가 동일하므로 화면을 분리하면 불일치가 발생합니다.
- 404 및 오류 화면과 동일한 `StatusScreen` 컴포넌트를 사용합니다. 3개 앱이 공통 컴포넌트를 사용합니다.
- 메뉴에 포함되지 않는 화면이므로 사이드바에서 활성화되는 항목이 없습니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

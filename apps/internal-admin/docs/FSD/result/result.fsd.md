## 5. 사용자 시나리오

### 정상

- 결과 읽기 → 결과가 화면에 바로 반영된다.
- 처리 번호 확인 → 결과가 화면에 바로 반영된다.
- 돌아갈 곳 고르기 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 결과 읽기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 처리 번호 확인 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 돌아갈 곳 고르기 **Then** 그 결과가 화면에 반영된다.

### 화면 정책

- 완료·실패가 한 화면이다 — 문구만 다르고 구조가 같아서, 나누면 한쪽만 고쳐 두 화면이 어긋난다.
- 404·오류와 같은 `StatusScreen` 을 쓴다. 세 앱이 같은 컴포넌트다.
- 메뉴에 없는 화면이라 사이드바에서 켜지는 항목이 없다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

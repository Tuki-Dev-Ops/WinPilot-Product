## 5. 사용자 시나리오

### 정상

- 고객사명 · 담당자 · 도메인 검색 → 결과가 화면에 바로 반영된다.
- 플랜 필터 → 결과가 화면에 바로 반영된다.
- 목록 항목 선택 시 상세 페이지로 이동 → 결과가 화면에 바로 반영된다.
- 해당 고객사의 연동 설정으로 이동 → 결과가 화면에 바로 반영된다.
- 고객사 등록 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 고객사명 · 담당자 · 도메인 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 플랜 필터 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 목록 항목 선택 시 상세 페이지로 이동 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 해당 고객사의 연동 설정으로 이동 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 고객사 등록 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 고객사명과 담당자가 미입력이면 등록하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 유지보수 종료일이 날짜 형식이 아니면 등록하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 고객사명과 담당자는 공백만으로 저장할 수 없습니다.
- 유지보수 종료일은 `YYYY-MM-DD` 형식이어야 합니다.

### 화면 정책

- 계약이 만료되었거나 만료 임박한 고객사를 목록 최상단에 배치합니다.
- 탭을 플랜이 아닌 유지보수 상태로 구성합니다. 본 목록의 주된 조회 목적이기 때문이며 플랜은 필터로 제공합니다.
- 배포가 연결되지 않은 항목은 오류가 아니라 미연결 상태입니다. 빈 값이 아니라 미연결로 표시합니다.
- 등록은 목록 화면의 모달에서 처리합니다. 계약 시점 입력 항목이 4개이기 때문입니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

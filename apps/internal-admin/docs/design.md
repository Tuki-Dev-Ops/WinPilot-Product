# 디자인 시스템 — Internal Admin

> 값의 원본: `@winpilot/tokens` · 이 앱은 색·글자·간격을 직접 선언하지 않는다.
> 훑는 곳: `app/globals.css` 의 `@source` 두 줄 (`packages/ui/src` · `packages/docs/src`)

## 1. 값을 앱이 소유하지 않는 이유

색 하나를 앱에 직접 적는 순간 디자인 시스템이 두 벌이 된다. 두 벌은 한 번에 고쳐지지 않고,
어느 쪽이 맞는지도 알 수 없다. 그래서 이 앱의 `globals.css` 가 하는 일은 셋뿐이다 —
Tailwind 를 들이고, 토큰을 들이고, 워크스페이스 패키지를 훑게 한다.

`@source` 두 줄이 필요한 이유: Tailwind v4 는 프로젝트를 자동으로 훑지만 `node_modules` 는
뺀다. 워크스페이스 패키지는 심링크로 그 안에 들어가 있어, 그대로 두면 **거기서만 쓰이는
클래스가 CSS 에 만들어지지 않는다.**

## 2. B2C Admin 과 다른 것은 값이 아니라 구분 표시다

세 콘솔이 같은 토큰을 쓴다. 두 어드민을 동시에 띄워 두고 일하다 어느 쪽인지 헷갈리면
고객사 설정을 잘못 건드리므로, **어느 콘솔인지 알리는 것**만 다르게 둔다.

| 자리 | B2C Admin | Internal Admin |
|---|---|---|
| 로고 칩 | 브랜드색 | **먹색**(`bg-ink`) |
| 워드마크 | `Admin` | **`Internal`** |
| 사이드바 머리 | 없음 | **사내 전용 · 고객사 설정을 다룹니다** 한 줄 |
| 헤더 오른쪽 | 로그아웃 | 계정 이메일만 (로그인 화면이 없다) |

색 하나로 먼저 알리고, 글자로 한 번 더 알린다. 색만으로 알리면 색각 이상 사용자에게는
두 콘솔이 같아 보인다.

## 3. 뼈대

| 자리 | 값 | 왜 |
|---|---|---|
| 사이드바 너비 | `w-56` | 최상위 메뉴만 담으므로 더 넓힐 이유가 없다 |
| 보조 메뉴 너비 | `lg:w-44` | 세부 이름이 짧다 |
| 본문 좌우 여백 | `px-6` · `lg:px-8` | B2C Admin 과 같다 |
| 본문 세로 여백 | `py-8` | |
| 덩어리 사이 | `gap-8` | 카드가 여럿인 화면에서 무엇이 한 묶음인지 갈리는 최소 간격 |
| 사이드바가 접히는 폭 | `lg` (1024px) | 그보다 좁으면 사이드바와 본문이 함께 서지 못한다 |

## 4. 컨트롤 높이

| 컨트롤 | 높이 | 쓰는 자리 |
|---|---|---|
| 목록 툴바(검색·필터 칩·등록) | `h-9` | 목록 위 한 줄 |
| 폼 입력 · 저장 단추 | `h-11` | 등록 모달, 연동 폼 |
| 행 안의 작은 단추 | `h-8` | 목록 행의 상세·연동, 파이프라인 단계 이동 |

목록의 컨트롤을 폼보다 낮게 두는 이유: 목록은 한 화면에 많은 줄이 서는 곳이라 컨트롤이
높으면 볼 수 있는 줄 수가 줄어든다. 폼은 한 번에 하나를 다루므로 누르기 쉬운 편이 낫다.

## 5. 상태 뱃지

| 뜻 | 배경 | 글자 | 쓰는 자리 |
|---|---|---|---|
| 좋음 · 끝남 | `bg-signal-ok/12` | `text-signal-ok` | 운영중 · 확인됨 · 답변완료 · 판매 중 |
| 진행 중 · 강조 | `bg-brand-50` | `text-brand-700` | 접수 · 처리중 · 확인 중 · 상담·계약·구축 |
| 중립 | `bg-surface` | `text-ink-muted` | 준비중 · 보류 · 판매 종료 · 조회 |
| 나쁨 · 막힘 | `bg-signal-danger/12` | `text-signal-danger` | 중지 · 불일치 · 만료 · 연체 |

모양은 `rounded-full px-2.5 py-1 text-xs font-medium` 한 벌이다.

**색만으로 상태를 알리지 않는다.** 뱃지 안에 언제나 글자가 들어가고, 색이 뜻을 더할 뿐이다.
색을 지워도 상태가 구분되는지가 이 규칙을 지켰는지 보는 기준이다.

## 6. 표와 목록

- 열은 `lg:grid-cols-12` 한 벌로 나눈다. 화면마다 열 폭이 다르면 옆 화면으로 옮겨 갈 때
  눈이 다시 자리를 잡는다.
- **`lg` 미만에서는 표 머리줄을 숨기고 각 행이 자기 라벨을 갖는다.** 좁은 폭에 열 이름을
  그대로 두면 글자가 겹쳐 어느 값이 어느 열인지 오히려 알 수 없다.
- 숫자는 `tabular-nums` 로 고정폭이다. 자릿수가 흔들리면 표에서 크기를 비교할 수 없다.
- 코드·도메인·시각은 `font-mono` 다. 옮겨 적는 값이라 글자가 헷갈리면 안 된다.
- 넓은 표와 파이프라인 칸은 **자기 상자 안에서만** 가로로 스크롤한다. 페이지 전체가 밀리면
  사이드바까지 따라 움직인다.

## 7. 값을 직접 적지 않는 자리와 예외

인라인 `style` · raw hex · raw px 를 쓰지 않는다. **예외는 값이 계산되는 자리 하나**다 —
막대 길이(`width: ${share}%`)와 SVG 좌표는 클래스로 만들 수 없다. 그 밖의 색·간격은 전부
토큰에서 온다.

차트를 라이브러리로 그리지 않는 이유도 같은 결이다. 대부분 캔버스로 그려서 추출기에 상자
하나로만 잡히고, 색도 라이브러리가 자기 팔레트로 정한다.

## 8. 도면

`/docs/ia` 와 `/docs/flow-chart` 의 mermaid 는 세 앱이 같은 규칙을 쓴다.

- 선은 **직각(step)**. 곡선으로 두면 갈래가 많아질수록 어느 선이 어디로 가는지 못 따라간다.
- **실선은 정상, 점선은 예외.** 눈으로 한 번에 갈려야 정상 경로만 훑는 읽기가 된다.
- **마름모는 갈림길**, **원통은 값이 오는 곳.**
- 도면은 카드 폭에 맞춰 줄이지 않는다. 줄인 도면은 글자가 뭉개져 아무것도 읽히지 않는다.

## 9. 아직 정하지 않은 것

- **다크 모드 확인** — 토큰에 어두운 값이 있고 뱃지도 `dark:` 를 함께 적었지만, 이 콘솔의
  화면을 어두운 배경에서 훑어본 적은 아직 없다.
- **인쇄** — 청구·연체 목록을 종이로 뽑는 자리가 생기면 그때 정한다.
- **모션** — 지금 쓰는 것은 색 전환(`transition-colors`)뿐이다. 화면이 움직이는 자리가
  없어서 모션 감소를 켠 사용자에게 멈출 것도 없다.

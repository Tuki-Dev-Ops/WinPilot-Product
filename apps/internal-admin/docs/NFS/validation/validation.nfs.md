# 입력 검증

> Internal Admin · 생성: `pnpm docs:build` · 원본: `tools/docs/nfs.ts`

## 목적

무엇이 왜 틀렸는지 그 자리에서 알려야 고칠 수 있다.

## 적용 범위

값을 넣는 모든 화면.

## 정책

- 검증은 **낸 뒤가 아니라 그 자리에서** 한다. 다 적고 나서 처음으로 돌아가게 하지 않는다.
- 틀린 곳으로 포커스를 옮기고, 무엇이 틀렸는지 그 입력 바로 아래 적는다.
- 값을 지우지 않는다 — 틀렸다고 비우면 다시 적어야 한다.

## 세부 기준

| 종류 | 기준 | 문구 |
|---|---|---|
| 필수 | 빈 값·공백만 불가 | `○○을(를) 입력해 주세요.` |
| 길이 | 항목별 최소·최대 | `○자 이상 입력해 주세요.` |
| 숫자 | 숫자만, 앞의 0 제거 | `숫자만 입력해 주세요.` |
| 금액 | 0 이상 정수 | `0 이상의 숫자만 입력해 주세요.` |
| 이메일 | `아이디@도메인` 모양 | `이메일 형식이 올바르지 않습니다.` |
| 전화 | 숫자·하이픈 | `연락처 형식이 올바르지 않습니다.` |
| 날짜 | `YYYY-MM-DD` | `날짜 형식이 올바르지 않습니다.` |

## 예외

- 목록의 검색·필터는 틀린 값을 오류로 보지 않고 **조건이 없는 것으로** 본다 — 목록을 비우지 않는다.

## 점검 항목

- [ ] 틀린 입력으로 포커스가 간다
- [ ] 입력값이 지워지지 않는다
- [ ] 같은 종류의 오류 문구가 화면마다 같다

# 6. 디자인 시스템

> SSOT: `packages/tokens/theme.css` 의 `@theme static` 블록
> 생성물: `artifacts/tokens/tokens.json` (DTCG) — `pnpm ssot:tokens`
> 관련: `docs/architecture/design-sync-ssot.md` §L0

## 6.1 원칙

1. **토큰이 아니면 쓸 수 없다.** raw hex·raw px 는 금지. Tailwind 유틸리티를 통해서만 접근한다.
2. **값의 진실은 브라우저에 있다.** 토큰 파일은 설정 파서가 아니라
   실행 중인 앱의 `getComputedStyle(:root)` 에서 추출된다.
3. **사이트와 콘솔은 같은 토큰을 쓴다.** 둘의 차이는 *토큰 값*이 아니라
   *어떤 토큰을 어디에 쓰는가* 로만 표현한다. 콘솔 전용 팔레트를 만들지 않는다.
4. **앱은 색을 선언하지 않는다.** `app/globals.css` 는 Tailwind 와
   `@winpilot/tokens/theme.css` 를 들이고, 자동 훑기에 걸리지 않는 `packages/ui/src` 를
   `@source` 로 지목하는 것이 전부다. 외식 브랜드라고 해서 여기에 브랜드색을 따로 풀지 않는다 —
   푸는 순간 `brand-500` 이 앱마다 다른 색이 되고, 공유 컴포넌트(`@winpilot/ui`)가 어느 색으로
   그려질지 아무도 모르게 된다.

## 6.2 색

### 시맨틱 토큰 (역할 기반 — 우선 사용)

| 토큰 | Light | Dark | 용도 |
|---|---|---|---|

| `surface-raised` | `#ffffff` | `#151822` | 카드·리스트 행 |
| `border` | `#e3e5eb` | `#21252f` | 기본 구분선 |
| `border-strong` | `#cbcfd9` | `#333846` | 강조 테두리·점선 |
| `ink` | `#333d4b` | `#f1f3f7` | 본문 |
| `ink-muted` | `#8b95a1` | `#98a0af` | 보조 텍스트 |
| `ink-faint` | `#b0b8c1` | `#6b7684` | 메타·라벨 |
| `night` | `#05060d` | `#05060d` | **모드를 따라가지 않는다** — 푸터와 첫 화면의 어두운 판 |

사용: `bg-canvas`, `text-ink-muted`, `border-border`

`night` 만 모드에 따라 바뀌지 않는 것은, 그 자리가 **밝은 모드에서도 어두워야 하는 판**이기
때문이다. 푸터와 첫 화면이 그렇다 — 시맨틱 토큰으로 두면 밝은 모드에서 흰 판이 되어 화면
전체가 한 덩어리로 붙는다.

### 팔레트 토큰 (모드 무관)

이 제품의 브랜드 스케일은 **`octo-*`** 다. `brand-*`(파랑)는 IR 템플릿의 것이고, 한 토큰 파일
안에서 두 스케일이 나란히 산다 — 파랑을 고치면 IR 사이트가 통째로 색이 바뀐다. **브랜드가
둘이면 스케일도 둘이다.**

| 토큰 | 값 | | 토큰 | 값 |
|---|---|---|---|---|
| `octo-50` | `#fdf3f6` | | `octo-500` | `#c03a68` |
| `octo-100` | `#fbe3ea` | | `octo-600` | `#a52d56` |
| `octo-200` | `#f5c2d2` | | `octo-700` | `#8a2547` |
| `octo-300` | `#ea94b0` | | `octo-800` | `#6b1d38` |
| `octo-400` | `#d95f88` | | `octo-900` | `#4a1427` |

**삶은 문어 껍질의 색**이다. 이 브랜드가 파는 것이 통문어 한 마리라 색이 곧 재료다. 한때 국밥
브랜드였고 그때는 적갈(뚝배기 색)이었는데, 이름이 바뀌면서 함께 옮겼다 — 색만 남겨 두면
**간판과 화면이 다른 집처럼** 보인다. 순수한 빨강을 쓰지 않는 것은 경고색과 구분되지 않고,
화면 전체에 깔면 급해 보이기 때문이다. 자주를 섞으면 붉되 차분해진다.

**500 이 단추, 600 이 호버, 700 이 글자.** 셋 다 흰 바탕·흰 글씨에서 본문 기준(4.5:1)을
넘긴다 — 흰 바탕 대비로 **500 은 5.19:1, 600 은 6.75:1, 700 은 8.4:1** 이다. 단계를 눈대중으로
고르지 않는 근거가 이 숫자이고, 토큰 파일 주석에 그대로 적혀 있다.

`octo-50` 은 **아주 옅은 분홍**으로 쓴다. 칸을 번갈아 깔 때 회색(`surface`)보다 이쪽이 이
브랜드에 맞고, 흰 바탕과 나란히 놓아도 회색처럼 그늘져 보이지 않는다 — 홈의 메뉴 구획과
`PhotoSlot` 의 바탕이 그 자리다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `signal-ok` | `#17915c` | 완료·성공 |
| `signal-wait` | `#9a7b12` | 진행중·주의 |
| `signal-danger` | `#d92d20` | 검증 오류. 흰 배경 대비 4.83:1 |

**시맨틱이 있으면 시맨틱을 쓴다.** `bg-white` 대신 `bg-surface-raised` —
전자는 다크 모드에서 깨지고, 후자는 자동으로 따라간다.

### 브랜드 색의 모드 대응

`octo-*` 는 모드에 따라 값이 바뀌지 않는다. 다크 모드에서 대비가 부족하면
**값을 바꾸지 말고 단계를 바꾼다** (`text-octo-700` → `dark:text-octo-300`).
값을 모드별로 나누면 팔레트가 두 벌이 되어 Figma Variables 매핑이 복잡해진다.

어두운 판 위에서는 단계를 바꾸는 것도 화면이 정한다 — 홈의 구획 라벨이
`onDark ? 'text-octo-300' : 'text-octo-700'` 로 갈리는 것이 그 예다. 같은 역할의 글자가 판의
밝기에 따라 두 단계를 쓰는 것이지, 두 색을 쓰는 것이 아니다.

## 6.3 타이포그래피

| 용도 | 패밀리 | 출처 · 라이선스 |
|---|---|---|
| 본문 | `Pretendard` (굵기 아홉 벌) | CDN · OFL 1.1 |
| 본문 대체 | `Pretendard Variable` | npm `pretendard` — 저장소 안 · OFL 1.1 |
| 코드·수치 | `JetBrains Mono Variable` | `apps/fnb-client-a/public/fonts/` 에 직접 보유 · OFL 1.1 |
| 루트 크기 | 16px | |

`--font-sans` 는 `Pretendard, 'Pretendard Variable', …` 순서다. **차례를 뒤집으면 굵기별
아홉 벌이 한 번도 쓰이지 않는다.** 가변 폰트는 CDN 이 막히거나 네트워크가 없을 때 메우는
자리이고, 그쪽은 저장소 안에서 온다.

**Figma 에 이 두 폰트가 설치되어 있어야 한다.** 없으면 플러그인이 생성 자체를 중단한다
(폰트 대체가 일어나면 전 페이지 검증이 무너지므로).

### 제네릭 패밀리 금지

`ui-monospace`, `system-ui`, `sans-serif` 같은 CSS 제네릭은 **폰트 스택 맨 끝의 최후 수단으로만** 둔다.
실행 환경마다 다른 폰트가 렌더되고, 그 이름은 Figma 에 존재하지도 않아 플러그인이 폰트를 찾지 못한다.
추출기는 스택에서 제네릭을 건너뛰고 `document.fonts.check()` 로 실제 사용 가능한 폰트를 고르며,
실물 폰트를 하나도 못 찾으면 경고를 남긴다.

### 한 구간에 한 폰트

브라우저는 폰트가 못 그리는 글자만 다른 폰트로 대체한다(글리프 단위 폴백).
**Figma 의 TextNode 는 한 구간에 하나의 폰트만 쓸 수 있으므로, 이 경우 반드시 어긋난다.**

→ 라틴 전용 폰트(JetBrains Mono)에 한글을 넣지 않는다. 이 사이트에서 `font-mono` 가 붙는 것은
값 · 전화번호 · 영업시간 · 창업 비용 · 날짜 · `SINCE 2019` 처럼 전부 ASCII 인 자리뿐이다.
추출기가 런마다 `document.fonts.check(size, text)` 로 커버리지를 검사해 위반을 잡아낸다.
- `line-height` 는 항상 px 로 확정된다 — `%`/`normal` 금지.
- 자간이 필요하면 `tracking-*` 토큰만 사용.

숫자는 `tabular-nums` 를 쓴다. 창업 비용표처럼 금액이 세로로 늘어서는 자리는 자릿수가 흔들리면
합계를 눈으로 못 따라간다.

## 6.4 간격·모서리·동작

- 간격 기준값: `--spacing` (Tailwind 배수 체계). `p-4` = 16px.
- 본문 폭은 `max-w-320` 가운데 정렬, 안쪽 여백 `px-6 py-10`, 구획 사이 `gap-10` (`FnbSiteShell`).
- 모서리: `--radius-*` 는 **전 단계가 4px 하나로 고정**되어 있다. `rounded-lg` 를 쓰든
  `rounded-xl` 을 쓰든 결과가 같으므로, 어느 유틸리티를 골랐는지로 곡률이 갈리지 않는다.
  `rounded-full`(알약형 배지·단추·원형 마크)만 예외다.
- **타원형 모서리(`border-radius: 50% / 20%`)는 사용 금지** — Figma 가 표현하지 못해
  해당 노드가 폴백 래스터로 강등되고 네이티브 커버리지가 떨어진다.

임의 모서리 값을 쓰는 자리가 **한 곳 있다.** `BrandPoints` 의 사진 칸이
`rounded-[4rem_1rem_4rem_1rem]` 로 마주 보는 두 모서리만 크게 깎는다. 다른 카드(메뉴 · 매장 ·
마케팅)는 **누르는 것**이고 여기 셋은 **읽는 것**이라 모양으로 갈라 둔 것인데, 스케일에 없는
값이므로 **알고 둔 예외**다. 같은 모양이 두 번째로 필요해지면 그때 토큰으로 올린다 — 한 곳을
위한 토큰은 스케일이 아니다.

**동작 값도 토큰이다.** 이 사이트가 쓰려고 더한 것이 `--animate-marquee` 다.

```css
--animate-marquee: marquee var(--roll, 40s) linear infinite;
```

지속시간을 값으로 박지 않은 이유는 **항목이 몇이냐에 따라 줄 길이가 달라서**다. 같은 시간을
주면 항목이 많을수록 빨리 흐르므로, 흐르는 시간은 화면이 `--roll` 로 넘긴다(`Marquee` 가
항목 하나당 초를 곱해 만든다). `linear` 인 것도 이유가 있다 — 가감속을 주면 되돌아가는 지점에서
속도가 한 번 꺾여, 두 벌을 이어 붙인 자리가 그 순간에 드러난다.

`motion-reduce` 로 애니메이션을 끈 사람에게는 첫 벌이 그대로 서 있고 넘치는 만큼은 잘린다 —
목록이 사라지는 것이 아니라 **저절로 움직이는 것**만 멎는다. 토큰 파일의 `prefers-reduced-motion`
블록이 지속시간을 `0.01ms` 로 눌러 두는 것과 같은 규칙이다.

## 6.5 Figma 매핑 (Phase 3)

| 토큰 그룹 | Figma |
|---|---|
| `color` (모드 무관) | Variable — Color |
| `color` (`com.winpilot.modes` 있음) | Variable — Color, Light/Dark 두 모드 |
| `fontFamily` + `fontSize` + `lineHeight` | Text Style |
| `shadow` | Effect Style |
| `radius`, `spacing` | Variable — Number |
| `animate` | *(매핑 없음)* — 추출기가 캡처 직전 모든 애니메이션을 끈다 |

> **바인딩 규칙**: Variable 바인딩은 *해석된 값이 UIR 실측값과 정확히 일치할 때만* 적용한다.
> 어긋나면 raw 값을 쓰고 리포트에 `token-drift` 로 기록한다. 토큰 재사용성보다 픽셀 정확도가 우선이다.

## 6.6 `@theme static` 을 쓰는 이유

Tailwind v4 는 기본적으로 **사용된 토큰만** `:root` 에 남긴다(트리셰이킹).
그대로 두면 아직 어떤 페이지도 쓰지 않은 브랜드 색이 토큰 파일과 Figma Variables 에서 통째로 빠져,
**디자인 시스템이 페이지 구축 순서에 따라 흔들린다.**

**이 제품이 그 문제의 산 증거다.** `octo-*` 열 단계 중 이 사이트가 실제로 쓰는 것은 일곱
(`50` `200` `300` `500` `600` `700` `900`)이고, 콘솔은 `600` 하나뿐이다. `static` 이 아니면
`100` · `400` · `800` 은 어느 앱의 토큰 파일에도 나타나지 않고, 다크 모드용 단계를 고르려 할 때
**팔레트가 반쪽만 있는 상태**가 된다.

그래서 우리 네임스페이스만 `static` 으로 고정해 항상 전량 방출한다.
Tailwind 기본 팔레트(`red-*` 등)는 트리셰이킹된 채로 두고, 토큰 파일에서
`source: 'tailwind-default'` 로 구분 표기한다.

## 6.7 토큰 추가 절차

```
1. packages/tokens/theme.css 의 @theme static 에 변수 추가 — 앱의 globals.css 가 아니다
2. pnpm ssot:tokens        → artifacts/tokens/tokens.json 재생성, 분류 확인
3. 다크 모드 값이 필요하면 :root / @media (prefers-color-scheme: dark) 에 원본 변수 추가
4. Phase 3 이후: 플러그인으로 Figma Variables 갱신
```

`pnpm ssot:tokens` 출력에서 확인할 것:
- `해석 실패` 0건 — 실패가 있으면 그 토큰은 Figma 로 넘어가지 않는다
- `출처 project` 수가 기대와 일치 — 누락 시 `@theme static` 밖에 선언한 것

## 6.8 금지 사항

- raw hex / raw px / `rounded-[Npx]` / `text-[Npx]` 같은 임의값 (§6.4 의 예외 한 곳은 이유를 함께 적었다)
- 뷰 전용 팔레트 (`--color-fnb-*`) · **앱의 CSS 에서 브랜드색 풀기** (§6.1)
- 인라인 `style` 로 색·간격 지정 — 화면이 애니메이션에 넘기는 `--roll` 만 예외다
- `oklch()` / `lab()` 직접 사용 — 토큰 경유 시 sRGB 로 정규화되지만, 직접 쓰면 추적이 끊긴다
- `bg-white` · `text-black` 처럼 모드를 따라가지 않는 값 (`night` 은 **일부러** 그런 것이고 토큰이다)
- 클래스 이름 문자열 조립 (`` `lg:col-span-${n}` ``) — Tailwind 가 그 클래스를 찾지 못해
  CSS 자체가 만들어지지 않는다

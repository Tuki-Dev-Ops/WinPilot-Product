## 5. 사용자 시나리오

### 정상

- 네 칸 채우기 → 결과가 화면에 바로 반영된다.
- 하고 싶은 말 남기기(선택) → 결과가 화면에 바로 반영된다.
- 개인정보 수집 · 이용 동의 → 결과가 화면에 바로 반영된다.
- 상담 신청 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 네 칸 채우기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 하고 싶은 말 남기기(선택) **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 개인정보 수집 · 이용 동의 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 상담 신청 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

- 성함이 비면 성함을 입력해 달라고 적는다.
- 연락처가 비면 비었다고, 형식이 아니면 형식을 적어 달라고 나눠 알린다.
- 지역 · 예산은 고르지 않으면 통과하지 않는다.
- 개인정보 동의 없이는 접수되지 않는다.
- 검사 결과는 한 번 눌러 본 뒤에만 보인다 — 적기 전부터 붉은 글이 서 있으면 양식이 이미 틀린 것처럼 보인다.

### 화면 정책

- 네 칸만 묻는다. 열몇 칸이 서면 비는 것은 양식이 아니라 신청 건수다.
- 예산을 구간으로 묻는다. 정확한 금액을 물으면 대부분 비워 둔다.
- 지역 목록을 매장과 같은 것으로 쓴다 — 따로 적으면 어느 거르개로도 걸리지 않는 문의가 생긴다.
- 처음 값을 비워 둔다. 서울이 미리 골라져 있으면 고르지 않은 사람의 문의가 전부 서울로 쌓인다.
- 하고 싶은 말은 선택이다. 필수로 두면 쓸 말이 없는 사람이 아무거나 적고 나간다.
- 프론트엔드 전용 — 보낸 신청은 이 화면에만 반영된다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 실제 접수. 지금은 토스트로 끝난다.
- 문자 발송 확인.
- 보고 계신 자리 주소 · 평수. 상담 단계가 늘어나면 그때 묻는다.

## 5. 사용자 시나리오

### 정상

- 알레르기 유발 재료 확인 → 결과가 화면에 바로 반영된다.
- 열량 확인 → 결과가 화면에 바로 반영된다.
- 같은 묶음의 다른 메뉴 열기 → 결과가 화면에 바로 반영된다.
- 메뉴판으로 돌아가기 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 알레르기 유발 재료 확인 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 열량 확인 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 같은 묶음의 다른 메뉴 열기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 메뉴판으로 돌아가기 **Then** 그 결과가 화면에 반영된다.

### 화면 정책

- 미리 만들어 두는 경로는 파는 것만이다 — 내려 둔 것까지 만들면 그 화면이 검색에 걸린다.
- 알레르기가 없으면 비우지 않고 해당 없음이라 적는다.
- 알레르기 옆에 조리 기구를 함께 쓴다는 단서를 늘 붙인다.
- 판매 중지 안내는 값과 설명 위에 둔다. 아래에 두면 다 읽고 매장에 갈 마음을 먹은 뒤에 만난다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

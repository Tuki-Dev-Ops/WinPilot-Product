# 어드민 연동 — 이 사이트가 읽는 값이 어디서 오는가

이 사이트에는 서버가 없다. 어드민에서 저장한 값이 여기 나타나는 것은 두 앱이 **같은 모듈을
읽기** 때문이지 통신하기 때문이 아니다.

```mermaid
flowchart LR
  A[F&B Admin · 3306] -->|저장| S[(packages/store/src/fnb.ts)]
  S -->|읽기| C[F&B Client · 3305]
```

값을 화면에 박아 두면 고칠 때마다 배포해야 한다. 그래서 **글자로 적어도 되는 것까지 값으로**
둔다 — 브랜드 이름이 그 예다. 한 번 바꿔 봤기 때문에 안다: 국밥 브랜드에서 이 이름으로 옮길 때
화면에 박아 둔 글자가 남는 자리가 실제로 있었다(푸터처럼 아래로 내려가야 보이는 곳).

## 걸러지는 것

사이트가 다시 판단하지 않는다. store 의 공개 필터가 한 벌로 거른다.

| 필터 | 거르는 것 |
|---|---|
| `publicMenuItems()` | 내려 둔 메뉴(품절 · 계절) |
| `publicStores()` | 휴점 매장. **준비중은 남긴다** |
| `openStores()` | 준비중까지 뺀 것 — `지금 N곳` 이라 적는 자리가 쓴다 |
| `publicFnbFaqs()` | 숨긴 FAQ |
| `orderedFnbNotices()` | 숨긴 공지. 고정한 것이 위로 |
| `postsOfChannel()` | 숨긴 글. 올린 날이 늦은 것부터 |

이 필터를 화면마다 적지 않는 이유: 새 화면을 만드는 날 그 한 줄을 빠뜨리고, 그러면 내려 둔 것이
그 화면에만 다시 뜬다.

## 배너와 팝업이 걸리는 규칙

`bannerState()` 가 **날짜로** 판정한다. 사람이 켜고 끄는 것은 `숨김` 하나뿐이다 — 개점 행사가
끝난 다음 날 아무도 안 끄기 때문이다.

| 상태 | 뜻 |
|---|---|
| `노출 중` | 지금 걸린다. `liveBanners()` · `livePopups()` 가 이것만 넘긴다 |
| `예정` | 시작일이 아직 안 됐다 |
| `종료` | 종료일이 지났다 |
| `숨김` | 사람이 내려 두었다. 기간과 상관없다 |

- **첫 화면**은 걸린 배너 중 **맨 위 하나**를 쓴다. 없으면 `FNB_BRAND.tagline` 으로 돌아간다 —
  기간이 끝난 날 새 배너를 미처 못 올렸을 때 그 자리가 비지 않게.
- **팝업**은 걸린 것 중 **하나만** 띄운다. 앞의 것을 닫으면 다음 것이 뜬다. 셋을 한꺼번에
  띄우면 손님이 셋을 닫고서야 첫 화면에 닿는다.
- `오늘 하루 보지 않기` 기록은 **그 사람의 브라우저에만** 있다. 어드민에서 볼 수 없다.

## 아직 이어지지 않은 것

정직하게 적는다. 사이트에 나가는데 어드민에서 못 고치는 값이다.

| 값 | 사이트 자리 | 어드민 |
|---|---|---|
| `BRAND_POINTS` | 홈 — 본사가 하는 것 셋 | 화면 없음. 코드에서 늘린다 |
| `GROWTH_FIGURES` · `STORE_SALES` | 홈 — 성장 판 | 화면 없음. **값이 예시라 실제 숫자로 바꿀 때 정보공개서와 맞춰야 한다** |
| `INTERIOR_GALLERY` | 인테리어 — 완성 매장 모자이크 | 화면 없음. 사진이 여덟의 배수여야 격자가 빈틈없이 채워진다 |

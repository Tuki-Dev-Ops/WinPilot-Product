# 6. 디자인 시스템

> SSOT: `packages/tokens/theme.css` 의 `@theme static` 블록
> 생성물: `artifacts/tokens/tokens.json` (DTCG) — `pnpm ssot:tokens`
> 관련: `docs/architecture/design-sync-ssot.md` §L0

## 6.1 원칙

1. **토큰이 아니면 쓸 수 없다.** raw hex·raw px 는 금지. Tailwind 유틸리티를 통해서만 접근한다.
2. **값의 진실은 브라우저에 있다.** 토큰 파일은 설정 파서가 아니라
   실행 중인 앱의 `getComputedStyle(:root)` 에서 추출된다.
3. **사이트와 콘솔은 같은 토큰을 쓴다.** 둘의 차이는 *토큰 값*이 아니라
   *어떤 토큰을 어디에 쓰는가* 로만 표현한다. IR 전용 팔레트를 만들지 않는다.

`app/globals.css` 가 하는 일은 세 줄뿐이다 — Tailwind 를 들이고, `@winpilot/tokens/theme.css` 를
들이고, 자동 훑기에 걸리지 않는 워크스페이스 패키지(`packages/ui/src`)를 `@source` 로 지목한다.
**색·글자·모서리 값을 여기에 적지 않는다.** 적는 순간 디자인 시스템이 한 벌 더 생기고,
공유 조각(`@winpilot/ui`)이 어느 색으로 그려질지 아무도 모르게 된다.

### 팔레트 토큰 (모드 무관)

| 토큰 | 값 | | 토큰 | 값 |
|---|---|---|---|---|
| `brand-50` | `#eef5ff` | | `brand-500` | `#3182f6` |
| `brand-100` | `#d9e8ff` | | `brand-600` | `#2272eb` |
| `brand-200` | `#b8d5ff` | | `brand-700` | `#1b5fc4` |
| `brand-300` | `#8abaff` | | `brand-800` | `#1a4f9c` |
| `brand-400` | `#5c9bfb` | | `brand-900` | `#1a437c` |

500 이 버튼, 600 이 그 호버, 700 이 링크·강조 글자다. 링크에 600 을 쓰지 않는 이유는 토큰 파일에
적혀 있다 — 흰 배경 대비 4.49:1 로 본문 기준(4.5:1)에 아슬아슬하게 못 미친다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `night` | `#05060d` | **어두운 칸의 바탕** — 첫 화면 · 서비스 그림 · 푸터 |
| `signal-ok` | `#17915c` | 완료·성공 |
| `signal-wait` | `#9a7b12` | 진행중·주의 |
| `signal-danger` | `#d92d20` | 오류·필수 표시 |

`night` 만 **밝기 모드를 따라가지 않는다.** 그 칸들은 배경 영상과 이어지는 자리라, 라이트
모드에서 밝아지면 영상 위의 흰 글씨가 사라진다 — 늘 어두워야 하는 색이다. 토큰으로 두기 전에는
`bg-[#05060d]` 로 일곱 파일에 흩어져 있었고, 그중 하나만 빠뜨려도 칸과 칸 사이에 보일락 말락 한
경계선이 생겼다.

**`octo-*` 는 이 사이트의 색이 아니다.** 같은 토큰 파일에 자줏빛 붉은 스케일이 열 단계 더 있는데
그것은 외식 템플릿의 브랜드색이고, 이 앱에서는 한 번도 쓰이지 않는다. 두 템플릿이 한 토큰 파일을
나눠 쓰는 구조라 브랜드가 둘이면 스케일도 둘이다 — `brand-*` 를 고치면 이 사이트가 통째로 색이
바뀐다.

**예외 한 곳 — `lib/palette.ts`.** 아이소메트릭 그림(`IsoMap` · `IsoEquipment`)이 쓰는 색만
그 파일에 모여 있다. SVG 의 `fill`·`stroke` 는 클래스가 아니라 속성으로 받고 값에 반투명이
섞여(`rgba(148,163,184,0.24)`) 유틸리티로 옮기면 같은 회색이 스무 자리에 스무 번 적힌다 —
그중 하나만 0.25 로 어긋나도 아무도 알아채지 못한다. 그 파일에 없는 색을 화면에서 직접 적는
일은 없어야 한다.

### 브랜드 색의 모드 대응

`brand-*` 는 모드에 따라 값이 바뀌지 않는다. 다크 모드에서 대비가 부족하면
**값을 바꾸지 말고 단계를 바꾼다** (`text-brand-700` → `dark:text-brand-300`).
값을 모드별로 나누면 팔레트가 두 벌이 되어 Figma Variables 매핑이 복잡해진다.

## 6.3 타이포그래피

| 용도 | 패밀리 | 출처 · 라이선스 |
|---|---|---|
| 본문 | `Pretendard` → `Pretendard Variable` | 굵기 아홉 벌은 CDN, 가변 폰트는 npm `pretendard` · OFL 1.1 |
| 코드·수치 | `JetBrains Mono Variable` | `public/fonts/` 에 직접 보유 · OFL 1.1 |
| 루트 크기 | 16px | |

굵기별 아홉 벌을 따로 선언하는 이유는 **Figma 에 설치하는 파일과 화면이 쓰는 파일을 같은 이름·
같은 굵기로 맞추기** 위해서다 — 가변 폰트는 Figma 에서 굵기가 한 단계로 뭉개지는 일이 있다.
그 아홉 벌은 CDN 에서 오고, 네트워크가 막히면 다음 자리인 `Pretendard Variable`(저장소 안의
파일)이 그대로 받는다. 이 사이트는 그렇게 네트워크 없이도 뜬다.

**Figma 에 이 두 폰트가 설치되어 있어야 한다.** 없으면 플러그인이 생성 자체를 중단한다
(폰트 대체가 일어나면 전 페이지 검증이 무너지므로).

### 제네릭 패밀리 금지

`ui-monospace`, `system-ui`, `sans-serif` 같은 CSS 제네릭은 **폰트 스택 맨 끝의 최후 수단으로만** 둔다.
실행 환경마다 다른 폰트가 렌더되고, 그 이름은 Figma 에 존재하지도 않아 플러그인이 폰트를 찾지 못한다.
추출기는 스택에서 제네릭을 건너뛰고 `document.fonts.check()` 로 실제 사용 가능한 폰트를 고르며,
실물 폰트를 하나도 못 찾으면 경고를 남긴다.

### 한 구간에 한 폰트

브라우저는 폰트가 못 그리는 글자만 다른 폰트로 대체한다(글리프 단위 폴백).
**Figma 의 TextNode 는 한 구간에 하나의 폰트만 쓸 수 있으므로, 이 경우 반드시 어긋난다.**

→ 라틴 전용 폰트(JetBrains Mono)에 한글을 넣지 않는다. 코드·경로·수치 등 ASCII 에만 쓴다.
추출기가 런마다 `document.fonts.check(size, text)` 로 커버리지를 검사해 위반을 잡아낸다.
- `line-height` 는 항상 px 로 확정된다 — `%`/`normal` 금지.
- 자간이 필요하면 `tracking-*` 토큰만 사용.

숫자는 `tabular-nums` 를 쓴다. 특히 재무·주가·배당 표는 **자릿수가 흔들리면 분기끼리 견줄 수
없다** — 여기 오는 사람이 하는 일이 바로 그 비교다.

크기는 `text-sm` 이 본문이고 `text-xs` 가 표 머리글·메타다. 그보다 큰 것(`text-xl` 이상)은
첫 화면과 각 화면의 제목처럼 **표가 없는 자리**에만 선다 — 콘솔과 반대다. 읽으러 온 사람에게는
제목이 길잡이지만, 운영자는 이미 메뉴로 자기 자리를 알고 들어온다.

`text-2xs`(11px) · `text-3xs`(10px) 는 Tailwind 스케일이 12px 에서 끝나기 때문에 나중에 들인
것이다. 그전에는 `text-[10px]` 같은 임의값으로 흩어져 있었고, 임의값은 `@theme` 가 방출하는
`--*` 가 아니라 유틸리티 클래스 안에 박힌 상수라 **추출기가 보지 못한다** — Figma Variables 에서
통째로 빠진다.

## 6.4 간격·모서리

- 간격 기준값: `--spacing` (Tailwind 배수 체계). `p-4` = 16px.
- 본문은 `max-w-320` 가운데 정렬에 `px-6 py-10`, 칸 사이는 `gap-10` 이다. 이 값은 `IrSiteShell`
  한 곳에 있다 — 화면마다 적으면 화면마다 조금씩 다른 여백이 생긴다.
- 첫 화면(`hero`)과 좌우 끝까지 닿는 판(`bleed`)만 그 폭 밖이다. 본문 안에 두고 음수 여백으로
  빼내면 너비 제한까지는 벗어나지 못해, 넓은 화면에서 배경만 가운데 상자로 남는다.
- 모서리: `--radius-*` 토큰만 사용. **전 단계가 4px 하나로 고정**되어 있어 `rounded-lg` 를 쓰든
  `rounded-xl` 을 쓰든 결과가 같다 — 어느 유틸리티를 골랐는지로 곡률이 갈리지 않는다.
  임의 `rounded-[7px]` 는 금지.
- `rounded-full` 만 예외다. 붙는 자리는 **한 마디짜리 딱지와 동그란 것** — 태그 알약, IR 보조
  내비의 칩, 화살표가 붙는 CTA, 동그란 아이콘 단추, 연혁의 점. 표와 카드에는 붙이지 않는다.
- **타원형 모서리(`border-radius: 50% / 20%`)는 사용 금지** — Figma 가 표현하지 못해
  해당 노드가 폴백 래스터로 강등되고 네이티브 커버리지가 떨어진다.

## 6.5 Figma 매핑 (Phase 3)

| 토큰 그룹 | Figma |
|---|---|
| `color` (모드 무관) | Variable — Color |
| `color` (`com.winpilot.modes` 있음) | Variable — Color, Light/Dark 두 모드 |
| `fontFamily` + `fontSize` + `lineHeight` | Text Style |
| `shadow` | Effect Style |
| `radius`, `spacing` | Variable — Number |

> **바인딩 규칙**: Variable 바인딩은 *해석된 값이 UIR 실측값과 정확히 일치할 때만* 적용한다.
> 어긋나면 raw 값을 쓰고 리포트에 `token-drift` 로 기록한다. 토큰 재사용성보다 픽셀 정확도가 우선이다.

## 6.6 `@theme static` 을 쓰는 이유

Tailwind v4 는 기본적으로 **사용된 토큰만** `:root` 에 남긴다(트리셰이킹).
그대로 두면 아직 어떤 페이지도 쓰지 않은 브랜드 색이 토큰 파일과 Figma Variables 에서 통째로 빠져,
**디자인 시스템이 페이지 구축 순서에 따라 흔들린다.**

페이지를 하나씩 늘려가는 이 프로젝트에서는 실제로 발생하는 문제이므로,
우리 네임스페이스만 `static` 으로 고정해 항상 전량 방출한다.
Tailwind 기본 팔레트(`red-*` 등)는 트리셰이킹된 채로 두고, 토큰 파일에서
`source: 'tailwind-default'` 로 구분 표기한다.

## 6.7 토큰 추가 절차

```
1. packages/tokens/theme.css 의 @theme static 에 변수 추가
2. pnpm ssot:tokens        → artifacts/tokens/tokens.json 재생성, 분류 확인
3. 다크 모드 값이 필요하면 :root / @media (prefers-color-scheme: dark) 에 원본 변수 추가
4. Phase 3 이후: 플러그인으로 Figma Variables 갱신
```

`pnpm ssot:tokens` 출력에서 확인할 것:
- `해석 실패` 0건 — 실패가 있으면 그 토큰은 Figma 로 넘어가지 않는다
- `출처 project` 수가 기대와 일치 — 누락 시 `@theme static` 밖에 선언한 것

**앱의 CSS 에 값을 추가하지 않는다.** 이 앱과 콘솔의 `app/globals.css` 는 바이트 단위로 같고,
그 상태를 유지하는 것이 두 앱이 한 디자인 시스템을 쓴다는 유일한 증거다.

## 6.8 금지 사항

- raw hex / raw px / `rounded-[Npx]` / `text-[Npx]` 같은 임의값
- 뷰 전용 팔레트 (`--color-ir-*` 같은 것)
- 인라인 `style` 로 색·간격 지정
- `bg-white` · `text-black` 처럼 모드를 따라가지 않는 값
- 클래스 이름 문자열 조립 (`` `lg:col-span-${n}` ``) — Tailwind 가 그 클래스를 찾지 못해 CSS 자체가 만들어지지 않는다
- `oklch()` / `lab()` 직접 사용 — 토큰 경유 시 sRGB 로 정규화되지만, 직접 쓰면 추적이 끊긴다
- `lib/palette.ts` 밖에서 SVG 색을 직접 적기 (§6.2)
- **단계 없는 `brand` 를 부르기** — `--color-brand` 는 토큰에 없다. 있는 것은 `--color-brand-50`
  부터 `900` 까지이고, 단계 없이 부르는 클래스는 CSS 가 만들어지지 않아 **아무 색도 나오지
  않는다.** 눈으로는 "색이 좀 흐리네" 로 지나가는 종류의 고장이다.

  그런 자리가 셋 있었고 지금은 없다 — 공지·FAQ 목록의 `hover:text-brand` 는 `brand-700`,
  공지의 `bg-brand/10 text-brand` 딱지는 `bg-brand-50 text-brand-700` 이 되었다. 규칙을 남기는
  이유는 다음에 또 이렇게 적히기 때문이다.

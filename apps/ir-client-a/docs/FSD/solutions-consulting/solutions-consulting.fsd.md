## 5. 사용자 시나리오

### 정상

- 서비스 상세 정보 조회 → 결과가 화면에 바로 반영된다.
- 페이지 하단 문의 영역에서 문의하기 페이지로 이동 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 서비스 상세 정보 조회 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 페이지 하단 문의 영역에서 문의하기 페이지로 이동 **Then** 그 결과가 화면에 반영된다.

### 화면 정책

- 제품 및 서비스 상세 6개 화면이 동일한 컴포넌트(`OfferingDetail`)를 사용합니다.
- 주요 기능보다 도입 대상 과제를 상단에 배치합니다.
- 적용 업종과 진행 절차는 하단에 배치합니다.
- 도입 효과에 수치를 기재하지 않습니다. 현장 조건에 따라 달라지는 값입니다.
- 서비스명은 등록 데이터의 값을 그대로 사용합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.

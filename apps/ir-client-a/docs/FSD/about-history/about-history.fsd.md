## 5. 사용자 시나리오

### 정상

- 해를 따라 내려가며 읽기 → 결과가 화면에 바로 반영된다.
- 같은 해의 일들을 묶음으로 읽기 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 해를 따라 내려가며 읽기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 같은 해의 일들을 묶음으로 읽기 **Then** 그 결과가 화면에 반영된다.

### 화면 정책

- 위가 최신이다. 오래된 것부터 쌓으면 지금 무엇을 하는 회사인지가 맨 아래에 있게 되는데, 여기 오는 사람의 절반은 첫 화면만 보고 나간다.
- 해마다 묶을 때 `Map` 을 쓴다 — 평범한 객체는 숫자처럼 생긴 키를 오름차순으로 다시 세워, 최신순으로 정렬해 둔 것이 뒤집힌다.
- 월이 비어 있으면 날짜 표기로 대신한다. 빈 자리를 그대로 두지 않는다.
- 개수를 자르지 않는다. 연혁은 끝까지 읽는 값이라 더 보기를 두면 그 아래가 안 읽힌다.
- 값을 이 앱이 따로 들지 않는다. 같은 회사의 연혁을 어드민이 고치고 있어 두 벌이 되면 한쪽만 고쳐진다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

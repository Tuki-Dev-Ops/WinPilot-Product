## 5. 사용자 시나리오

### 정상

- 연도별 연혁 조회 → 결과가 화면에 바로 반영된다.
- 동일 연도 연혁 항목 조회 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 연도별 연혁 조회 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 동일 연도 연혁 항목 조회 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

_N/A — 이 화면에는 해당되지 않습니다._

### 화면 정책

- 최신 연도를 상단에 배치합니다.
- 연도별 그룹화에 `Map` 을 사용합니다. 일반 객체는 숫자 형태의 키를 오름차순으로 재정렬하여 최신순 정렬이 유지되지 않습니다.
- 월 정보가 없으면 날짜 표기로 대체합니다.
- 표시 건수를 제한하지 않습니다. 더 보기 방식을 적용하면 하위 항목의 조회율이 저하됩니다.
- 연혁 데이터를 본 앱에서 별도 관리하지 않습니다. 관리자와 동일한 데이터를 조회합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 연도 바로가기 내비게이션. 연혁이 20개 연도를 초과하는 시점에 도입합니다.
- 연혁 항목별 이미지 등록.

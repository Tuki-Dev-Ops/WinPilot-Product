## 5. 사용자 시나리오

### 정상

- 질문·답으로 검색 → 결과가 화면에 바로 반영된다.
- 분류·상태로 거르기 → 결과가 화면에 바로 반영된다.
- 줄을 눌러 상세로 들어가기 → 결과가 화면에 바로 반영된다.
- 질문 등록 → 결과가 화면에 바로 반영된다.
- 삭제 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 질문·답으로 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 분류·상태로 거르기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 줄을 눌러 상세로 들어가기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 질문 등록 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 삭제 **Then** 그 결과가 화면에 반영된다.

### 화면 정책

- 고객센터 FAQ 와 표 한 벌을 쓴다. 화면마다 그리면 열 폭 · 거르개 · 지울 때 나오는 말이 두 벌이 되고, 그러다 한쪽에만 분류 열이 빠진다.
- 분류가 첫 칸이다 — 사이트가 이것으로 왼쪽 기둥을 세운다. 여기서 안 보이면 어느 기둥에 붙을지 모르는 채로 글을 쓰게 된다.
- 답을 질문보다 넓게 세운다. 이 화면에서 하는 일은 답이 옛말인지 확인하는 것이다 — 값이 오르면 창업 비용을 적은 답도 함께 고쳐야 한다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

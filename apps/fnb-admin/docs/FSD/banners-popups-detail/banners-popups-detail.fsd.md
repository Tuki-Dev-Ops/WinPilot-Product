## 5. 사용자 시나리오

### 정상

- 제목 및 내용 수정 → 결과가 화면에 바로 반영된다.
- 게시 기간 수정 → 결과가 화면에 바로 반영된다.
- 오늘 하루 보지 않기 설정 변경 → 결과가 화면에 바로 반영된다.
- 노출 상태 변경 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 제목 및 내용 수정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 게시 기간 수정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 오늘 하루 보지 않기 설정 변경 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 노출 상태 변경 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

- 제목과 내용은 공백만으로 저장할 수 없습니다.
- 시작일은 `YYYY-MM-DD` 형식이어야 하며 종료일은 미입력 또는 동일 형식이어야 합니다.
- 종료일이 시작일보다 이전이면 노출되지 않는다는 안내를 함께 표시합니다.
- 내용이 120자를 초과하면 안내만 표시하고 저장은 허용합니다.

### 화면 정책

- 내용을 짧게 작성하도록 안내합니다. 팝업은 열람을 차단하는 형태이므로 길이가 길면 읽지 않고 닫습니다.
- 설정 항목 옆에 해당 설정의 영향을 함께 표시합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 노출 위치와 크기 설정.

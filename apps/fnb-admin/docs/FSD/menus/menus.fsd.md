## 5. 사용자 시나리오

### 정상

- 메뉴명·설명으로 검색 → 결과가 화면에 바로 반영된다.
- 묶음·상태로 거르기 → 결과가 화면에 바로 반영된다.
- 줄을 눌러 상세로 들어가기 → 결과가 화면에 바로 반영된다.
- 메뉴 등록 → 결과가 화면에 바로 반영된다.
- 삭제 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 메뉴명·설명으로 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 묶음·상태로 거르기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 줄을 눌러 상세로 들어가기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 메뉴 등록 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 삭제 **Then** 그 결과가 화면에 반영된다.

| 발생 조건 | 사용자 안내 | 화면 처리 |

### 화면 정책

- 알레르기를 상세에만 두지 않고 목록에 세운다. 스무 줄을 하나씩 열어 확인하게 두면 아무도 확인하지 않는다.
- 값 칸을 두 칸으로 둔다 — 알레르기는 잘려도 뜻이 남지만 값은 잘리면 다른 숫자가 된다.
- 표와 매운 정도를 한 칸에 적는다. 둘 다 사이트 카드의 같은 자리(사진 위 왼쪽)에 서는 값이다.
- 대개는 지우지 않고 내린다 — 지우면 다시 팔 때 처음부터 적어야 한다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

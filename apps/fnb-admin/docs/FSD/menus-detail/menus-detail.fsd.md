## 5. 사용자 시나리오

### 정상

- 메뉴명 · 카테고리 · 가격 · 열량 · 설명 수정 → 결과가 화면에 바로 반영된다.
- 알레르기 유발 재료 수정 → 결과가 화면에 바로 반영된다.
- 태그 및 맵기 정도 설정 → 결과가 화면에 바로 반영된다.
- 메뉴 노출 상태 변경 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 메뉴명 · 카테고리 · 가격 · 열량 · 설명 수정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 알레르기 유발 재료 수정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 태그 및 맵기 정도 설정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 메뉴 노출 상태 변경 **Then** 그 결과가 화면에 반영된다.

| 발생 조건 | 사용자 안내 | 화면 처리 |

| 알레르기 유발 재료는 사전 정의된 목록에서만 선택합니다. 자유 입력 시 검색과 대조가 불가능한 값이 등록됩니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 가격과 열량은 숫자만 입력할 수 있습니다.
- 미입력과 형식 오류를 구분하여 각각의 메시지를 표시합니다.
- 메뉴명과 메뉴 설명은 공백만으로 저장할 수 없습니다.
- 알레르기 유발 재료를 선택하지 않아도 저장할 수 있으나, 의도한 입력인지 확인하는 안내를 표시합니다.

### 화면 정책

- 가격은 숫자만 입력받습니다. 단위와 구분 기호가 포함되면 집계가 불가능해집니다.
- 천 단위 구분 표시는 화면에서 처리합니다(`formatPrice`). 고객 사이트와 관리자가 동일한 표기를 사용해야 합니다.
- 카테고리는 코드와 명칭이 다르므로 선택 항목에는 명칭을 표시합니다. 명칭을 값으로 저장하면 카테고리명 변경 시 연결이 끊어집니다.
- 노출을 비활성화해도 상세 URL 은 접근 가능하며 판매 중지 안내를 표시합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

## 5. 사용자 시나리오

### 정상

- 주요 지표 카드 6개 조회 → 결과가 화면에 바로 반영된다.
- 미응대 창업 문의 상세로 이동 → 결과가 화면에 바로 반영된다.
- 고객 사이트에 게시 중인 공지 조회 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 주요 지표 카드 6개 조회 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 미응대 창업 문의 상세로 이동 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 고객 사이트에 게시 중인 공지 조회 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

_N/A — 이 화면에는 해당되지 않습니다._

### 화면 정책

- 미응대 문의는 접수일이 오래된 순으로 정렬합니다.
- 기준일은 화면에서 결정하여 컴포넌트에 전달합니다. 컴포넌트 내부에서 현재 시각을 조회하면 사전 생성 페이지에서 빌드 시점 값으로 고정됩니다.
- 배너 및 팝업의 게시 여부는 `bannerState()` 단일 함수로 판단합니다. 화면별로 계산하면 목록과 대시보드가 서로 다른 결과를 표시합니다.
- 팝업 카드는 게시 건수가 3건을 초과할 때만 강조합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

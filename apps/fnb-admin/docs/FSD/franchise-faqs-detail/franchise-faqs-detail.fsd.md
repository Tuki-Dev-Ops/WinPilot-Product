## 5. 사용자 시나리오

### 정상

- 분류 수정 → 결과가 화면에 바로 반영된다.
- 질문 및 답변 수정 → 결과가 화면에 바로 반영된다.
- 공개 상태 변경 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 분류 수정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 질문 및 답변 수정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 공개 상태 변경 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

- 질문과 답변은 공백만으로 저장할 수 없습니다.
- 질문이 물음표로 끝나지 않으면 안내만 표시하고 저장은 허용합니다.

### 화면 정책

- 답변 길이를 제한하지 않습니다. 고객 사이트에서 아코디언으로 표시되어 높이가 가변이기 때문입니다.
- 사내 용어가 아닌 방문자가 사용하는 표현으로 질문을 작성합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

## 5. 사용자 시나리오

### 정상

- 이름 및 이메일 수정 → 결과가 화면에 바로 반영된다.
- 권한 등급 변경 → 결과가 화면에 바로 반영된다.
- 계정 상태 변경 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 이름 및 이메일 수정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 권한 등급 변경 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 계정 상태 변경 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 활성 상태의 대표 등급 계정이 1개뿐이면 해당 계정의 등급을 낮추거나 비활성화할 수 없습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 비밀번호는 본 화면에서 관리하지 않습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 계정 번호는 수정할 수 없습니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 이름은 공백만으로 저장할 수 없습니다.
- 이메일은 `아이디@도메인` 형식이어야 합니다.
- 활성 상태의 대표 등급 계정이 1개뿐이면 등급 변경과 비활성화를 차단하고 사유를 안내합니다.

### 화면 정책

- 이메일 수정을 허용합니다. 수정이 불가능하면 도메인 변경 시 동일인의 계정이 2건으로 등록됩니다.
- 비활성화 시 로그인만 차단되며 변경 이력은 유지됩니다.
- 확인 모달 문구를 계정 권한 기준으로 표시합니다. 고객 사이트 반영 여부가 아니라 콘솔 수행 범위가 변경되기 때문입니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 비밀번호 재설정 메일 발송. 로그인 화면 구현과 함께 도입합니다.

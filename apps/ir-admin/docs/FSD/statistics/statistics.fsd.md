## 5. 사용자 시나리오

### 정상

- 달마다의 방문과 문의를 훑는다 → 결과가 화면에 바로 반영된다.
- 많이 방문한 화면을 확인한다 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 달마다의 방문과 문의를 훑는다 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 많이 방문한 화면을 확인한다 **Then** 그 결과가 화면에 반영된다.

### 화면 정책

- 방문과 문의를 같은 줄에서 본다. 방문만 보면 늘었는지만 알고 문의만 보면 왜 늘었는지 모른다 — 둘을 겹쳐 두면 방문은 늘었는데 문의는 그대로인 달이 눈에 띈다.
- 막대를 CSS 로 그린다. 여섯 달의 높낮이 때문에 그래프 라이브러리를 들이면 묶음 크기가 수백 KB 늘고 콘솔 첫 화면이 그만큼 늦게 뜬다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

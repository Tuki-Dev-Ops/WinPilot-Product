## 5. 사용자 시나리오

### 정상

- 분류 입력 → 결과가 화면에 바로 반영된다.
- 제목 및 게시일 입력 → 결과가 화면에 바로 반영된다.
- 본문 입력 → 결과가 화면에 바로 반영된다.
- 상단 고정 및 노출 설정 → 결과가 화면에 바로 반영된다.
- 공지 등록 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 분류 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 제목 및 게시일 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 본문 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 상단 고정 및 노출 설정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 공지 등록 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |

| 공지 코드는 화면 외부에서 채번하여 전달합니다. 폼 내부에서 채번하면 리렌더링 시 값이 변경됩니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 공지 코드는 수정할 수 없으며 「자동 생성」으로 표시합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 등록 시 확인 모달을 표시합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 분류 · 제목 · 게시일 · 본문은 공백만으로 저장할 수 없습니다.

### 화면 정책

- 본문을 단일 입력 항목으로 받고 빈 줄을 기준으로 문단을 구분합니다. 문단별 입력 항목을 제공하면 순서 변경과 삭제 기능이 필요합니다.
- 상단 고정 설정 항목 옆에 적용 결과를 함께 표시합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

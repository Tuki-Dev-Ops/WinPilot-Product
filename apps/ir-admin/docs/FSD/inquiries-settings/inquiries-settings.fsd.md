## 5. 사용자 시나리오

### 정상

- 대표 수신 메일 고치기 → 결과가 화면에 바로 반영된다.
- 양식이 묻는 칸 확인 → 결과가 화면에 바로 반영된다.
- 접수 안내 문구 고치기 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 대표 수신 메일 고치기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 양식이 묻는 칸 확인 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 접수 안내 문구 고치기 **Then** 그 결과가 화면에 반영된다.

### 화면 정책

- 카드를 셋으로 나누고 카드마다 자기 저장 단추를 둔다 — 한 카드에 다 넣으면 무엇이 저장되는지 흐려지고 아래쪽이 스크롤 밖으로 나간다.
- 필수 여부를 배지가 아니라 아이콘 + 글자로 적는다. 배지를 일곱 줄 세우면 목록이 배지 줄로 보이고 하나뿐인 `선택` 이 묻힌다.
- 첨부는 20MB 까지다(`policy.md` §3 IR).
- 문의 내용은 10자 이상만 받는다 — 한 줄짜리는 되묻는 문의가 된다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 칸을 끄고 켜는 자리 — 처리방침을 함께 고칠 수 있게 될 때.

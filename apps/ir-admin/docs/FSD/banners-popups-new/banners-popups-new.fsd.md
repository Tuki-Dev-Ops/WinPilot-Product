## 5. 사용자 시나리오

### 정상

- 제목 및 본문 입력 → 결과가 화면에 바로 반영된다.
- 상세 보기 URL 입력 → 결과가 화면에 바로 반영된다.
- 게시 기간 입력 → 결과가 화면에 바로 반영된다.
- 노출 설정 → 결과가 화면에 바로 반영된다.
- 팝업 등록 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 제목 및 본문 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 상세 보기 URL 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 게시 기간 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 노출 설정 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 팝업 등록 **Then** 그 결과가 화면에 반영된다.

| 상세 보기 URL 을 미입력하면 버튼이 표시되지 않는다고 안내합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 본문이 미입력이면 저장하지 않습니다.
- 제목과 시작일은 미입력으로 저장할 수 없습니다.

### 화면 정책

- 기존에는 본문 입력 항목이 없어 제목에 안내 내용을 모두 작성해야 했고 목록의 열 구성이 유지되지 않았습니다.
- 메인 배너와 동일한 폼 컴포넌트를 사용하며 노출 위치를 `slot` 으로 전달받아 문구만 변경합니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

- 오늘 하루 보지 않기 기본값 설정.

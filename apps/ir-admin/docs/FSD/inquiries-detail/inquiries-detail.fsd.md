## 1. 기능 명칭

| 항목 | 내용 |
|---|---|
| 화면명 | Inquiry Detail |

여기서 정한 값이 나타나는 고객 화면이다. 이 화면이 원본이고, 고객 화면은 받아 그린다.

## 5. 사용자 시나리오

### 정상

- 발신자 정보 조회 → 결과가 화면에 바로 반영된다.
- 문의 내용 조회 → 결과가 화면에 바로 반영된다.
- 답변 내용 입력 → 결과가 화면에 바로 반영된다.
- 처리 상태 변경 → 결과가 화면에 바로 반영된다.
- 목록으로 이동 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 발신자 정보 조회 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 문의 내용 조회 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 답변 내용 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 처리 상태 변경 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 목록으로 이동 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 문의 내용은 조회 전용입니다. 수정 가능하게 할 경우 원본 데이터가 유실됩니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 답변완료로 변경할 때만 답변 내용을 필수로 요구합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 저장 시 확인 모달을 표시하며 처리 상태에 따라 문구를 구분합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 목록으로 이동할 때 저장하지 않은 입력은 반영되지 않는다고 안내합니다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 처리 상태가 답변완료인데 답변 내용이 미입력이면 저장하지 않습니다.

### 화면 정책

- 지역과 연락처를 답변 입력 영역보다 상단에 배치합니다. 답변 작성 전에 확인하는 정보이기 때문입니다.
- 전화번호와 이메일은 고정폭 서체로 표시합니다.
- 문의 원문 수정 불가는 정책 사항입니다(`policy.md` §3 IR).

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

### 향후 확장

## 5. 사용자 시나리오

### 정상

- 보낸 사람 정보 확인 → 결과가 화면에 바로 반영된다.
- 문의 내용 읽기 → 결과가 화면에 바로 반영된다.
- 답변 적기 → 결과가 화면에 바로 반영된다.
- 상태 바꾸기 → 결과가 화면에 바로 반영된다.
- 목록으로 돌아가기 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 보낸 사람 정보 확인 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 문의 내용 읽기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 답변 적기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 상태 바꾸기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 목록으로 돌아가기 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

- 상태가 `답변완료` 인데 답변 본문이 비면 막는다.

### 화면 정책

- 지역과 연락처를 답 상자 **위**에 둔다. 답을 쓰기 전에 보는 것이 그 둘이고, 아래에 두면 다 쓰고 나서 다시 올라와 읽게 된다.
- 번호와 주소는 고정폭으로 적는다 — 자릿수를 눈으로 견줄 수 있어야 한다.
- 문의 원문 수정 불가는 정책이다(`policy.md` §3 IR).

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

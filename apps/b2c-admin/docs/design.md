# 디자인 시스템 — B2C Admin

> SSOT: `packages/tokens/theme.css` 의 `@theme static` 블록
> 앱이 색을 선언하는 자리: **없다** — `app/globals.css` 는 그 파일을 `@import` 만 한다.

## 1. 값의 원본은 한 곳이다

`app/globals.css` 가 하는 일은 세 줄뿐이다: Tailwind 를 들이고, `@winpilot/tokens/theme.css` 를
들이고, 자동 훑기에 걸리지 않는 워크스페이스 패키지(`packages/ui/src` · `packages/docs/src`)를
`@source` 로 지목한다. **색·글자·모서리 값을 여기에 적지 않는다.** 적는 순간 어드민만의
디자인 시스템이 한 벌 더 생기고, 고객 화면과 같은 브랜드라는 말이 성립하지 않는다.

어드민 전용 팔레트(`--color-admin-*` 같은 것)도 만들지 않는다. **고객 화면과 어드민의 차이는
값의 차이가 아니라 같은 값을 어디에 얼마나 쓰는가의 차이**이고, 그 차이는 4장 아래에 적어 둔다.

## 2. 색

### 2.1 시맨틱 토큰

역할로 이름이 붙어 있어 밝은 모드·어두운 모드가 자동으로 따라간다. `bg-white` 처럼 값을
직접 부르면 어두운 모드에서 그 자리만 하얗게 남는다.

| 토큰 | Light | Dark | 어드민에서 쓰는 자리 |
|---|---|---|---|
| `canvas` | `#ffffff` | `#090a0d` | 사이드바 · 상단 헤더 · 목록 카드 · 폼 카드 안쪽 |
| `surface` | `#f6f7f9` | `#0f1117` | 화면 바탕(`AdminShell` 바깥) · 행 hover · 중립 뱃지 바탕 |
| `surface-raised` | `#ffffff` | `#151822` | 모달 패널 · 선택 막대 |
| `border` | `#e3e5eb` | `#21252f` | 카드 테두리 · 표 행 구분선 |
| `border-strong` | `#cbcfd9` | `#333846` | 입력란 · 보조 버튼 테두리 |
| `ink` | `#333d4b` | `#f1f3f7` | 본문 |
| `ink-muted` | `#8b95a1` | `#98a0af` | 보조 텍스트 · 비활성 메뉴 · 보조 버튼 글자 |
| `ink-faint` | `#b0b8c1` | `#6b7684` | 표 머리글 · 항목 라벨 · 식별자 |

쓰는 법은 `bg-canvas` · `text-ink-muted` · `border-border` 처럼 유틸리티를 통해서만이다.

**어드민은 `surface` 위에 `canvas` 를 얹는다.** 고객 화면은 흰 바탕(`canvas`) 위에 회색
구획(`surface`)을 두는데, `AdminShell` 은 반대로 화면 전체가 `bg-surface` 이고 사이드바·헤더·
목록·폼 카드가 `bg-canvas` 로 떠 있다. 표와 폼이 화면을 가득 채우는 곳이라, 바탕이 밝으면
카드 경계가 사라져 어디까지가 한 덩어리인지 읽히지 않는다.

### 2.2 브랜드 팔레트

모드에 따라 값이 바뀌지 않는다. 어두운 모드에서 대비가 모자라면 **값이 아니라 단계를 바꾼다**
(`text-brand-700` → `dark:text-brand-300`).

| 토큰 | 값 | 토큰 | 값 |
|---|---|---|---|
| `brand-50` | `#eef5ff` | `brand-500` | `#3182f6` |
| `brand-100` | `#d9e8ff` | `brand-600` | `#2272eb` |
| `brand-200` | `#b8d5ff` | `brand-700` | `#1b5fc4` |
| `brand-300` | `#8abaff` | `brand-800` | `#1a4f9c` |
| `brand-400` | `#5c9bfb` | `brand-900` | `#1a437c` |

어드민이 실제로 쓰는 단계는 다섯이다.

| 단계 | 자리 |
|---|---|
| `brand-500` | 주요 버튼 바탕 · 활성 필터 테두리 · 체크박스 체크 · 필터 개수 표시 |
| `brand-600` | 그 버튼들의 hover |
| `brand-700` | 링크 · 활성 메뉴 글자 · 활성 탭 글자 · 일괄 작업 줄 글자 (밝은 모드) |
| `brand-50` / `brand-900` | 활성 메뉴·활성 탭·정보성 뱃지 바탕 (밝은 모드 / 어두운 모드) |
| `brand-200` / `brand-800` | 일괄 작업 줄(`AdminBulkBar`) 테두리 |

링크에 `brand-600` 을 쓰지 않는 이유는 토큰 파일에 적혀 있다 — 흰 배경 대비 4.49:1 로 본문
기준(4.5:1)에 아슬아슬하게 못 미친다.

### 2.3 신호 색

| 토큰 | 값 | 어드민에서 쓰는 자리 |
|---|---|---|
| `signal-ok` | `#17915c` | 긍정 상태 뱃지 (노출 · 판매중 · 답변완료 · 결제완료 · 배송완료 · 활성) |
| `signal-danger` | `#d92d20` | 검증 오류 문구 · 삭제 버튼 · 부정 상태 뱃지 (판매중지 · 차단 · 기간 만료) |
| `signal-wait` | `#9a7b12` | **어드민에는 쓰는 자리가 아직 없다** |

`signal-wait` 를 쓰지 않는 것은 우연이 아니다. 어드민의 '대기' 상태(판매대기 · 배송준비 ·
처리중 · 사용 완료)는 전부 **중립 뱃지**(`bg-surface text-ink-muted`)로 그린다 — 표 한 장에
뱃지가 스무 개씩 놓이는 화면에서 노랑까지 섞으면 정말 봐야 할 빨강이 묻힌다.

## 3. 글자

| 용도 | 토큰 | 값 |
|---|---|---|
| 본문 | `font-sans` | `Pretendard Variable` |
| 코드 · 식별자 · 순번 | `font-mono` | `JetBrains Mono Variable` |

**JetBrains Mono 에 한글을 넣지 않는다.** 라틴 전용 폰트라 한글은 브라우저가 다른 폰트로
대체해 그리는데, Figma 의 텍스트 노드는 한 구간에 폰트 하나만 쓸 수 있어 그 자리가 반드시
어긋난다. 어드민에서 `font-mono` 가 붙는 것은 상품코드 · 주문번호 · 문의 경로 · 목록 순번처럼
전부 ASCII 인 값뿐이다.

숫자가 열로 늘어서는 자리에는 `tabular-nums` 를 붙인다. 금액·재고·건수·페이지 번호가 여기
해당한다 — 자릿수가 흔들리면 표는 훑을 수 없다.

### 3.1 어드민의 글자 크기 운용

쓰는 크기는 넷뿐이다.

| 크기 | 자리 |
|---|---|
| `text-lg` | 상단 헤더의 현재 위치 한 줄 (`AdminShell` 의 `<h1>`) |
| `text-base` | 카드 제목 (`ContentSection`) · 모달 제목 |
| `text-sm` | **본문 기본** — 표의 값 · 입력란 · 버튼 · 메뉴 · 탭 |
| `text-xs` | 표 머리글 · 항목 라벨 · 상태 뱃지 · 식별자 |
| `text-2xs` (11px) | 미리보기 안의 보조 줄 · 문서 사이드바의 구역 이름 |
| `text-3xs` (10px) | 뱃지 안의 보조 표시 · 미리보기 속 도메인 줄 |

예외는 둘이다. 로그인 화면의 왼쪽 문구(`text-3xl`)와 통계 카드의 숫자(`StatCard`, `text-3xl`).
둘 다 표가 없는 화면이다.

**`text-2xs`·`text-3xs` 는 나중에 스케일에 들인 것이다.** Tailwind 의 크기 스케일은 12px 에서
끝나는데 화면에는 그보다 작은 글자가 실제로 있어서, 지금까지는 `text-[10px]`·`text-[11px]`
같은 **임의값**으로 서른일곱 자리에 흩어져 있었다. 그러면 셋이 어긋난다 — 같은 성격의 글자가
10px 인지 11px 인지 우연으로 정해지고, 한 단계 키우려면 서른일곱 자리를 찾아야 하며,
**추출기가 보지 못해** Figma Variables 에서 통째로 빠진다(임의값은 `@theme` 가 방출하는
`--*` 가 아니라 유틸리티 클래스 안에 박힌 상수다). 8px 은 파비콘 자리 표시 한 곳뿐이라
올리지 않았다 — 한 곳을 위한 토큰은 스케일이 아니다.

**고객 화면과 다른 점은 제목 계단이 없다는 것이다.** 고객 화면에는 `text-2xl` 화면 제목
(`PageTitle`)과 `text-xl` 구획 제목이 있어 위계가 크기로 드러나지만, 어드민의 제목은
`text-lg` 한 줄이 끝이고 그마저도 위치 표시(`사용자 | 관리자 | 상세`)다. 운영자는 이미
사이드바와 보조 메뉴로 자기가 어디 있는지 알고 들어오므로 제목이 클 이유가 없고, 그 자리를
표에 내준다.

반대로 **`text-xs` 의 비중은 어드민이 훨씬 높다.** `app/**` 의 클래스를 세면 고객 화면은
`text-sm` 156 · `text-xs` 79 인데 어드민은 320 · 229 다. 표 한 줄마다 머리글·라벨·식별자·
뱃지가 따라붙기 때문이다 — 이 값들을 `text-sm` 으로 올리면 값과 라벨이 같은 무게가 되어
표가 읽히지 않는다.

## 4. 여백 — 고객 화면과 다른 점

| 자리 | 고객 화면 | 어드민 |
|---|---|---|
| 본문 폭 | `max-w-320` 가운데 정렬 | **제한 없음** — 사이드바를 뺀 나머지를 다 쓴다 |
| 본문 안쪽 여백 | `px-6 py-10` | `px-6 py-8` (`lg:px-8`) |
| 구획 사이 | `gap-12` | `gap-8` |

폭을 묶지 않는 것이 가장 큰 차이다. 고객 화면은 글줄이 길어지면 읽기 어려워지므로 폭을
막지만, 어드민의 본문은 **열 열두 칸짜리 표**다. 폭을 막으면 그만큼 열이 좁아지고, 상품명이
잘리거나 관리 버튼이 다음 줄로 밀린다.

### 4.1 컨트롤 높이

높이는 네 값만 쓴다. 값이 늘어나면 같은 줄에 놓인 버튼과 입력란의 밑선이 어긋난다.

| 높이 | 자리 |
|---|---|
| `h-11` (44px) | 폼 화면의 입력란 · 드롭다운 · 저장/목록 버튼 · 토글 |
| `h-9` (36px) | 목록 툴바의 검색 · 필터 · 주요 액션 · 모달 푸터 버튼 · 선택 막대 버튼 |
| `h-8` (32px) | 표 행 안의 관리 버튼 · 페이저 버튼 · 일괄 작업 줄 버튼 |

**폼은 44px, 목록은 36px, 행 안은 32px.** 폼은 한 화면에 열 칸 남짓이라 손이 편한 쪽을
택하고, 목록은 한 화면에 스무 줄이 들어가야 하므로 줄일 수 있는 만큼 줄인다. 표 안의 버튼이
가장 작은 것은 그것이 행의 높이를 결정하기 때문이다 — 여기서 4px 을 키우면 화면에 들어가는
행이 한 줄 줄어든다.

가로로 놓이는 버튼에는 `shrink-0 whitespace-nowrap` 을 함께 건다. 좁은 폭에서 flex 가 버튼을
눌러 글자가 잘리거나 두 줄로 접히는 것을 막는다.

**이 값들은 이제 손으로 적지 않는다.** 36px 은 `@winpilot/ui` 의 `Button`, 32px 은
`RowTextButton`·`RowIconButton` 이 갖는다. 손으로 적는 동안 같은 파란 단추가 **열다섯 가지
클래스 조합**으로 갈라져 있었다 — `transition-colors` 가 있는 것과 없는 것(옆 단추는 색이
탁 바뀐다), `shrink-0` 이 있는 것과 없는 것(좁은 폭에서 어떤 단추만 글자가 접힌다), 취소
단추에 `hover:` 가 있는 것과 없는 것. 셋 다 고칠 때 한 곳만 고쳐서 생긴 자리이고, 눈에 잘
띄지 않아 오래 남았다.

44px(`h-11`) 은 아직 컴포넌트가 없다. 폼 화면의 조각들(`ContentField` 등)이 각자 들고 있는데,
두 앱이 같은 폼 뼈대를 쓰기로 정한 적이 없어 올릴 근거가 아직 없다.

## 5. 모서리

`--radius-*` 는 **전 단계가 4px 하나로 고정**되어 있다(`packages/tokens/theme.css`). `rounded-lg`
를 쓰든 `rounded-xl` 을 쓰든 결과가 같으므로, 어느 유틸리티를 골랐는지로 곡률이 갈리지 않는다.
`rounded-[7px]` 같은 임의값은 쓰지 않는다.

예외는 `rounded-full` 하나다. 붙는 자리는 **한 마디짜리 딱지**다 — 상태 뱃지, 목록 툴바의
상태 탭과 필터 개수 표시, 좁은 화면의 사이드바 칩, 자동 태그 뱃지(`ProductTagBadges`),
자동 입력 항목의 꼬리표(`ContentReadonly` 의 `note`).

**입력란 · 저장 버튼 · 목록 카드 · 모달에는 붙이지 않는다.** 값을 담는 것과 한 마디로
끝나는 딱지를 모양으로 갈라 두면, 표를 훑을 때 어느 쪽이 읽을 값인지 먼저 보인다.

## 6. 상태 뱃지

목록 화면의 대부분이 상태 한 칸을 가진다. 모양은 어디서나 같다 — `@winpilot/ui` 의 `Badge`
하나가 그린다. **클래스를 손으로 적지 않는다.**

색은 뜻에 따라 **다섯 중 하나**이고, 화면은 클래스가 아니라 그 **뜻 이름**을 넘긴다.

| `tone` | 뜻 | 예 |
|---|---|---|
| `ok` | 긍정 · 살아 있음 | 노출 · 판매중 · 답변완료 · 결제완료 · 배송완료 · 활성 · 사용 가능 |
| `neutral` | 중립 · 아직 · 끝남 | 숨김 · 판매대기 · 배송준비 · 처리중 · 휴면 · 환불완료 · 사용 완료 |
| `brand` | 진행 · 정보 | 접수 · 배송중 · 예정 · 최고 관리자 |
| `danger` | 부정 · 막힘 | 판매중지 · 차단 · 정지 · 결제취소 · 교환요청 · 종료 · 기간 만료 |
| `wait` | 기다리는 중 | **아직 쓰는 곳이 없다** — 아래 참고 |

바탕에 `/12` 를 붙여 12% 로 옅게 깐다. 색을 꽉 채우면 표 한 장에 원색 덩어리가 스무 개
생겨 글자보다 뱃지가 먼저 읽힌다.

### 6.0 클래스가 아니라 뜻을 넘기는 이유

전에는 화면과 시드 파일이 `'bg-signal-ok/12 text-signal-ok'` 같은 **클래스 문자열**을 직접
들고 있었다. 서른세 장에 마흔아홉 자리, 톤 표만 스물한 개였는데 실제 값은 위의 넷뿐이었다 —
같은 말을 스물한 번 적어 둔 셈이고, 그래서 셋이 어긋났다.

1. **어긋나도 드러나지 않는다.** `dark:bg-brand-900` 을 빠뜨린 표가 있어도 그 화면을 다크
   모드로 열기 전에는 모른다. 타입이 `string` 이라 컴파일은 통과한다.
2. **색을 바꾸려면 스물한 곳을 고쳐야 한다.** 하나라도 놓치면 그 화면만 옛 색으로 남는다.
3. **시드가 화면을 안다.** `packages/store` 는 값이 사는 곳인데 Tailwind 클래스를 들고 있었다.
   서버에서 값을 받게 되는 날 그 문자열은 갈 곳이 없다.

이제 표는 `엔터프라이즈: 'ok'` 처럼 뜻만 적고(`Record<X, BadgeTone>`), 클래스는 `Badge` 만 안다.

### 6.0.1 `wait` 를 쓰는 곳이 없다는 것

`--color-signal-wait` 는 토큰에 있는데 뱃지에서 아무도 쓰지 않는다. 지금은 '만료 임박'·'보류'
처럼 **끝난 것이 아니라 기다리는 것**을 `danger` 나 `neutral` 로 적고 있어, 고객사 목록에서
`만료` 와 `만료 임박` 이 **같은 붉은색으로 선다.** 색을 바꾸는 것은 디자인 결정이라 여기서
하지 않고 자리만 열어 두었다 — 정하면 톤 표 한 줄만 고치면 된다.

### 6.0.2 색 지도를 두는 곳

**어드민만 쓰는 것은 어드민에** 둔다. `PAY_TONE`·`SHIP_TONE` 은 `lib/data/orders.ts`,
`INQUIRY_STATE_TONE` 은 `lib/data/inquiries.ts`, `COUPON_STATE_TONE` 은 `lib/data/coupons.ts`,
`SCHEDULE_TONE`·`TAG_TONE` 은 `lib/data/banners.ts`·`lib/data/product-tags.ts` 에 있다.

뒤의 둘은 원래 `@winpilot/store` 에 있었다. 고객 화면 여섯 벌 중 어느 것도 부르지 않는데
공유 패키지에 있었던 것이라 내렸다 — 공유 패키지에 값을 두는 기준은 "두 화면이 같은 것을
본다" 이고, 여기 맞지 않았다.

### 6.1 뱃지를 쓰지 않는 자리

**값이 둘로만 갈리고 그 갈림이 이미 다른 열에 적혀 있으면 뱃지를 만들지 않는다.**
문의 목록의 미답변 표시가 그렇다 — 제목 옆에 `text-xs text-signal-danger` 글자 한 마디로
붙는다. 상태 열에 이미 접수·처리중·답변완료 뱃지가 있어서, 그 옆에 뱃지를 하나 더 두면
같은 말을 두 번 하게 된다.

## 7. 목록 화면의 크기 규칙

### 7.1 툴바 (`@winpilot/ui` 의 `ListToolbar`)

두 줄로 고정한다. **윗줄은 상태 탭(왼쪽)과 주요 액션(오른쪽), 아랫줄은 검색과 필터**다.

| 조각 | 크기 |
|---|---|
| 상태 탭 | `rounded-full px-3 py-1.5 text-sm` · 건수는 `text-xs text-ink-faint` |
| 주요 액션 | `h-9 rounded-lg bg-brand-500 px-4 text-sm font-medium` |
| 검색 | `h-9 rounded-lg border border-border-strong pl-9 pr-3` — 왼쪽 9칸은 돋보기 자리 |
| 필터 버튼 | `h-9 rounded-lg border px-4` · 걸린 조건 수를 `brand-500` 알약으로 붙인다 |
| 필터 패널 | `rounded-xl border border-border bg-canvas px-5 py-4` · 1 → 2 → 3열 |

안내 문구를 `placeholder` 로 넣지 않는다. placeholder 는 DOM 텍스트 노드가 아니라 추출되지
않고 Figma 에서 빈 상자로 나온다(`docs/spec/05-component.md`). 실제 텍스트 노드를 겹쳐 두고
포커스가 오거나 값이 들어오면 CSS 로만 숨긴다.

### 7.2 표

12칸 그리드다. `lg` 미만에서는 한 칸으로 풀려 라벨과 값이 위아래로 쌓인다.

| 자리 | 칸 | 여백 |
|---|---|---|
| 체크박스 + 순번 | 1 | — |
| 값 열 | **합쳐서 9칸을 넘지 않는다** | — |
| 관리 버튼 | 2 | — |
| 머리글 줄 | | `px-5 py-3 text-xs text-ink-faint` |
| 행 | | `px-5 py-4` · hover 에 `bg-surface` |
| 빈 목록 | | `px-5 py-16 text-center text-sm text-ink-muted` |

9칸이 예산인 이유는 넘기면 관리 열이 다음 줄로 밀려 표가 두 줄로 접히기 때문이다.
`ContentListView` 는 개발 모드에서 열 합을 세어 경고한다 — 조용히 접히면 만든 사람이
모른다.

`lg:col-span-${n}` 처럼 클래스를 문자열로 조립하지 않는다. Tailwind 가 그 클래스를 찾지
못해 CSS 자체가 만들어지지 않는다. 칸 수는 표(`SPAN`)로 적어 둔다.

### 7.3 페이저 (`AdminListPager`)

`border-t border-border px-5 py-4` 로 표 아래에 붙는다. 왼쪽에 총 건수, 오른쪽에
`h-8` 이전/다음 버튼과 `{현재} / {마지막}` 이다. 숫자는 전부 `tabular-nums`.

쪽 번호를 1·2·3… 으로 늘어놓지 않는다. 어드민의 목록은 검색과 필터로 좁혀 들어가는 것이지
쪽을 짚어 뛰어다니는 곳이 아니다.

## 8. 모달

| 조각 | 크기 |
|---|---|
| 패널 | `max-w-md` · `rounded-lg border border-border bg-surface-raised` |
| 머리 | `px-6 py-5` · 제목 `text-base font-semibold` |
| 본문 | `px-6 py-6` · 넘치면 여기만 스크롤한다 |
| 발 | `px-6 py-4` · 버튼은 오른쪽 정렬 `h-9` |
| 덮개 | `bg-ink/40` |

**폭은 `max-w-md` 하나뿐이다.** 이보다 넓어야 하는 자원은 모달을 쓰지 않고 화면을 따로
가진다 — 그 경계는 `docs/path.md` §3.1·§3.2 에 적혀 있다.

겹쳐 뜨는 확인 창은 `elevated` 로 `z-55` 에 올린다(기본은 `z-50`). 뒤 모달과 층이 같으면
확인 창이 뒤에 깔린다.

동작 값도 토큰이다 — 덮개는 `animate-overlay-in`(150ms), 패널은 `animate-panel-in`(180ms).
앱마다 제각각인 지속시간이 생기지 않도록 `packages/tokens/theme.css` 에 모아 두었다.
추출기는 캡처 직전 애니메이션을 모두 끄므로 Figma 결과에는 영향이 없다.

이 표의 값은 `@winpilot/ui` 의 `Modal` 한 곳에 있다. **두 어드민이 각자 모달을 들고 있던
동안 위의 넷 중 셋이 사내 어드민에만 없었다** — 열림 애니메이션 · `elevated` ·
`bg-surface-raised`(그쪽은 `bg-canvas` 라 다크 모드에서 뒤 배경과 붙어 보였다). 여기에
모달 스택까지 없어 확인 창 위에서 Esc 를 누르면 뒤의 입력 폼까지 함께 닫혔다. 표를 문서에
적어 두는 것만으로는 두 벌이 갈라지는 것을 막지 못한다는 자리다.

## 9. 금지 사항

- raw hex · raw px · `rounded-[Npx]` · **`text-[Npx]`** 같은 임의값 (§3.1)
- 어드민 전용 팔레트 (`--color-admin-*`)
- 인라인 `style` 로 색·간격 지정 — 추출은 되지만 토큰 추적이 끊긴다
- `oklch()` · `lab()` 직접 사용
- `bg-white` · `text-black` 처럼 모드를 따라가지 않는 값
- 클래스 이름 문자열 조립 (`` `lg:col-span-${n}` ``)
- **Tailwind 클래스 문자열을 값 쪽 파일에 담기** — `lib/data/*` · `packages/store` 는 색을
  모른다. 상태 색은 `BadgeTone` 처럼 뜻으로 적는다 (§6.0)
- **뱃지·단추·모달의 클래스를 손으로 적기** — 각각 `Badge` · `Button`/`RowTextButton` ·
  `Modal` 이 갖는다. 이 셋은 전부 손으로 적는 동안 갈라진 적이 있다

## 10. 아직 없는 것

- **`animate-drawer-in`** — 토큰에 있으나 어드민에는 서랍이 없어 쓰는 자리가 없다.
  (`animate-dropdown-in` 은 쓰이지만 `@winpilot/ui` 의 `Dropdown` 안이고, 어드민 코드에는
  직접 나오지 않는다.)
- **그림자 토큰** — `shadow-lg`(Tailwind 기본)를 `AdminSelectionBar` 한 곳에서 쓴다.
  우리 네임스페이스의 그림자 토큰은 없다.
- **밀도 전환** — 표를 더 좁게 보는 옵션은 없다. 위의 값 한 벌이 전부다.
- **다크 모드 수동 전환** — `prefers-color-scheme` 를 따르기만 하고 화면에서 고를 수 없다.

### 상태 탭과 보조 메뉴의 선택 표시

골라진 것과 누르는 것을 **색으로 가른다.**

| 자리 | 골라졌을 때 | 아닐 때 |
|---|---|---|
| 상태 탭 (`ListToolbar`) | `bg-ink text-white` · 모서리 `rounded`(4px) | `bg-surface text-ink-muted` |
| 등록 단추 | 언제나 `bg-brand-500 text-white` | — |
| 본문 왼쪽 보조 메뉴 | `border-l-2 border-brand-500` · `font-semibold` · `text-brand-700` | `border-l-2 border-transparent` · `text-ink-muted` |

탭을 브랜드색으로 채우지 않는 이유: 같은 줄 오른쪽의 등록 단추가 이미 브랜드색이라, 둘을 같은
색으로 채우면 **골라진 상태**와 **누르는 것**이 같은 무게로 보인다. 연한 `bg-brand-50` 도 쓰지
않는다 — 흰 바탕과 거의 붙어 어느 탭이 켜졌는지 눈으로 찾지 못했다.

보조 메뉴는 배경을 채우지 않고 **왼쪽 모서리 선 하나**로만 알린다. 채우면 왼쪽 사이드바의 최상위
선택과 무게가 같아져 지금 자리가 어느 쪽인지 헷갈린다. 꺼진 항목에도 같은 두께의 투명 선을 주어
켜고 끌 때 글자가 옆으로 밀리지 않게 한다.

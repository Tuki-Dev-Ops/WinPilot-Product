## 5. 사용자 시나리오

### 정상

- 기본 정보 입력 → 결과가 화면에 바로 반영된다.
- 옵션 조합 만들기 → 결과가 화면에 바로 반영된다.
- 이미지 올리기 → 결과가 화면에 바로 반영된다.
- 적립·배송 정하기 → 결과가 화면에 바로 반영된다.
- 미리보기 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 기본 정보 입력 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 옵션 조합 만들기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 이미지 올리기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 적립·배송 정하기 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 미리보기 **Then** 그 결과가 화면에 반영된다.

## 6. 예외처리

| 발생 조건 | 사용자 안내 | 화면 처리 |
|---|---|---|
| 옵션이 있으면 재고는 옵션 합계로 정해진다 — 따로 받으면 두 값이 어긋난다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |
| 필수 항목이 비면 저장 단추가 잠긴다. | 무엇이 왜 막혔는지 그 자리에서 알린다 | 입력값과 스크롤 자리를 지킨 채 안내만 더한다 |

## 7. 검증 규칙

- 판매가·재고는 0 이상의 정수만 받는다.
- 정가는 판매가보다 작을 수 없다.
- 옵션이 있으면 재고 입력칸이 잠기고 옵션 합계가 대신 들어간다.
- 조건부 무료를 고르면 기준 금액이 필수가 된다.

### 화면 정책

- 등록 직후에는 숨김 상태다 — 값을 다 채우기 전에 고객 화면에 뜨지 않게.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

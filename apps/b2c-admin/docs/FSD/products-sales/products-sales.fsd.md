## 5. 사용자 시나리오

### 정상

- 주문번호 · 주문자 검색 → 결과가 화면에 바로 반영된다.
- 주문 상태 필터 → 결과가 화면에 바로 반영된다.
- 운송장 등록 → 결과가 화면에 바로 반영된다.
- 교환 및 반품 처리 → 결과가 화면에 바로 반영된다.

### 인수 조건

- **Given** 이 화면을 열었을 때 **When** 주문번호 · 주문자 검색 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 주문 상태 필터 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 운송장 등록 **Then** 그 결과가 화면에 반영된다.
- **Given** 이 화면을 열었을 때 **When** 교환 및 반품 처리 **Then** 그 결과가 화면에 반영된다.

## 7. 검증 규칙

- 운송장 번호는 숫자와 하이픈만 입력할 수 있습니다.

### 화면 정책

- 기본 정렬은 등록일 최신순입니다.
- 검색어 · 필터 · 페이지를 URL 파라미터로 유지합니다. 새로고침과 뒤로가기에서 조건이 유지되어야 합니다.
- 검색어가 미입력이면 조건에서 제외합니다. 목록을 비우지 않습니다.
- 기본 정렬은 주문일 최신순입니다.

## 8. 화면 상태

| 상태 | 화면 |
|---|---|
| 최초 | 값이 오기 전의 자리(뼈대)를 그려 둔다 — 자리를 비우면 화면이 튄다 |
| 불러온 뒤 | 정상 화면 |
| 비어 있음 | 목록 자리를 비우지 않고 왜 비었는지 한 줄로 알린다 |
| 오류 | 같은 자리에 안내와 다시 시도할 길을 둔다 |

### UX 정책

- 조건을 채우지 못한 단추는 **잠근다.** 눌러 놓고 다음 화면에서 막으면 무엇이 잘못됐는지 늦게 안다.
- 알림은 화면 하단 정중앙 토스트 한 곳에서만 띄운다.
- 되돌릴 수 없는 일(삭제·취소)은 확인을 한 번 묻는다.
- 키보드만으로 모든 요소에 닿을 수 있고, 포커스가 어디 있는지 눈에 보인다.
- ESC 로 열린 것(모달·서랍)을 닫는다.

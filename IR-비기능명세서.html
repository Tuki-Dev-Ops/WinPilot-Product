회사 홈페이지 비기능 명세서

비기능 요건 · 4/4 2026년 8월 20일

1. 적 용 범 위

본 문서는 회사 사이트와 관리자 전 화면 63개에 적용된다. 화면 하나에만 걸리는 요건은 3장 「화면별 비기능 요건」에 따로 두었다.

1단계(Front-End)에서 판정 가능한 요건과 2단계(Back-End)에서 판정하는 요건을 구분해 표기한다. 구분하지 않으면 서버가 없는 상태에서 보안 요건이 미충족으로 잡히고, 실제로는 아직 만들 차례가 아닌 것을 결함으로 다루게 된다.

2. 공 통 비 기 능 요 건

주제별로 정리한다. 요건마다 기준값과 검증 방법을 함께 적었으며, 저장소에 검사 도구가 있는 항목은 그 도구를 적었다.

순번구분요건기준검증 방법
1성능화면 하나가 내려받는 자원 크기를 예산 안으로 관리한다.JavaScript 700KB · CSS 120KB · 이미지 400KB (전송 기준). 문서 화면은 JavaScript 1600KB 를 적용한다.저장소의 weight:check 가 전 화면을 실제로 열어 전송 바이트를 잰다.
2목록 화면은 조회 조건이 바뀔 때 화면 전체를 다시 그리지 않는다.조건 변경 시 목록 영역만 갱신되며, 헤더 · 필터 상태는 유지된다.화면별 검수 기준으로 확인한다.
3반응형정의된 기준 해상도에서 의도하지 않은 가로 스크롤이 발생하지 않는다.1280 · 1024 · 768 · 390 네 너비. 화면 63개 × 4 지점을 모두 검사한다.저장소의 overflow:check 가 자동으로 검사한다.
4표와 넓은 콘텐츠는 화면 밖으로 넘치지 않고 자체 영역에서 스크롤한다.좁은 너비에서 표는 가로 스크롤 영역을 가지며, 페이지 본문은 가로로 움직이지 않는다.overflow:check · 육안 확인.
5접근성색만으로 상태를 알리지 않는다.노출 · 미노출 등 상태 표시는 색과 함께 모양 또는 글자를 둔다.상태 표시 요소를 흑백으로 두고 구분 가능한지 확인한다.
6모션 감소를 켠 사용자에게는 자동 전환이 동작하지 않는다.캐러셀 자동 넘김과 흐르는 띠가 멈춘다. 사용자가 직접 조작하는 이동은 유지한다.운영체제의 모션 줄이기 설정을 켜고 확인한다.
7자동 전환은 사용자 조작 중에 멈춘다.마우스가 올라가거나 포커스가 들어오거나 직접 밀면 자동 넘김이 멈춘다.화면별 검수 기준으로 확인한다.
8화면 밖으로 벗어난 영역의 자동 전환은 동작하지 않는다.보이지 않는 영역에서 타이머가 돌지 않는다.스크롤 후 동작 확인.
9사용성알림은 한 자리에서만 표시한다.토스트는 화면 하단 정중앙 한 곳에서만 뜬다.전 화면 공통 확인.
10데이터가 없는 상태를 빈 화면으로 두지 않는다.목록 결과가 0건이면 빈 상태 문구를 세우고, 조건이 걸려 있으면 조건을 지우는 경로를 함께 둔다.「기능 명세서」의 예외 처리 기준으로 확인한다.
11입력 오류는 미입력과 형식 오류를 구분해 안내한다.「형식이 아닙니다」는 빈 칸에 대한 답이 아니다. 항목별로 사유를 구분한다.양식이 있는 화면의 검수 기준으로 확인한다.
12호환성최신 브라우저에서 동작한다.Chrome · Edge · Safari · Firefox 의 최신 두 개 버전과 iOS · Android 기본 브라우저.대상 브라우저에서 주요 화면 육안 확인. 지원 범위는 발주처 확인이 필요하다.
13이미지가 없는 상태에서도 화면 구조가 무너지지 않는다.이미지 미제공 영역은 대체 표기로 자리를 유지한다.이미지 차단 상태로 확인한다.
14보안사이트와 관리자 모두 HTTPS 로만 제공한다.개인정보가 오가는 경로가 있다.배포 환경 설정 확인. 2단계 · 배포 시점 적용.
15관리자는 인증된 운영자만 접근한다.권한 등급과 등급별 연산 범위는 4장에 정리한다.2단계 구현 대상. 1단계에서는 화면 흐름까지 구현되어 있다.
16개인정보가 포함된 데이터는 접근 권한을 분리한다.콘텐츠 관리와 다른 권한으로 다룬다. 분리 수준은 발주처 확인이 필요하다.2단계 구현 대상.
17화면 검증에 의존하지 않는다.「기능 명세서」에서 서버 검증으로 표기된 규칙은 API 직접 호출에도 적용되어야 한다.2단계 완료 기준. API 를 직접 호출해 확인한다.
18데이터동일한 값을 두 곳에서 관리하지 않는다.사이트와 관리자는 같은 데이터를 참조한다. 합계 · 건수 · 목록은 저장하지 않고 계산한다.「기능 명세서」의 데이터 변경 영향도로 확인한다.
19노출 중단과 데이터 삭제를 구분한다.노출 상태를 해제해도 데이터는 유지된다. 삭제는 더 이상 사용하지 않는 데이터에 한정한다.상태 변경 후 관리자 목록에 값이 남아 있는지 확인한다.
20삭제는 사본까지 함께 처리한다.본문뿐 아니라 첨부 · 검색 색인 · 캐시에 남은 사본을 함께 제거한다.2단계 구현 대상.
21운영변경 이력을 남긴다.등록 · 수정 · 삭제마다 누가 · 언제 · 무엇을 바꿨는지 기록한다.2단계 구현 대상. 보존 기간은 5장 참조.
22개인정보 열람 기록을 남긴다.개인정보가 담긴 건을 열어 본 기록을 남긴다. 변경 기록만으로는 누가 들여다봤는지 알 수 없다.2단계 구현 대상.
23성능지도는 좌표 변환 요청을 발생시키지 않는다.본사 좌표는 데이터가 보유한다. 화면에서 주소를 좌표로 변환하지 않는다.네트워크 요청 확인
- 지도 SDK 외 외부 호출이 없어야 한다.
24보안첨부 파일은 웹에서 직접 접근할 수 없는 곳에 보관한다.주소를 아는 사람이 그대로 받을 수 있으면 접근 통제가 없는 것과 같다. 인증된 요청에만 내려보낸다.2단계 구현 대상.
25첨부 파일의 확장자와 크기를 서버에서 검증한다.허용 확장자와 크기 상한은 발주처가 정한다. 실행 파일과 압축 파일의 허용 여부는 보안 판단이 필요하다.2단계 구현 대상.
26외부 연동지도를 이용할 수 없어도 주소와 교통편은 조회된다.키 미설정 · 도메인 미등록 · 쿼터 초과 시 지도 영역은 대체 안내를 표시하며, 주소 · 연락처 · 교통편 안내는 정상 표시된다.키를 비운 상태로 오시는 길 화면을 확인한다.
27외부 서비스 사용량을 관리한다.카카오 지도는 개발자 계정당 앱 1개에 무료 쿼터가 부여된다. 사용량은 개발자 콘솔에서 확인한다.「요구사항 정의서」 참조. 운영 주체는 발주처다.
28문서문서와 코드가 어긋난 상태로 남지 않는다.화면이 등록되었는데 명세가 비어 있거나, 명세가 가리키는 화면이 사라진 상태를 허용하지 않는다.spec:check · sync:check · docs:check · bind:check

2.1 전 화면 공통 제작 기준

화면을 가리지 않고 전 화면 제작에 적용되는 기준이다.

  • 데스크톱 1440 · 태블릿 768 · 모바일 375 세 너비에서 가로 스크롤이 생기지 않습니다.
  • placeholder·option·input value 는 추출되지 않으므로 화면 문구로 쓰지 않는다 (겹친 글자·직접 그린 목록으로 대체).
  • 차트·아이콘·삽화는 전부 인라인 SVG 입니다. 비트맵은 Figma 에서 벡터로 복원되지 않습니다.
  • 모션 감소를 켠 사용자에게는 자동 넘김·전환이 돌지 않습니다.
  • 색만으로 상태를 알리지 않습니다
    - 모양이나 글자를 함께 둡니다.
  • 토스트는 화면 하단 정중앙 한 곳에서만 뜹니다.

3. 화 면 별 비 기 능 요 건

해당 화면에만 걸리는 요건이다. 전 화면에 걸리는 것은 2장에 한 번만 적었으므로 여기서 되풀이하지 않는다. 총 101항목.

순번기능 ID화면구분요건
1COMPANY-001회사 소개회사 사이트
  • 숫자 칸 사이 선은 바깥 격자의 한 픽셀 간격이 그립니다
    - 칸마다 테두리를 두르면 선이 겹쳐 두꺼워집니다.
  • 표는 자기 상자 안에서만 가로로 밀립니다. 페이지가 통째로 밀리지 않습니다.
  • 값은 전부 store 에서 읽습니다. 회사명 · 대표 · 주소를 글자로 적지 않습니다.
2HISTORY-001연혁회사 사이트
  • 세로선과 점에 aria-hidden 을 겁니다. 장식이라 낭독기에 넘길 것이 없습니다.
  • 바깥은 순서 있는 목록, 해 안쪽은 순서 없는 목록입니다
    - 차례가 뜻을 갖는 것은 해 쪽입니다.
  • 선을 묶음마다 그어 이어 붙이고 마지막 묶음만 점 아래를 덮습니다. 하나의 긴 선을 바깥에 두면 마지막 묶음 아래로 삐져나옵니다.
3CERT-001특허 및 인증회사 사이트
  • 번호는 고정폭입니다
    - 자릿수가 눈으로 맞아야 다른 번호와 견줄 수 있습니다.
  • 표 머리 줄은 넓은 화면에서만 뜹니다. 좁은 화면에서는 한 줄이 카드처럼 접혀, 머리 줄만 남으면 어느 값이 어느 칸인지가 오히려 어긋납니다.
  • 구분 줄은 좁은 화면에서 가로로 눕습니다. 세로로 두면 표가 화면 밖으로 밀립니다.
  • 고른 구분에 aria-current 를 달고, 검색 상자에는 보이지 않는 이름을 둡니다.
4CERT-002특허 · 인증 상세회사 사이트
  • 번호와 취득일은 고정폭입니다
    - 자릿수가 눈으로 맞아야 다른 번호와 견줄 수 있습니다.
  • 값 표는 좁은 화면에서 이름표와 값이 위아래로 눕습니다. 두 칸을 유지하면 이름이 두 글자씩 접힙니다.
5SOLUTION-001스마트 컨설팅회사 사이트
  • 구성도를 그림이 아니라 층 목록으로 둡니다
    - 그림으로 그리면 좁은 화면에서 글자가 뭉개지고 층이 하나 늘 때마다 다시 그려야 합니다.
  • 칸 이름은 본문과 층이 갈리게 작고 흐리입니다. 크게 두면 칸마다 제목이 경쟁합니다.
  • 값이 없으면 그리지 않고 404 로 보냅니다
    - 빈 칸이 늘어선 상세는 만들다 만 화면으로 보입니다.
6SOLUTION-002인프라 서비스회사 사이트
  • 제품 넷과 같은 뼈대를 쓰므로 칸의 차례와 여백이 갈리지 않습니다.
  • 값이 없으면 404 입니다.
7PRODUCT-001제품회사 사이트
  • 사진의 대체 글을 비웁니다
    - 사진이 말하는 것이 옆의 제목과 본문에 이미 글자로 있어, 넣으면 낭독기가 같은 말을 두 번 읽습니다.
  • 서비스 묶음은 모듈이 처음 불릴 때 한 번만 계산합니다.
  • 사진 위의 그라디언트는 장식이라 낭독기에 넘기지 않습니다.
8SOLUTION-003Cloud MES회사 사이트
  • 여섯 상세가 한 조각을 쓰므로 이 화면만 따로 손대는 일이 없습니다.
  • 값이 없으면 404 입니다.
9SOLUTION-004Cloud ERP회사 사이트
  • 여섯 상세가 한 조각을 씁니다.
  • 값이 없으면 404 입니다.
10SOLUTION-005Cloud CRM회사 사이트
  • 여섯 상세가 한 조각을 씁니다.
  • 값이 없으면 404 입니다.
11SOLUTION-006Cloud DXP회사 사이트
  • 여섯 상세가 한 조각을 씁니다.
  • 값이 없으면 404 입니다.
12INQUIRY-001문의하기회사 사이트
  • 필수 표시를 손으로 붙이지 않습니다. 필수라는 사실이 화면과 검사 두 곳에 적히면 반드시 어긋납니다.
  • 오류 문구는 알림 역할을 달아 뜨는 즉시 읽히고, 입력 칸에는 어긋났다는 표시가 함께 붙습니다.
  • 파일 고르개는 화면에서만 감춥니다
    - 키보드와 낭독기에는 그대로 파일 선택으로 읽힙니다.
  • 같은 파일을 다시 고를 수 있게 고른 뒤 값을 비웁니다.
  • 왼쪽 갈래는 좁은 화면에서 가로로 눕습니다. 세로로 두면 양식이 화면 밖으로 밀립니다.
13NOTICE-001공지사항회사 사이트
  • 펼침 상태를 낭독기에 알립니다.
  • 올린 날은 시간 표시 요소로 두어 기계가 날짜로 읽습니다.
  • 왼쪽 갈래는 좁은 화면에서 가로로 눕습니다.
  • 고정은 색이 아니라 딱지 글자로 알립니다.
14NEWS-001뉴스회사 사이트
  • 카드에 올렸을 때 움직이지 않습니다
    - 움직이지 않는 것이 누를 수 없다는 말이 됩니다.
  • 무늬는 값에서 정해져 뽑을 때마다 같은 그림이 나옵니다. 난수로 만들면 도면과 화면을 견줄 수 없습니다.
  • 격자는 좁은 화면에서 한 칸, 넓은 화면에서 세 칸이 됩니다.
15FAQ-001FAQ회사 사이트
  • 펼침 상태를 낭독기에 알립니다.
  • 접히는 줄이 공지사항과 같은 조각을 씁니다
    - 한 번 배운 사람이 다시 배우지 않습니다.
  • 왼쪽 갈래는 좁은 화면에서 가로로 눕습니다.
16SUPPORT-001오시는 길회사 사이트
  • 전화번호는 고정폭이라 자릿수가 맞습니다.

순번상황발생 조건시스템 처리 · 화면 표시
1존재하지 않는 데이터 조회요청한 식별자에 해당하는 데이터가 없습니다.서버는 404 로 응답한다. 화면은 목록으로 돌아가는 경로와 함께 없는 대상임을 안내한다.
2미노출 데이터의 사이트 접근노출 상태가 아닌 데이터를 사이트 주소로 직접 요청했습니다.서버는 404 로 응답한다. 데이터의 존재 여부를 드러내지 않는다.
3필수값 누락필수 항목이 비어 있는 상태로 저장을 요청했습니다.서버는 400 과 함께 누락 항목 목록을 응답한다. 화면은 입력값을 유지한 채 항목별로 안내한다.
4형식 오류연락처 · 이메일 · 날짜 등 형식이 정해진 항목의 값이 규칙에 맞지 않습니다.서버는 400 과 함께 항목별 사유를 응답한다. 미입력과 형식 오류를 구분한다.
5첨부 파일 오류허용되지 않은 확장자이거나 크기 상한을 넘었습니다.서버는 400 으로 응답하며 접수하지 않는다. 화면은 사유를 구분해 안내한다.
6중복 데이터 등록이미 존재하는 값으로 등록을 요청했습니다. 특허 · 인증의 등록번호가 이에 해당합니다.서버는 409 로 응답한다. 화면은 중복 항목을 지목하여 안내한다.
7허용되지 않은 상태값정의되지 않은 상태값으로의 변경을 요청했습니다.서버는 400 으로 응답하며 상태를 변경하지 않는다.
8권한 없는 접근인증되지 않았거나 등급이 부족한 요청입니다.미인증은 401, 등급 부족은 403 으로 구분하여 응답한다. 인증 구현은 2단계 대상이다.
9검색 결과 없음조건에 해당하는 데이터가 없습니다.서버는 200 과 함께 빈 목록 및 총 건수 0 을 응답한다. 오류로 처리하지 않는다.
10외부 서비스 오류지도 SDK 가 응답하지 않거나 인증 키가 유효하지 않습니다.화면은 빈 영역 대신 대체 안내를 표시한다. 주소와 교통편 정보는 지도와 무관하게 제공되어야 한다.

7. 검 증 도 구

아래 검사는 저장소에 포함되어 있으며, 인수 시점에 모두 통과한 상태로 인도한다. 검사를 여럿 두는 것은 하나가 나머지를 대신하지 못하기 때문이다.

순번검사확인하는 것적용 단계
1spec:check이름 · 주소 · 화면 등록부가 기능 레지스트리와 일치하는가1단계
2sync:check레지스트리에 적힌 컴포넌트 이름이 실제 파일에도 그대로인가1단계
3docs:check화면은 있는데 명세가 비어 있는 자리가 있는가1단계
4bind:check화면이 적어 둔 값의 출처가 아직 존재하는가1단계
5overflow:check네 너비에서 가로로 넘치는 곳이 있는가1단계
6weight:check화면 하나가 실제로 내려받는 바이트가 예산 안인가1단계
